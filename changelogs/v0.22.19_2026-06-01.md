# v0.22.19 — 2026-06-01

## Phase 2 scoring signals: Relative Strength vs SPY + Sector Momentum

Completes the Phase 2 signal build scheduled in `project_scoring_engine_gaps.md`.
Two new live signals added to the Trade Scoring Engine — both read entirely from
`historical_prices`, no new API calls at scoring time.

### New signals

| Signal key | Strategies | Weight | Formula |
|---|---|---|---|
| `relativeStrength` | Bullish (15), Buy (20) | enabled | `ticker_90d_return − spy_90d_return` (pp). normMax 50. |
| `relativeWeakness` | Bearish (15) | enabled | Same raw value, `direction: lower_better`, normMax 100. |
| `sectorMomentum` | Bullish (10), Buy (10) | enabled | 90-day return of the ticker's SPDR sector ETF. normMax 30. |
| `sectorWeakness` | Bearish (10) | enabled | `−sectorMomentumPct`, `higher_better`, normMax 20. |

All four were Phase 2 placeholder entries (disabled) in the baseline configs.
They are now fully wired and enabled. The Phase 2 `relativeStrengthVsSpy` /
`sectorMomentum` column in `project_scoring_engine_gaps.md` is resolved.

### Sector ETF mapping (GICS → SPDR)

```
Technology → XLK  |  Financials → XLF  |  Health Care → XLV
Energy → XLE      |  Industrials → XLI  |  Consumer Staples → XLP
Consumer Disc → XLY  |  Materials → XLB  |  Real Estate → XLRE
Utilities → XLU   |  Communication Services → XLC
```

Sector is read from `ScreenResultPayload.sector` in the latest screen run.

### `PriceGapFillJob` bootstrap pass

SPY and the 11 sector ETFs are now maintained in `historical_prices` by
`PriceGapFillJob`. Before the main stale-ticker loop, the job checks which
reference tickers are missing or stale (latest bar > 2 days old) and fetches
6 months of bars for each. This ensures enough history for the 90-day return
calculation from day one.

The constant `SCORING_REFERENCE_TICKERS` is exported from
`price-gap-fill-job.ts` so other code can reference the canonical list.

### Normalization details

- **relativeStrength**: Outperforming SPY by 50 pp → score 100. Underperformers
  clamp to 0 (no penalty beyond zero). New tickers with < 60 price bars → null
  (missing signal, contributes 0 per FR-SE-03).
- **relativeWeakness**: Same raw value read as `lower_better`; underperforming
  SPY by 30 pp → score ≈ 100. Strong outperformers score near 0.
- **sectorMomentum**: Sector ETF up 30% → score 100; flat → score 0.
- **sectorWeakness**: Sector ETF down 20% → score 100; rising sector → score 0.

### Reference ticker exclusion

The 12 `SCORING_REFERENCE_TICKERS` (SPY + sector ETFs) are explicitly excluded from
three jobs that use screener candidates as input:

- `DailyTechnicalSignalsJob` — skips them when iterating `historical_prices` so they
  don't appear as noise in the Batch Jobs live log.
- `DailyIntelligenceBriefJob.loadCandidates()` — never emits them as brief picks,
  even if they somehow appear in `screen_results` (e.g. ETF universe screener run).
- `DailyOptionsSnapshotJob.loadTopCandidates()` — same; avoids wasting E*Trade chain
  calls on tickers that are infrastructure, not trade picks.

Other ETFs from the screener ETF universe (SPY, QQQ, etc.) are not excluded — those
can legitimately appear as Wheel/Income candidates if the user screened the ETF universe.
Only the 12 reference tickers are blocked.

# v1.1.48 — 2026-06-17

## Fix: on-demand E*Trade options path self-heals from token dormancy

### Context
Follow-up to v1.1.47. After the Saturday-expiration date bug was fixed, evening TraderAgent runs *still* returned zero option contracts. Diagnosis showed a second, independent cause: **E\*Trade token dormancy**.

### Root cause
E\*Trade access tokens go dormant after ~2 hours of inactivity; the API then returns HTTP 401 (surfaced by `etradeGet` as `E*Trade API error (401) …`). The nightly batch jobs (daily IV capture, brief, orchestrator) detect this and call `renewAccessToken()` to wake the token, then retry. But the **on-demand** options path did not:

- `ETradeDataProvider.getOptionsChain` and `getOptionsExpirations` called E\*Trade directly with no renew-on-failure.
- These back the API-server `GET /api/v1/options/:ticker` route (TraderAgent scout), the Strategy Lab, and other live features.
- The options route catches per-expiration failures and continues, so a dormant-token 401 became a silent empty chain.

Net effect: any options fetch made more than ~2 h after the last E\*Trade activity (e.g. an agent run at 11 PM ET, hours after the afternoon snapshot job) returned nothing, and `decide` had no contracts to select.

### Evidence
- Last successful agent run (run 22) fired at **15:05 ET — during market hours** — with correct Friday contracts.
- An explicit, correct Friday expiration (`2026-07-17`) returned 0 from the live route at **23:30 ET**, with the v1.1.47 date fix already deployed — proving the late-night failure was E\*Trade-side, not date math.
- Today's snapshot job kept E\*Trade alive until 17:27 ET; by 23:30 ET (~6 h idle) the token was dormant.

### Fix
Added a private `withRenew<T>()` wrapper to `ETradeDataProvider`: it runs the E\*Trade call, and on a dormant-token auth error (`isEtradeAuthError`) calls `renewAccessToken()` once and retries with fresh creds. Applied to both `getOptionsChain` and `getOptionsExpirations`. This mirrors the dormancy handling the nightly jobs already use, so the on-demand path is now equally resilient.

- A non-auth error (e.g. 500) propagates without a wasted renew.
- A fully expired token (past midnight ET) makes the renew itself throw; that propagates — it genuinely needs a manual re-auth in **Settings → E\*Trade Connection**.

### Scope / limits
- Rescues **early-evening** runs where the token is idle but E\*Trade is still serving quotes.
- Does **not** manufacture data when E\*Trade is fully dark overnight. For reliability, run the agent during market hours or within ~1–2 h of the close.

### Tests
- New `tests/etrade-dormant-token-renew.test.ts` (4 tests): renew-and-retry on 401 for both chain and expirations; no renew on a non-auth error; propagate a failed renew.
- Full suite: **599 passing**, typecheck clean.

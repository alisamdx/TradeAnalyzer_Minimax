# v1.1.52 — 2026-06-18

## v2 execution — small-account spread fitness (infrastructure, default OFF)

Phase 7 paper calibration on the real top inflection pick (AMAT 580/520 put vertical) surfaced two
gaps that stop the engine from ever taking a small-account trade. Both are implemented here behind
config flags, **default off**, pending FR-SEY-5 validation.

### Gap 1 — spreads too wide to size (risk-budget width)
The strategy lab picks both vertical legs by delta (sell 0.30Δ, buy 0.15Δ), so width is whatever
the delta gap is: $60 on AMAT, max loss $4,428/contract. At $10k capital / 5% per-trade ($500) the
risk gate sizes that at **0 contracts** → the pick is silently un-tradeable.

- `findBudgetWidthHedge(contracts, side, shortStrike, shortMid, budget, maxWidth)` (exported, pure):
  picks the **widest** long strike whose per-contract max loss still fits the budget — wider = more
  credit + better reward/risk, up to the cap. Returns null (→ structure `unavailable`) when even the
  narrowest one-strike spread busts the budget. `docs/formulas.md#budget-width`.
- `buildSetup` takes an optional `maxLossBudget`; for `short-put-vertical` / `short-call-vertical`
  only, the hedge leg uses the budget selector instead of the 0.15Δ target. Everything else (short
  leg, P&L math, degenerate-wing guard) is unchanged. Null budget → today's delta behavior.
- `StrategyLabService.validate(db, ticker, maxLossBudget?)` threads it; the **brief job** reads
  `exec_config` and, when `budget_width_enabled = 1`, passes `(max_risk_per_trade_pct/100) ×
  capital_ceiling`. Migration **053** adds the flag (default 0).

### Gap 2 — wide markets bleed the edge (liquidity gate)
Even sized, AMAT's wide bid/ask cost ~23% of the credit to cross (live). Migration **054** adds
`exec_config.max_combo_spread_pct` (default 0 = off). When > 0, `EntryPolicy.buildProposal` rejects a
proposal (`wide_market`) whose combo relative spread `(ask − bid) / |mid|` exceeds the threshold,
computed from the live `priceCombo` quote.

### Default off — validation gate (FR-SEY-5)
Both flags default off, so there is **no behavior change** yet. The budget-width change alters the
structure's risk/reward, so before it ships enabled, `simulateSingleSpread` must model the
budget-sized width and a Brief-Replay/Backtest delta must show it is at worst neutral vs the current
wide spread. That validation + enabling is the next step (v1.1.53).

### Config plumbing
`ExecConfig` gains `budgetWidthEnabled: boolean` and `maxComboSpreadPct: number`; `RiskGovernor`
maps both (`ConfigRow`, `CONFIG_COLUMN`, `getConfig`, generic `updateConfig`). No UI toggles yet —
they land with the enable step.

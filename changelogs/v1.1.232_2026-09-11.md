# v1.1.232 — 2026-09-11

## Every brief hand-off failed from the day the contract shipped

`core` 0.6.3, dictionary **v14**.

### What was observed

Three hand-offs exist — 2026-09-10 19:03, 2026-09-11 10:32, 2026-09-11 17:36 — each a manual run with
**one call, ~100 KB, one parse failure, zero rows**. `legacy_brief_candidate`: **0 rows**.

### Cause: one vocabulary, two spellings

`legacy_brief_candidate.mode` stores the existing app's **scoring strategy**. The dictionary declared:

```ts
const LEGACY_MODES = ['wheel', 'buy', 'options', 'bullish', 'bearish'];
```

That list came from CLAUDE.md's prose description of the *analysis* engine, and it matches neither
real vocabulary:

| Source | Values |
|---|---|
| Brief (`scoring-service.ts` `STRATEGIES`) | wheel, bullish, bearish, **income**, buy, **inflection** |
| Analysis engine (`AnalysisMode`) | buy, **options_income**, wheel, bullish, bearish, jade_lizard, big_lizard |
| Dictionary (before v14) | wheel, buy, **options**, bullish, bearish |

`'options'` is in neither — it reads as a truncation of `options_income`. The brief scores **all six**
strategies every run, so every payload carried `income` candidates, every insert violated the generated
CHECK inside the write transaction, and `indexAndIngest` recorded `parse_status = 'failed'` with zero
data rows. Deterministic, from the first hand-off onward.

### Why it stayed invisible for three runs

1. **A hand-off is a MANUAL run, and manual runs are not gate-evaluated** — "no checks recorded".
2. **The parse error was computed and discarded.** `parseError` lived on the returned `CaptureResult`;
   `meta_response` had no column for it. `parse_status` said *that* a parse failed; nothing said *why*.
3. **The caller logged counts, not outcome** — `0 rows` printed to a console nobody reads.
4. **The pins still landed.** `pinSticky` builds from `c.legs` and never touches `mode`, so 141 pinned
   contracts sat beside an empty candidate table, which reads like success at a glance.

### Why the tests passed

Every fixture in `legacy-handoff.test.ts` and `legacy-import.test.ts` used `mode: 'wheel'` — inside the
four values the two lists happened to share. **A fixture drawn from the overlap of two vocabularies
cannot test that they agree.** And the hand-off site carried
`mode: strategy as LegacyBriefHandoff['candidates'][number]['mode']` — an `as` cast, which is exactly
what silenced the compile error that would have reported this before it ever ran.

### The knock-on nobody attributed

`runChainSubsetPhase` admits `recommended_by_legacy` members by reading `legacy_brief_candidate`. With
that table empty, the entire admission path was dead. The chain subset sitting at ~1 ticker was
previously attributed wholly to the 20-bar dollar-volume rule; that was **half** the cause.

### Fix

- `LEGACY_MODES` is defined from the brief's `STRATEGIES`. `'options'` is dropped — nothing ever wrote
  it, and the table is empty, so the rebuild is clean.
- `LegacyHandoffCandidate.mode` mirrors it, and the cast is deleted, so the compiler now checks the two
  vocabularies against each other.
- `legacy_brief_candidate` holds 0 rows, so `applyDictionary` treats the enum change as drift on an
  **empty** table: DROP and recreate. **No new generation; the pilot clock is untouched.**

### Three observability fixes, any one of which would have caught this alone

- **`meta_response.parse_error`** (nullable). A failure that cannot explain itself is one somebody has
  to re-derive — this took an hour of reading source instead of one query.
- **The hand-off caller warns** on a non-`ok` parse and names `meta_response.parse_error`.
- **QC-010** (warning, `cross_cutting`): a hand-off that arrived was ingested. Scoped to the trading
  date rather than the run, because the hand-off lands in its own manual run. **Warning, not blocking**
  — a day the brief did not run is not a collector fault — and silent when none arrived, so "none" and
  "one arrived broken" stay distinguishable.

### Tests

`packages/core/test/legacy-mode-vocabulary.test.ts` (new):

- the enum equals the brief's `STRATEGIES`, **read from that file** rather than restated here — a
  restatement would agree with a copy, which is the failure being tested for;
- no enum value exists that the brief cannot produce (`'options'` sat unwritable for six versions);
- the v14 rebuild applies on an empty table and its four foreign-key children survive — `PRAGMA
  foreign_keys = OFF` is a no-op inside a transaction, so a parent rebuild is exactly where a cascade
  would quietly empty them.

The hand-off fixture now uses `income`.

### Not fixed here

The three archived payloads are intact and replayable. Recovering 9/10 and 9/11's candidate sets is a
**replay after Monday's run**, deliberately not before — a replay must not interfere with day 1 of the
pilot streak.

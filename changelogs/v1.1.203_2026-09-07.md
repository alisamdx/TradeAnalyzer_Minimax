# v1.1.203 — 2026-09-07

## fix — the collector could create a generation, and did

Found while verifying v1.1.202 on a live machine, which is the only place it
could have been found.

After the corrupt `gen-001` was deleted, the collector's 2-minute claim tick
**recreated it** — 52 tables, `integrity_check: ok`, every row count zero, and
`meta_open_handle` naming only `TradeAnalyzer`. It looks like a healthy
generation from every angle except the one that says whose it is.

**Generation creation belongs to the new exe alone** (NewApp 06 §3). This
application is a collector host: it writes *into* a generation and has no
business making one. `readSharedPointer` already refuses to invent a pointer for
exactly that reason — but the guard stopped one level short, because
`new Database(path)` creates the file when it is missing. So the pointer was
protected and the database was not.

The tell is **`meta_generation` = 0**: only the new exe writes that row. Which is
worth noting against the original corruption report, where `meta_generation`
reading 0 was filed as evidence of the corruption. It is *also* the signature of
a generation the wrong application created — and once the two causes are known to
share a symptom, neither can be read from it alone.

### The fix

- `ElectronCollectorHost.openGenerationDb()` throws if `data.sqlite` does not
  exist, **before** the `mkdirSync` that would create the directory and before
  the open that would create the file. That is the choke point, so creating one
  is impossible rather than merely unlikely.
- `generationExists(pointer)` is exported, and all four callers check it first —
  `collector-oneshot`, both `collector-daily` handlers, and the claim loop in
  `index.ts` — so the operator sees `skipped` with a reason rather than a stack
  trace every two minutes. The choke point makes it safe; the call sites make it
  legible.
- Regression tests in `tests/collector-host.test.ts`: one asserts the refusal is
  positioned before both `mkdirSync` and `new Database`, the other that every one
  of the four callers checks.

### Recovery needs no reset

A generation created this way is structurally correct and empty; it only lacks
its `meta_generation` row, and the new exe writes that on open
(`INSERT ... ON CONFLICT DO NOTHING`). Starting TradeAnalyzer 2 once repairs it
in place.

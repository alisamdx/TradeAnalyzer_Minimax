# v1.1.190 — 2026-09-04

## The critic context change is defaulted OFF — measured, it would have emptied the dice

v1.1.189 fixed two real defects and shipped them **enabled**. The A/B says that was wrong.

## The measurement

`tests/critic-context-ab.test.ts`, 20 wheel picks. Both arms are the same code path on the same
picks with the same rule flags, differing only in the flag — so nothing but the context can explain
the difference.

| | pass | caution | flag |
|---|---|---|---|
| before | **8** | 10 | 2 |
| after | **0** | 19 | 1 |

**40% stricter, and not one `pass` survives.**

The dice rejects anything that is not `pass`. On this sample the change would have produced
**zero picks** — it would have turned the feature off without appearing to.

## The cause, in the model's own words

All 8 flips cite the cost basis against SMA200. None cites a weak signal. The ownership half is
unambiguously responsible:

```
2026-09-04  DINO   pass -> caution
    "cost basis if assigned ($94.25) sits 43.6% above the 200-day SMA ($65.64)..."
2026-08-26  AAPL   pass -> caution
    "assignment cost basis of $296.52 sits 4.5% above the 200-day SMA ($283.87)..."
```

**AAPL at 4.5% above.** That is the tell.

## What was actually wrong with it

The fact was true and the reasoning was superficially sound. What was missing is the **base rate**.

- a cost basis above SMA200 is the **normal** case — **70% of 82 critic-passed wheel picks**
- the above-SMA200-**but**-below-the-20-day-low cell is the **best performing of the four**:
  **+3.46% mean / +5.49% median**, against −2.10% for the cell where both readings agree

So the model was handed a property that two thirds of good picks share, with nothing to calibrate
it against, and turned it into a blanket veto.

**v1.1.188 had removed exactly this error from the operator-facing sentence eight hours earlier** —
that release stopped "an extended price, not a discount" firing on the support-only cell. Feeding
the raw fact to a model reintroduced it through a different door.

**This is the conviction band inverted.** That threshold was anchored so it could never fire; this
one fires on everything. Neither is visible without measuring the distribution of the quantity
being tested against the threshold.

## What shipped now

- **Flags split** into `CRITIC_CONTEXT_SIGNALS` and `CRITIC_CONTEXT_OWNERSHIP`, **both default
  false**, because the two halves behave completely differently and have to be testable apart.
- **The signals half is unmeasured alone.** It is off not because it was shown harmful — every
  flipped rationale points at the other half — but because the only A/B available bundled the two,
  and FR-SEY-5 does not accept "the other half was probably fine". `CRITIC_CONTEXT_SIGNALS=1` plus
  a re-run isolates it.
- **The finding is recorded in the source**, above the flags, so the next person to consider this
  reads the measurement before the idea.

## A second, smaller trap worth recording

v1.1.189 shipped the harness as `scripts/critic-context-ab.mjs`. **It could not run.** A plain node
script cannot resolve the `@shared/*` path aliases that `critic-service.ts` imports, so the only
way to make it work would have been to reimplement the prompt and context assembly in the script —
which would have tested a copy of the thing under test, and reported a blast radius of zero.

The harness now lives in `tests/`, where vitest resolves the aliases and the real service runs. It
is skipped unless `RUN_CRITIC_AB=1`, and reads the key from `settings.anthropicApiKey` (not in
`SENSITIVE_KEYS`, so no Electron safeStorage needed) rather than demanding an env var.

```bash
RUN_CRITIC_AB=1 AB_LIMIT=20 npx vitest run tests/critic-context-ab.test.ts
```

## If this is re-opened

Give the model the **base rate**, not the bare fact: the 70% prevalence and the four-cell outcome
table, so it can tell an unusual reading from a universal one. Then re-run the A/B. The defect
v1.1.189 identified is real — the reviewer genuinely was shown a filtered-favourable view — and
still worth fixing; this release only says that *this particular* fix, measured, costs more than it
gives.

## Lesson recorded in CLAUDE.md

**Giving a model a measured fact is not the same as giving it the fact's base rate, and without the
base rate a common property reads as an alarm.** Always A/B a context change to an LLM gate before
shipping it.

# v1.1.278 — 2026-09-18

`core` 0.6.33, `next` 0.4.21.

## The gate no longer reads "not evaluated" as "clean"

### Problem

Spec 03 lets the gate resolve a finding only when a remediation succeeded **and** the same fingerprint evaluates clean. `reconcileStoppedFiring` tested only the first half plus "did not fire this run". A fingerprint can be missing from the fired set for two reasons, and only one is evidence:

- the check measured the key and it did not fire, or
- the check never looked at it: the ticker was not collected this run, a deduplicated fetch stored no rows, the key fell outside the check's window, or the check threw.

Both closed the finding as `data_corrected`. Found while writing v1.1.277's tests: a second backfill with identical bytes stored no bars, QC-204 had nothing to compare for that ticker, and the gate "corrected" a step it had not looked at.

No production finding had been closed this way. On gen-002 all 28 `data_corrected` QC-204 resolutions came from the JAN and SOLS reuse rulings. The fix is preventive. It matters now because R6 records successes on every QC-204 finding it re-fetches.

### Fix

- `runGate` collects `evaluatedClean`: fingerprints a check returned this run with `fired: false`. A check that threw contributes none.
- The `data_corrected` branch of `reconcileStoppedFiring` requires membership. Otherwise the finding stays open with `still_firing = 0`, which is the existing "no longer observed, unresolved" state.

### QC-501 orphans

QC-501 reads only open QC-204 findings. Once QC-204's finding is resolved, QC-501 stops evaluating that key, so under the corrected rule its own finding could never close. QC-501 now also evaluates its open findings whose QC-204 finding is resolved: not fired, with `closesAs` carrying QC-204's resolution kind and note. `Evaluation.closesAs.kind` now accepts every resolution kind so the alias can mirror `data_corrected`.

### Measured

- Snapshot 2026-09-18: open findings with a successful remediation that were never evaluated: **0** (all 98 were evaluated clean and are closed by v1.1.277's verified-move rule).
- Rehearsal: QC-204 / QC-501 123 → 25, identical to v1.1.277.

### Tests

- `gate.test.ts`: a remediated finding whose key the next run does not evaluate stays open; a remediated finding whose check throws stays open.
- `remediation.test.ts`: QC-501 closes `data_corrected` the run after its QC-204 finding does.

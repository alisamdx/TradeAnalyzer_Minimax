# v0.32.35 — 2026-06-08

## Brief scoring: fundamental signals decoupled from screener

### Problem
`loadFundamentals()` in `scoring-service.ts` queried `screen_results` from the latest screener run to get earningsGrowth, fundamentalScore, revenueGrowth5Y, epsGrowth5Y, leverageQuality, and sector data. Because the last screener run was ETF-universe only (60 tickers), all ~1000 stock picks in the brief had null fundamental signals. The AI Critic's `checkCriticalSignalMissing` rule then flagged every one of them (warning-severity), making flags the dominant brief outcome.

### Fix
Three methods in `scoring-service.ts` now use batch-job-populated tables:

| Method | Old source | New source |
|---|---|---|
| `loadFundamentals()` | `screen_results` (latest run, scoped to screener universe) | `fundamentals_cache` (1067 rows, updated daily by market-sync jobs) |
| `loadSectorMomentum()` | `screen_results.payload_json.sector` | `fundamentals_cache.payload_json.sector` (same field, full coverage) |
| `loadTechnicalSignals()` | `buySignalScore` only | also populates `rsi`, `smaStack`, `lastPrice` from `technical_signals` (1055 rows, nightly DailyTechnicalSignalsJob) as fallbacks when `analysis_snapshots` has no data |

### Notes
- `sectorMomentum` signal remains null for most tickers because the sector strings in `fundamentals_cache` (SIC descriptions) don't match the GICS sector names in `SECTOR_ETF`. This was true before too — pre-existing issue.
- `trendStrengthAdx` (ADX value) still comes from `analysis_snapshots` — it is not computed by any batch job.
- `annualizedReturn` and `optionLiquidityScore` still come from `analysis_snapshots` — require live options data.

# v1.1.338 — 2026-10-01

## The bull put spread study reads through the app

`scripts/fr-bull-put-spread-study.mjs` opened `%APPDATA%\trade-analyzer\trade-analyzer.sqlite` itself,
write-capable. Its redirect guard correctly refused inside the Claude app's shell, which is
MSIX-containerised (CLAUDE.md: opening a WAL database from a redirected shell can move it), so the study
could only run from a separate terminal after `npm run rebuild:node`. That is why `bps10-ranking.md`,
cited by `NewApp/TODO-bull-put-spread.md`, could not be regenerated from a session.

**Change.** Same fix as the liquidity study (v1.1.267) and the wheel A/B (v1.1.220):
- **`GET /api/v1/diagnostics/spread-study-panel?strategy=wheel[&quotes=1]`**
  (`services/spread-study-panel.ts`) returns exactly what the script's SQL selected: the strategy's
  replay picks (best rank per ticker and date), each picked ticker's bars over the union of its picks'
  `[date − 90, date + 75]` windows with non-positive closes skipped, its `iv_history` as stored, and,
  with `quotes=1`, the three quote sources for the quoted-slippage model. A quote table that cannot be
  read is `null`, never `[]`, so the script still prints it as unavailable rather than as empty.
- **The script** fetches that panel with the agent token. Its two loaders keep their per-pick windows,
  filters and arithmetic; only where the rows come from changed, so a run's output is unchanged by the
  move. The redirect guard, the better-sqlite3 import and the `rebuild:node` step are gone; `--selftest`
  still needs nothing.

Spec 22's diagnostics route list now also names `premium-roc` (v1.1.336), which it had missed.

Tests: `tests/spread-study-panel.test.ts` (6) — picks at best rank and per strategy, the bar window
bounds on both sides, non-positive closes skipped, `iv_history` for picked tickers only, quotes only
when asked, and an unreadable quote table reported as `null`.

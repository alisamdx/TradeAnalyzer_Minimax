# v0.32.75 — 2026-06-11

## Fix: false "Invalid Polygon API Key" abort from 403 plan-restriction responses

### Root cause (two bugs)

**Bug 1 — screener-service.ts: error check too broad**

```typescript
// OLD — matches ANY error whose message contains "api key":
if (err instanceof Error && (
  err.message.includes('401') ||
  err.message.toLowerCase().includes('unauthorized') ||
  err.message.toLowerCase().includes('api key')    // ← too broad
)) {
  throw new Error('Invalid or missing Polygon API Key...');
}
```

Polygon returns HTTP **403** (not 401) for plan-tier restrictions. Their 403 body
often says something like:
> "You do not have access to this endpoint, your current plan is: Stocks Starter.
>  Please visit polygon.io/dashboard/api-keys to upgrade your apiKey plan."

That body contains `"apiKey"` → matched `'api key'` → entire sync aborted with a
misleading "Invalid or missing Polygon API Key" error even though the key was valid.

**Bug 2 — polygon-provider.ts: 4xx responses retried unnecessarily**

```typescript
// OLD — retries ALL non-ok responses (including 401 and 403):
if (!response.ok && retryCount < this.maxRetries) { ... }
```

Retrying 401/403 wastes 3 round-trips and delays — auth/plan errors will never
recover on retry. The comment already said "5xx or network errors" but the code
did not match.

### Fix

**screener-service.ts**: Only abort the sync on a genuine `'Polygon HTTP 401'`.
403 plan-restriction errors now silently skip that ticker (same treatment as any
other per-ticker failure like delisted tickers).

**polygon-provider.ts**: Only retry 429 (rate limit) and 5xx (server errors).
4xx responses throw immediately.

# v1.1.159 — 2026-09-02

## feat: nightly portfolio sync — with an audit trail, because it writes to money

Adds `portfolio-sync` as the last job in the after-close chain: refresh open positions from
E*Trade, then import closed positions with real broker fills, so the Portfolio and Performance
views are current every morning without a manual sync.

### Why this is safe to automate *now* and wasn't before

Three things from v1.1.144–158 had to land first:

- **`withRenew` on all four portfolio paths** (v1.1.154). Without it a dormant token fails the
  sync outright — and an unattended evening job is precisely the scenario that meets dormancy.
- **The import actually works** (v1.1.150–156), through executed orders in ~376 ms.
- **Idempotency verified against real data** — a second import produced zero duplicates and
  zero changes.

Automating before those would have written garbage nightly, unattended.

### Two deliberate design decisions

**1. It never returns `failed`.** The orchestrator is stop-on-failure: a failed sub-job halts
every job after it. E*Trade's transactions endpoint answered `oauth_problem=nonce_used` after
~120 s for weeks, and a broker hiccup must not stop the daily brief from generating. Errors
surface as `success` plus a `WARNING:` note — the same contract `constituents-refresh` uses for
a broken holdings feed. A failure in either half still lets the other half run.

**2. Open positions sync BEFORE closed ones are imported.** When a position vanishes from the
broker, `syncPortfolio` writes an estimate marked *"realized P&L estimated from last mark"*, and
those are systematically wrong — an assigned CSP reads as a large loss when it was a conversion
into stock (TSLA $350: estimate **−$3,735.53**, actual **+$499.48**). Importing immediately after
supersedes the estimate with the real fill **in the same run**, so the wrong figure never reaches
the Performance tab. Reversed, it would sit there for a day.

### The audit trail

This is the **first batch job that mutates the user's real financial record** rather than market
data. Every other job touches prices, chains or signals — if one corrupts something you re-fetch
it. This one rewrites `positions`, and its supersede path overwrites a stored P&L.

`position_audit` (migration 073) records one row per write: action (`imported` / `superseded`),
position, **old and new** `realized_pnl` and `exit_price`, source (`orders` / `transactions`) and
a note. The overwritten value is captured *before* the update, so a figure can always be traced
to the run that produced it. Auditing is wrapped so it can never break the write it records, and
an idempotent rerun that changes nothing writes nothing — the log does not grow for doing
nothing.

The whole E*Trade investigation only became tractable once those calls were logged. The same
argument applies with more force to a job that runs unattended against money.

### Placement

Registered last (nothing consumes portfolio data), `after_close_only = 1` — end-of-day record
keeping has no business in the lean intraday slot. Typical cost is ~3 API calls and under two
seconds. Run note reads e.g.
`Positions: 2 updated, 5 unchanged · Closed: 1 imported, 24 already present · 1 audited write`.

### Tests

`tests/portfolio-sync-job.test.ts` (6): open-before-closed ordering; a throwing import does not
fail the chain; a throwing position sync does not fail the chain *and* the import still runs;
non-fatal E*Trade errors surface as warnings on a successful result; a clean skip when E*Trade
is not connected; the run note reports what happened.
`tests/position-audit.test.ts` (3): an import records no prior value; a superseded estimate
preserves the **overwritten** −$3,735.53; an idempotent rerun writes nothing. Suite: 1044 passed.

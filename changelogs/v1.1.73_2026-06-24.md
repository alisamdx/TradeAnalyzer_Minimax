# v1.1.73 — 2026-06-24

## Backup & Restore — real zips, working auto-backup

### What was wrong
- **Backup Everything** showed a "Save as `.zip`" dialog but then **ignored the chosen path** and
  wrote an **un-zipped folder** into `%APPDATA%\trade-analyzer\backups\backup-<ts>\`, ending with a
  message telling the user to "copy the backup folder manually." It also copied the live `.sqlite`
  with a plain file copy, which under WAL can miss recently-written data.
- **Restore** only accepted a bare `.sqlite`/`.db` — not the thing Backup produced.
- **Auto-backup** had a checkbox (buried in the **General** tab) but **nothing ever ran it** — no
  scheduler was wired to the `autoBackupEnabled` / `autoBackupIntervalDays` settings.

### Fix
New shared `src/main/services/backup-service.ts`, used by both the interactive IPC handlers and the
startup auto-backup so the two can't drift:

- **`createBackupZip(db, outZipPath, appVersion, sources)`** — writes a single real `.zip` to the
  chosen path containing a **consistent DB snapshot** (better-sqlite3 `db.backup()` → WAL-safe),
  plus `logs/`, `AI_CONTEXT.md` (when present), and `manifest.json`. Uses `adm-zip` (new pure-JS
  dependency — no native/ABI impact).
- **`restoreDbFromFile(sourcePath, destDbPath)`** — accepts a backup `.zip` (extracts the
  `trade-analyzer.sqlite` entry) **or** a bare `.sqlite`/`.db`; overwrites the live DB. Returns
  false for anything unrecognized (handler surfaces a clear error).
- **`runAutoBackupIfDue(db, appVersion, backupsDir, sources)`** — reads the settings, and if enabled
  and the interval has elapsed since `lastAutoBackupAt`, writes a zip to `backups/auto/`, records the
  timestamp, and prunes to the newest 5. Called fire-and-forget at startup in `index.ts`.

### UI
- `settings:backup-everything` now zips to the user's chosen path (appends `.zip` if missing) and
  reports the real saved location + item count.
- `settings:restore-backup` accepts `.zip`/`.sqlite`/`.db`; restores against `db.name` (the live DB
  path) and prompts for restart.
- Settings → **Backup** tab: descriptions updated to say ".zip"; the **Automatic Backup** control
  (enable toggle + **interval days** field) moved here from **General**, where it was hard to find.

### Tests
`tests/backup-service.test.ts` (12) — zip contents, zip↔restore round-trip, bare-sqlite restore,
unrecognized/empty-zip rejection, auto-backup disabled/not-due/due transitions + timestamp, prune,
and path derivation. Full suite **704 passing**.

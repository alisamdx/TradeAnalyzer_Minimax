# v1.1.43 — 2026-06-17

## Portfolio Unrealized P&L populates from the E*Trade sync

### The bug (user report: "not showing P&L")
The portfolio's **Unrealized P&L** summary read $0. `getPnLSummary` sums each position's
`unrealized_pnl`, but that column was `null` for every E*Trade-synced position: `upsertPosition`
stored `market_value` and `total_gain_pct` (the percentage) but **discarded `raw.totalGain`** (the
dollar gain/loss E*Trade hands back) and never wrote `unrealized_pnl`. The only thing that set
`unrealized_pnl` was the manual per-ticker price refresh (`portfolio:updatePrice`), which isn't
part of the sync flow — so after a sync, P&L was blank.

### The fix
`upsertPosition` now stores `raw.totalGain` into `unrealized_pnl` on both the INSERT and the
UPDATE paths. After a sync, per-position and total Unrealized P&L reflect the broker's numbers.

- `current_price` is intentionally left to the live-quote refresh: a short option's
  `market_value` is a negative liability, so a clean per-share "current price" can't be derived
  from it.
- The manual `portfolio:updatePrice` path (which recomputes `unrealized_pnl` with simpler logic)
  is unchanged and isn't auto-run after sync, so it doesn't clobber the broker P&L.

### Re-sync required
Existing rows still have `unrealized_pnl = null`; run the portfolio E*Trade sync once on the new
build to backfill them.

INSERT, and refreshed on UPDATE (re-sync). Full suite: **557 passing**.

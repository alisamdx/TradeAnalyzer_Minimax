# v1.1.93 — 2026-07-01

## Structure-liquidity instrumentation (measure, don't guess)

### Why
NEW_FRONTIER §11 found the after-close brief measures structure liquidity ~**−1.42 pts**
below intraday (bar clearance 68% → 47%, all paired deltas ≤ 0) — right at the 8/15
tradability bar that drives most critic `low_liquidity` flags. But the evidence was only
**19 paired observations from a single date**: `ScoringService.storeBrief` deletes the
same-ET-day rows, so the evening brief destroys the morning brief's intraday
measurements every day.

### What
- **Migration 064** — `structure_liquidity_log` (captured_at UTC, date_et, ticker, slug,
  liquidity_score, grade, no_bid_leg; indexed on date_et+ticker+slug).
- **`src/main/services/structure-liquidity-log.ts`** — `extractLoggableScores` (valid,
  constructible structures only), `logStructureLiquidity` (transactional append),
  `pruneStructureLiquidityLog` (120-day retention).
- **Brief job Stage 4** logs each validated ticker's structures right after
  `strategyLabService.validate()`; wrapped in try/catch so instrumentation can never
  break the brief; prune runs once per brief run.
- **`scripts/fr-liquidity-slot-comparison.mjs`** now prefers the instrumentation table
  (pairs by date_et + ticker + slug, slot bucketed from captured_at ET hour; first
  measurement per slot wins) and falls back to stored briefs when the table is empty.

### How this plays out
With the 10:15 slot healthy again (v1.1.92 dormant-token fix), both slots log ~50
structures/day → hundreds of intraday/after-close pairs within 2–3 weeks. Then re-run
`node scripts/fr-liquidity-slot-comparison.mjs`. If the −1.4 artifact holds at sample
size, the candidate fix is letting the critic/liquidity gate use the same-day intraday
measurement — that change gates engine entries (critic verdicts feed `entry-policy.ts`),
so it goes through a full FR-SEY-5 validation at that point.

Pure instrumentation — nothing on the live path reads this table.

# v0.32.7 — 2026-06-07

## Scoring engine: phase2 dead code removed

The `ScoringSignal` interface had a `phase2?: boolean` field, and multiple `!s.phase2` guards scattered across the scoring engine (scoring-service, critic-service, daily-intelligence-brief-job) and the TradeScoringView UI. No current baseline config ever set this field to `true` — it was vestigial infrastructure from an earlier design sketch.

**Problem it was causing**: the UI showed a "Phase 2 signals — not yet available" section that was always empty. Any user-edited DB config that somehow had phase2-flagged signals would have those weights excluded from the scoring denominator, inflating composite scores.

**What changed**:
- `phase2?: boolean` removed from `ScoringSignal` in `shared/types.ts` and `scoring-service.ts`
- All `filter(s => s.enabled && !s.phase2)` → `filter(s => s.enabled)` in 4 files
- `TradeScoringView`: removed `isPhase2` logic, Phase 2 badge, disabled checkbox state, and the Phase 2 divider section
- All signals are now fully active or user-toggled — no hidden suppression layer

## Daily Brief: Haiku → Sonnet 4.6

**Rationale**: The daily brief is the primary AI output users act on. Haiku is fast and cheap but optimizes for throughput over reasoning depth. Sonnet 4.6 produces better second-order signal synthesis — e.g., noticing that high IVR + strong sector momentum + RSI near 50 for a wheel candidate is a more cohesive story than three independent facts.

**What changed**:
- `daily-intelligence-brief-job.ts` stage 5 (pick rationale): `claude-haiku-4-5-20251001` → `claude-sonnet-4-6`
- `critic-service.ts` stage 5b (AI critic verdict): `claude-haiku-4-5-20251001` → `claude-sonnet-4-6`
- Cost estimate comments updated: ~$3/M input, ~$15/M output (vs $0.25/$1.25 for Haiku); critic estimate ~$0.008/pick

**AI_CONTEXT model table updated**: daily brief and critic now show `claude-sonnet-4-6`.

# v1.1.14 — 2026-06-14

## v2 execution — FR-SEY-2: drawdown-scaled risk

The second Seykota extension (after the FR-SEY-5 process rule). Adds graduated
"equity-curve money management" between normal operation and the binary daily kill switch:
when the account draws down, the engine takes **smaller** positions until it recovers.

See `Requirements/v2-execution/06-seykota-risk-extensions.md` (FR-SEY-2).

### Behaviour

- A **closed-equity high-water mark** is tracked: `equity = capitalCeiling + Σ realized P&L
  of closed positions`; the HWM ratchets up only.
- When drawdown from the HWM reaches `drawdownThrottlePct`, the effective per-trade risk is
  multiplied by `drawdownThrottleFactor` (e.g. 0.5 = half size). Factor ≤ 0 halts new
  entries; ≥ 1 is no throttle.
- Closed-equity (not mark-to-market) is used deliberately, so open-position swings don't
  thrash the throttle.
- **Default OFF** (`drawdownThrottlePct = 0`) → identical behaviour to before. Enable in
  Execution Settings → Risk limits.

### Changes

- Migration **049**: `exec_config.drawdown_throttle_pct` (default 0), `.drawdown_throttle_factor`
  (default 0.5); `exec_risk_state.equity_high_water` (seeded to `capital_ceiling`).
- `src/main/execution/risk-gate.ts`: pure `drawdownThrottleFactor(drawdownPct, config)`;
  `GateContext.effectiveMaxRiskPct?` (optional) drives the `per_trade_risk` limit.
- `src/main/execution/risk-governor.ts`: `getDrawdownPct()` (computes closed equity, ratchets
  the HWM), throttle applied in `sizeEntry` and `checkEntry`; config/state mapping for the
  new columns.
- `src/main/execution/execution-engine.ts`: `EngineStateView.drawdownPct`.
- UI: Execution Settings exposes the two knobs; Trading Desk shows drawdown % + HWM +
  throttle status in the Capital panel.
- Types: `ExecConfig.drawdownThrottlePct`/`drawdownThrottleFactor`,
  `ExecRiskState.equityHighWater`, `ExecEngineStateView.drawdownPct`.

### FR-SEY-5 compliance

Ships **disabled by default**. Enabling it only *reduces* size during drawdowns — an
unambiguously conservative risk reduction, not an edge claim — so no backtest edge delta is
required; turning it on is the operator's risk-appetite choice.

# v1.1.6 — 2026-06-14

## v2 execution subsystem — Phase 4b (order manager)

The bridge between proposals/exits and the broker — turning an approved proposal into a
live order and reconciling fills into managed positions. Still dormant.

### Migration 047

`exec_orders.position_id` — links an order to the position it opens (set on the open
fill) or closes (set at close-submit time so the close fill resolves the position).

### `order-manager.ts` — `OrderManager`

- **`approveProposal(id, now)`**: validates pending + not-expired, **re-runs the pre-trade
  gate at submission** (§2.5), mints a client order id and persists the order row **before**
  the broker send (idempotency, §2.8), submits an open combo order, and audits each step
  (`proposal_approved`, `order_submitted`). Rejects with a reason on not-pending / expired
  / gate failure.
- **Fill handling** (broker `onOrderStatus` + `onFill`): drives the order state machine and,
  on an open fill, **creates the `exec_positions` row** (entry credit, max-loss capital,
  contracts) and recomputes deployed capital; fills de-duplicated by broker exec id.
- **`submitClose(positionId, reason, now)`**: reverses the position's legs into a close
  order, marks the position `closing` → `closed` with its `close_reason` on fill, frees the
  capital.

# v0.32.81 — 2026-06-11

## Fix: daily brief AI rationales silently dropped (max_tokens truncation)

### The bug

Found during the post-batch deep-dive: tonight's brief had `aiRationale: null` on all
25 picks while `run_meta.stage5` showed `rationales: 0, costUsd: 0.066`.

Stage 5 sends all 25 picks (5 strategies × 5) to claude-sonnet-4-6 in one call asking
for a JSON array of rationales, with `max_tokens: 2048`. 25 rationales at ~60 words
each need ~2.3K+ output tokens. The response hit the cap and truncated mid-object, so
the array never closed. The extraction regex `\[[\s\S]*\]` requires a closing `]`,
matched nothing, and the code moved on — money spent, zero rationales, no error logged.

The cost backs this out: $0.066 ≈ 11.8K input tokens + a full 2,048-token capped output.

### The fix

1. **`max_tokens: 4096`** — comfortable headroom for 25 rationales.
2. **`parseRationaleResponse()`** in new pure module `brief-rationale-parser.ts` —
   tries the complete-array fast path, then falls back to salvaging every complete
   `{ticker, strategy, rationale}` object individually. A future truncation now
   yields 23/25 rationales instead of 0/25.
3. **Visibility** — `stop_reason === 'max_tokens'` or a zero-parse outcome is recorded
   in `runMeta.aiError`, which surfaces in the Batch Jobs run history.

# v1.1.81 — 2026-06-25

## Root cause: two position-greek write paths with opposite sign conventions

v1.1.80 fixed the *symptom* (a reconstructed CSP read as "bearish") by normalizing greeks in the
Payoff reconstruction. This fixes the *source*: why `positions.delta/theta/vega` had an unstable
sign in the first place.

### Investigation
Two code paths write position greeks, and they disagreed:

| Path | Code | Convention written |
|------|------|--------------------|
| E*Trade portfolio **sync** | `etrade-portfolio-service.ts` — `delta = num(Complete?.delta)` (verbatim) | **raw** (E*Trade returns contract greeks; a short put's δ is negative — confirmed by the morning sync storing −0.79 for a deep-ITM CSP) |
| **Refresh greeks from chain** | `ipc-portfolio.ts` — `sign = isShort ? -1 : 1; delta = sign * contract.delta` | **position-signed** (short put → +δ/+θ/−ν) |

Whichever path wrote last set the stored sign. The user's positions were synced in the morning
(raw), then a chain-refresh ran later (position-signed) — so the *same* short put flipped from
δ −0.25 to δ +0.27 between reads. E*Trade itself is consistent (always raw); the instability was
entirely the two divergent app paths.

The intended convention is **position-signed**: the Portfolio net-greek aggregation
(`PortfolioView`) multiplies by magnitude only and its comments say "short-position convention",
and the planned Book Greeks monitor sums directly. So the sync (raw) was the wrong one.

### Fix
New single source of truth: `src/shared/position-greeks.ts` →
`toPositionSignedGreeks(positionType, delta, theta, vega)` (negate CSP/CC, keep longs; nulls
pass through; gamma deliberately excluded — not part of the convention and never written by the
refresh path). **Both** write paths now call it:
- `etrade-portfolio-service.ts` converts E*Trade's raw greeks before storing.
- `ipc-portfolio.ts` replaced its inline `sign` logic with the helper.

So the stored convention is deterministically position-signed and the two paths can't drift —
the same consolidation lesson as the brief's shared strategy-slug map.

### Interaction with v1.1.80
`position-payoff.ts` still normalizes to canonical *raw by type* before the Payoff engine applies
the side sign — that remains correct (and defensively handles any pre-v1.1.81 raw rows): a stored
position-signed CSP (+0.27) → normalized to −0.27 (raw put) → engine sell-flip → +0.27 (bullish).

### Tests
`tests/position-greeks.test.ts` (6): CSP/CC negate, longs keep, nulls pass through, sign helper.
Full suite green; typecheck clean.

### Data note
Open positions currently in the DB are already position-signed (last written by a chain-refresh),
so they're correct. Any rows last written by the pre-v1.1.81 sync would be raw until the next
sync re-writes them through the helper — a portfolio sync normalizes everything.

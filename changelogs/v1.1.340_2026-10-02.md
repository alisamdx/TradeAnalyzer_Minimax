# v1.1.340 — 2026-10-02

## The BPS-2 pool-selection study reads through the app

`scripts/fr-spread-pool-selection-study.mjs` opened `%APPDATA%\trade-analyzer\trade-analyzer.sqlite`
directly and carried a "run from a normal terminal, not a Claude session" warning. It was the last
bull-put-spread study that did; v1.1.338 and v1.1.339 moved the others onto the API.

**Change.**
- **`GET /api/v1/diagnostics/pool-selection-panel`** (`services/pool-selection-panel.ts`) returns the
  study's inputs, reduced the way the study reduced them:
  - one wheel `analysis_snapshots` payload per date, the latest `run_at` winning, each row projected
    to the eight fields the study reads. An unparsable payload stays as an empty date, and a non-object
    row stays as a row, so the study's raw-row and no-structure counts are unchanged.
  - each snapshot ticker's closes from **400 calendar days before the first snapshot** (~275 sessions).
    The study's signals look back by bar index, SMA200 at most, so every lookback on every snapshot
    date sees the same bars as the full series. Sending only that span keeps the response bounded.
- **The script** loads that panel through one `loadPanel()`; `--db <fixture>` builds the same shape
  locally for the self-test and is the only path that imports better-sqlite3. No `rebuild:node` needed
  for a real run.

Verified: `selftest-spread-pool-selection.mjs` 16/16 through the fixture path.
`tests/pool-selection-panel.test.ts` (5): latest run per date with other modes ignored, both payload
shapes and the eight-field projection, unparsable payloads and non-object rows kept, the series span
covering more than 200 sessions before the first snapshot, and an empty table.

No bull-put-spread study opens the live SQLite file any more.

## fix: drop the mislabelled short twin left by the pre-v1.1.155 import

v1.1.155 fixed the long/short sign bug so it cannot recur, but the bad row was already
persisted:

```
TSLA Jul 17 '26 $375 Put — BOUGHT 19.63, SOLD 15.98 → real −$364.06
  id 14  Long Put   −364.03   correct, written when v1.1.155 superseded the estimate
  id 39  CSP        +361.97   phantom, from the pre-fix import
```

One trade, two rows, opposite signs — a $726 swing in the direction that flatters the book. It
survived migration 071's dedupe because that grouped on `position_type`, and these twins
disagree on exactly that column.

**Rule:** when the same trade (ticker + strike + expiry + entry_date + entry_price + quantity)
has both a `Long *` row and a `CSP`/`CC` row, the `CSP`/`CC` one is the pre-fix artefact.
Deliberately narrow — it cannot touch a genuine wheel position, because a real CSP never shares
an entry price *and* date with a long option on the same contract.

Simulated against a copy of the live table before shipping: 29 → 28 rows, one removed.

The **$499.48 assignment** is a genuine convention difference, not an error: an assigned short
put defers its premium into the assigned stock's cost basis rather than realising it. The app
books it when the option closes; E*Trade holds it until the shares are sold. Worth remembering
whenever the app's realized figure is compared against a broker tax statement.

E*Trade's `Total Gain $ = 673.44` (unrealized) already matched the app's open-position mark of
**$673.45** to the cent before any of this.

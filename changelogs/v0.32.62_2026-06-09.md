# v0.32.62 — 2026-06-09

## Fix: paper trades — replace, not accumulate, on same-day re-runs

### Changes

**`src/main/services/paper-trading-service.ts`**

1. **`autoCapture`: DELETE before INSERT**
   - Root cause: `ON CONFLICT DO UPDATE` updated matching tickers with the new brief's data, but had no way to remove tickers that were in a previous run but not the current one. Each run could only ADD new tickers, never subtract stale ones. Running the brief 5–7 times in one day accumulated the union of all runs' picks (e.g. 13 income picks instead of 5).
   - Fix: added `DELETE FROM paper_trades WHERE brief_strategy = ? AND brief_date = ? AND status = 'open'` before the insert loop. Each brief run is now authoritative for its date/strategy — closed trades are unaffected.
   - The `ON CONFLICT` clause removed (no longer needed; plain INSERT after DELETE).

2. **`cleanupStalePicksAllDates()` method**
   - Finds all days where open paper trades include tickers not in the latest brief for that date/strategy.
   - Uses `json_each(db.picks)` to parse the picks JSON array in `daily_briefs` and identify stale entries.
   - Returns count of deleted rows for logging.

**`src/main/services/jobs/daily-intelligence-brief-job.ts`**

3. **Call `cleanupStalePicksAllDates()` in Stage 6**
   - Runs before `autoCapture` calls; non-fatal (warnings logged on failure).
   - Cleans up historical multi-run pollution once on the next brief generation.
   - Log: `[brief] pruned N stale paper picks from multi-run days`.

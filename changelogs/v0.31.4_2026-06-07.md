# v0.31.4 — 2026-06-07

## Earnings Refresh — redesign

### Universe
Now scans `DISTINCT ticker FROM constituents` (S&P 500 + Russell 1000, ~1,100 unique tickers) instead of portfolio + watchlist + conviction. The manual "Refresh" button in EarningsCalendarView still targets portfolio + watchlist + conviction for a faster targeted refresh.

### Smart caching
Replace the 24h TTL with date-aware logic:
- **Future date stored** → skip (still valid, no API call)
- **Past date or no date** → fetch next earnings date from E*Trade
- **Manual entry** → never overwritten

Effect: after the first full run, subsequent daily runs only refresh tickers where earnings just occurred — near-zero API calls on most days.

### E*Trade only (no fallback)
Removed `estimateFromPolygon` / analysis_snapshots fallback entirely. Single source of truth. If E*Trade doesn't return a date, the ticker shows `no-data` with a clear message. If E*Trade is not connected, the job returns `skipped` immediately rather than looping 1,100 failed calls.

### Rate limiting
- `callDelayMs` config (default 500ms, range 200–2000ms) configurable via Edit modal
- Delay only applied when an actual E*Trade API call is made (not on cache hits)
- First run estimate shown in Edit modal

### Files changed
- `src/main/services/earnings-service.ts` — smart caching, E*Trade only
- `src/main/services/jobs/earnings-refresh-job.ts` — constituents universe, readCallDelay, early-exit if no creds
- `src/renderer/src/views/BatchView.tsx` — earnings-refresh in hasDelayConfig, estimate label

# v0.32.61 — 2026-06-09

## Fix: critic context mismatch, LLM pass calibration, grade-F rule

### Changes

**`src/main/services/critic-service.ts`**

1. **Context mismatch: `unavailableReason` structures excluded from LLM context**
   - Root cause: `synthesizeVerdict` used `s.setup != null` to find the best structure for the LLM context. A structure with `unavailableReason` has a non-null setup object (it's `{ unavailableReason: "..." }`) so it was selected. The LLM received grade-F data with no legs, no strike, no credit — and correctly called it a flag, but for the wrong reason.
   - Fix: changed to `s.setup != null && !s.setup.unavailableReason` in both `synthesizeVerdict` (context building) and `getStructureExpiry` (earnings-in-window rule). Same fix applied in both places.
   - Impact: LLM now sees the actual gate-passing structure (e.g. call-zebra for VRT), not the ghost unavailable-PMCC.

2. **LLM prompt: explicit verdict calibration allows `pass` for clean picks**
   - Root cause: "Your job is to find problems, not validate decisions" + mandatory 2-sentence format ("what should the user check") meant the LLM almost never gave `pass`, even for picks with 0 rule flags.
   - Fix: added `VERDICT CALIBRATION` block with clear definitions of pass/caution/flag. "Do NOT default to 'caution' — only raise an issue if it is specific and actionable. Generic market risk is not a caution." Changed "exactly 2 sentences" to "1–2 sentences" allowing single-sentence confirmation for clean picks.
   - Impact: picks with genuinely no material concern can now receive `pass` verdict.

3. **`checkStructureGrade` rule: grade-F structures flagged deterministically**
   - Fires `severity: 'warning'` when the best valid (non-unavailable) structure for the strategy-relevant slugs is grade F.
   - Catches VRT-type picks (all buy slugs grade F) as an explicit rule flag, replacing reliance on LLM to catch the same issue.
   - Added `GRADE_RANK` module constant `{ A:5, B:4, C:3, D:2, F:1 }` for grade ordering.
   - Rule is registered in `runRuleChecks` after `checkEarningsInWindow`.

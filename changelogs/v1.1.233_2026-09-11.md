# v1.1.233 — 2026-09-11

## Auditing for "never worked once", before Monday rather than after

`core` 0.6.4.

The evening's four bugs shared a property: each was a path that had **never succeeded a single time**,
and nothing checked whether it ever had. So the audit was: *which phases have never produced a row, and
would we notice?* Run 6's own domain table named the suspects — `events_indexQuotes` **expected 0,
stored 0**, `events_insider` 0.

### 1. `ref_macro_series` had no seeder

The only `INSERT INTO ref_macro_series` in the repository was inside a test fixture.

So `runIndexQuotes` read `WHERE enabled = 1`, found nothing, and returned
`skipped('no enabled series in ref_macro_series')` on every run since B7a. `raw_index_quote`: **0 rows**,
confirmed on gen-001.

The sharper half is QC-901. It is **blocking**, and it maps over the enabled series:

```ts
const series = ctx.db.prepare('SELECT symbol, sane_min, sane_max FROM ref_macro_series WHERE enabled = 1').all();
return series.map(...)
```

On an empty table that returns zero evaluations — **a blocking check that cannot fire, guarding a value
that is never fetched.** Same family as the conviction band that could never fire and the liquidity gate
that always did: the check looked healthy precisely because nothing it could object to reached it.

Fixed by `ensureMacroSeries`, called from preflight beside `ensureTradingCalendar`, idempotent, seeding
VIX with the `[5, 150]` band QC-901's own evidence note cites. VIX3M and VVIX are deliberately **not**
seeded: unverified symbols would fail every run, which is noise asserting nothing.

### 2. The insider sweep asked for a file that does not exist yet

`runInsiderSweep` fetches `form.YYYYMMDD.idx` for `run.tradingDate`. EDGAR publishes that index late in
the evening; the collector's 17:05 slot runs hours earlier (in practice 18:05–19:33, behind the
after-close chain). Both the 9/10 and 9/11 runs got **404** on a URL that serves correctly later the
same night.

A same-day fetch was therefore structurally incapable of storing a Form 4, and `events_insider` sitting
at 0 is indistinguishable from a day nobody filed one.

It now tries today's index, falls back to the previous trading day's on a 404, and records the date it
**actually used** in `params` — so a late row is identifiable as late rather than mislabelled.
`previousTradingDay` is new in `trading-calendar.ts` and looks back a fortnight, covering any weekend
plus the longest run of consecutive holidays.

### 3. A precondition that existed only in a comment

`backfillQueueClear` has said this since B5:

> "Whether the backfill's review queue is clear — B5's gate, and **a precondition on the pilot's
> clean-day streak** (04 §7.2). … Counting such a day toward the streak would certify a generation whose
> history is known to be wrong."

It was referenced by **nothing**. `pilotExitStatus` never called it. A generation could have been
promoted with an unruled ticker-reuse candidate outstanding — the precise outcome the comment forbids.

Now the ninth pilot-exit condition. **Its real scope is narrower than the prose**, and that is recorded
rather than silently widened: `reviewQueue` selects `severity = 'blocking'`, while QC-204/205 are
warnings that promote by value, so it catches a discontinuity severe enough to have been promoted — not
every one. Changing what it measures is a separate decision from making it load-bearing.

### 4. The rule behind all three

`packages/core/test/preconditions-are-wired.test.ts` — any exported function whose docstring claims to
be a *precondition on* or *gate on* something must be referenced outside its own file.

Four times in one evening, prose asserted a mechanism that did not exist: `void dte;` parked after a
`return`; a comment claiming the host signed a request it never signed; a blocking check reading a table
nobody wrote; and a precondition nothing called. **Prose is what gets read when someone asks "is this
handled?"** — so the claim itself is now the thing under test.

The scan carries its own non-vacuity guard (`claimedPreconditions().length > 0`), because a regex that
stops matching makes every assertion below it pass for free — the failure mode of every source scan in
this repository.

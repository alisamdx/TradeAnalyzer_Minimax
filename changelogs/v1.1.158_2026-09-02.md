# v1.1.158 — 2026-09-02

## fix: Performance tab styling now matches the rest of the Portfolio view

The v1.1.157 panel styled its stat boxes inline with a light palette — white backgrounds,
`#e5e7eb` borders, `#6b7280` labels — which read as bright cards punched into the app's dark
surface. Reported straight after shipping: *"the ones at the top are more easy on the eyes."*

### Change

The panel now reuses the existing markup rather than approximating it:

- `Stat` emits `.summary-card` / `.summary-label` / `.summary-value` / `.summary-sub` — the same
  structure as the Total Positions / Unrealized P&L cards above it
- the stat row uses `.pnl-summary-cards`, so it inherits the same responsive grid
  (`auto-fit, minmax(140px, 1fr)`) instead of an ad-hoc flex wrap
- P&L and ROC cells use the existing `.positions-table td.positive` / `.negative` rules
- **every hardcoded hex is gone** — remaining colours are `var(--text-muted)`, and
  `.positive` / `.negative` resolve through `var(--success)` / `var(--danger)`

Return-on-deployed and Realized P&L now carry a positive/negative tone like the cards above,
rather than the arbitrary green highlight the first version used to mark one card as important.

The point is not only that it looks consistent today: colours defined once in `styles.css` follow
any future theme change, whereas a second hand-maintained palette silently drifts. That drift is
exactly what produced light-mode cards in a dark-mode view.

No behaviour or numbers changed. Suite: 1035 passed.

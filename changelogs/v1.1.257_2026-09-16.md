## Fixes

### Insider sweep: fall back on 403 as well as 404

Measured with a declared User-Agent on 2026-09-16: `form.20260915.idx` 200 (839 KB), `form.20260916.idx` 403 with a 215-byte `AccessDenied`, a future date 403. Without a contact in the User-Agent SEC returns 403 for everything (a 4,818-byte "Undeclared Automated Tool" page) while `data.sec.gov` still answers 200 — the collector's own 403 read "Access Denied", which is the not-yet-published case, so its EDGAR contact is configured correctly. The fallback, written against the 404s of 2026-09-10/11, never fired on a 403. This is a collection change and cannot be rehearsed; tomorrow's run is its test.

### Recommendations key on the ticker asked (dictionary v18)

`makeRecommendationIngest` stored `ticker: r.symbol ?? opts.ticker`. In the 9/14 sweep Finnhub answered four tickers for another listing:

| asked | answered | |
|---|---|---|
| GOOG | GOOGL | same issuer; GOOG's rows landed on a ticker that has its own |
| BRK.B | BRK.A | same issuer |
| GFL | GFL.TO | same issuer, Toronto listing |
| LLYVA | FWONA | **different company** (Liberty Live vs Formula One) |

`ticker` is now always the ticker asked; Finnhub's symbol is kept in the new nullable `provider_symbol`. **QC-909** (warning) fires when a ticker's latest rows carry a different `provider_symbol`, for a ruling — same issuer or not is not decidable from symbols. Rows stored before v18 keep the old keying. A replay of run 8 will now report `different` for those four responses, which is the parser change it is meant to surface.

# v0.32.95 — 2026-06-13

## Brief Replay — premium-history readiness banner (in-app check)

### Why

The `options_premium_history` table (v0.32.94) starts empty and only becomes useful for
true income/wheel ROC after months of daily capture. Rather than an external reminder,
an in-app check surfaces in Brief Replay exactly when there's enough matured data to act
on — and stays invisible until then.

### What

- **`BriefReplayService.getPremiumHistoryReadiness()`** → `PremiumHistoryReadiness`
  (`totalRows`, `days`, `fromDate`, `toDate`, `maturedDays`, `thresholdDays`, `ready`).
  - **Matured** = captured ≥ `MATURITY_DAYS` (45) ago, so the recommended ~30–45 DTE
    option would have expired and realized ROC is computable.
  - **ready** = `maturedDays >= THRESHOLD_DAYS` (40, ≈ two months of matured captures).
- **IPC** `replay:premium-history-readiness` + preload `briefReplay.premiumHistoryReadiness()`.
- **`PremiumHistoryBanner`** in `BriefReplayView`:
  - empty table → renders nothing.
  - accumulating → muted note `⏳ N/40 matured days (M captured since DATE)`.
  - ready → green note prompting to build the ROC view.

### Tests

- `tests/options-premium-history.test.ts` (+3): not-ready below threshold (recent dates
  excluded from matured count), ready at/above threshold, empty-table state. Full suite:
  269 passing.

### Follow-up

When the banner flips to "ready" (≈ a quarter from first capture), build the real
income/wheel ROC view/analysis off `options_premium_history` joined to forward prices.

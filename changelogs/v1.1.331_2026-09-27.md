## SEC's own ticker map overrides a stale Polygon CIK

Polygon's reference data gives FWONA, LLYVA and LLYVK the CIK **0000869614**. At SEC that is the old
*Liberty Media Corporation*: no tickers, and no 10-Q or 10-K anywhere in its filing history. SEC's
`company_tickers.json` maps FWONA to **1560385** (Liberty Media Corp) and LLYVA/LLYVK to **2078416**
(Liberty Live Holdings, Inc.). Because every EDGAR lookup keyed on Polygon's CIK, the collector asked
SEC about the wrong filer for these three:
- no report filings;
- no XBRL facts;
- no insider-transaction mapping;
- and QC-603 could not see a filing for LLYVA/LLYVK.

A cross-check of the whole universe found 1,027 stocks matching SEC and only these 3 different. The
other 53 are ETFs, which SEC's map does not list.

### What changed

- **New raw table `raw_sec_ticker_map`** (ticker, cik, registrant). SEC's `company_tickers.json` is
  fetched weekly (1 call, ~1 MB) and filtered to the universe at ingestion (recipe `sec_ticker_map`).
  Two format details, both from the live file:
  - the body is an object keyed "0", "1", … and not an array;
  - `cik_str` is a number and is zero-padded. SEC's `BRK-B` is stored as `BRK.B`.
- **One rule for which CIK to use** (`collector/cik.ts`): SEC's CIK from the latest capture, else
  Polygon's. It is used by:
  - the collector's `cikMap`, and so by the filings sweep, the daily-index report filings and the
    insider sweep;
  - QC-603, QC-701 and QC-702.

  Only the latest capture counts, so a ticker SEC stops listing falls back to Polygon rather than to an
  old SEC row.
- **The fetch runs first in phase 8's EDGAR block,** so a corrected CIK is used the same night.
- **New check QC-703 (warning, exempt from repeat escalation)** reports each ticker whose Polygon CIK
  disagrees with SEC's, naming both. It closes `provider_fixed` when Polygon agrees. It is a report, not
  a gate, because the lookups already use SEC's CIK.

### Checked on SEC's real file

Run against a scratch copy of the generation with the real `company_tickers.json` downloaded on
2026-09-27:
- **1,030 universe rows stored.**
- **QC-703 fires on exactly FWONA, LLYVA and LLYVK**, each naming SEC's CIK.
- **LLYVA and LLYVK still fire QC-603 for now.** Their filings under the correct CIK have not been
  fetched yet; the filings sweep asks never-asked CIKs first, so they arrive within the next runs.

### A column named `title` fails TA2's AC-13 scan

The inspector test forbids renderer code from naming any dictionary column, and `title` is also an HTML
attribute used across TA2's views. So the column is `registrant`, not `title`, and no exception was
added to the scan.

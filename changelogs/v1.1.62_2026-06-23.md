# v1.1.62 — 2026-06-23

## IBKR combo orders silently dropped — fills never reached the paper account

### Symptom
The app was running during trading hours, armed for an unattended paper day on IBKR
(`/exec/state` → `broker: "ibkr"`, `brokerConnected: true`, `executionMode: "paper"`,
`engineState: "running"`, `armed: true`). The live activity feed and audit log showed two
complete AVGO wheel entries:

```
proposal_created · AVGO → gate_pass → proposal_approved #N → order_submitted #N (open)
```

…but **no `order_filled` event, no fills, no `exec_positions` rows, and nothing at the
brokerage paper account.** Orders were stuck in `submitted` forever.

### Cause
`IbkrExecutionBroker.placeOrder()` built its IBKR `Order` object **without** the two legacy
compliance flags `eTradeOnly` and `firmQuoteOnly`. Newer TWS **silently drops** a combo (BAG)
order when these are absent — it sends no `orderStatus`, no `error`, and never fills — while the
`ib.placeOrder(...)` call itself returns cleanly. So the engine's seam saw a successful
submission (`accepted: true`, status `submitted`), recorded the `order_submitted` audit row, and
waited for a fill that TWS was never going to send.

This is a documented TWS gotcha (CLAUDE.md → "IBKR gotchas"): *"Orders need `eTradeOnly:false,
firmQuoteOnly:false` or newer TWS silently drops them (no status, no error)."* All three
validated diagnostic scripts (`scripts/ibkr-fill-calibration.mjs`,
`scripts/ibkr-level3-spread-test.mjs`, `scripts/ibkr-options-permission-test.mjs`) set both flags
— which is exactly why the live-paper validation on 2026-06-18 succeeded through the scripts but
the engine's own placement path was never exercised end-to-end. The bug lived only in the
production placement path.

### Fix
Extracted a single exported, unit-tested `buildComboOrder()` that constructs the combo LMT order
for **both** the live placement and the whatIf permission preflight, and always sets
`eTradeOnly: false` + `firmQuoteOnly: false` (plus `transmit: true` and the `NonGuaranteed`
smart-combo routing param). Both call sites now route through it, so the two order objects can
never drift apart again.

```ts
const order = buildComboOrder({
  action, lmtPrice,
  totalQuantity: o.contracts,
  orderRef: o.clientOrderId,
  account: this.accountId ?? undefined,
});
```

### Validation (FR-SEY-5)
Validation-exempt: this is a fix to order **delivery**, not to trade logic. It does not change
which trades the engine selects, how it sizes them, or how/when it exits — those decisions were
already made upstream; the orders simply weren't reaching the broker. No scoring weight, entry/exit
policy parameter, or risk-gate rule changed.

### Files
- `src/main/execution/ibkr-execution-broker.ts` — new exported `buildComboOrder()`; `placeOrder()`
  and `whatIfProbe()` both route through it.
- `tests/ibkr-execution-broker.test.ts` — regression: `eTradeOnly`/`firmQuoteOnly` are `false` on
  live and whatIf orders; optional `orderRef`/`account`/`whatIf` are omitted when unset.

### Tests
`tests/ibkr-execution-broker.test.ts` → 29 passing. Typecheck clean.

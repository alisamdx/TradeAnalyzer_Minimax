# v1.1.202 — 2026-09-07

## fix — the NewApp generation corrupted because an app was launched from a container

The open bug recorded at v1.1.201 is resolved, and none of the three hypotheses
written down with it was right. `applyDictionary` running on every tick, the FK
behaviour of the rebuild paths, and the archive/transaction ordering were all
innocent.

### What it was

Both applications had at some point been launched from a **containerised (MSIX)
shell**, which redirects `%APPDATA%` into that package's `LocalCache\Roaming`
with **copy-on-write** and announces nothing. The evidence was on disk:

- A full Electron profile for each app under
  `AppData\Local\Packages\<pkg>\LocalCache\Roaming\` — `trade-analyzer-next\`
  (with `data\gen-001\data.sqlite`) and `trade-analyzer\`, the latter's
  `Preferences` and `blob_storage` written **2026-09-07 17:16**, inside the
  corruption window.
- Listing the generation directory through `%APPDATA%` shows `gen-001` **and**
  `gen-001-corrupt-20260907`; listing the container path shows `gen-001` only. A
  redirected listing merges both views, so there are demonstrably two
  `data.sqlite` files behind one logical path.

The redirect is per file. `data.sqlite` had been copy-on-written into the
container while `-wal` and `-shm` still fell through to the real ones — so the
two processes coordinated through **one lock and one write-ahead log while
writing two different base files**. WAL frames written against one base were
read and checkpointed against the other.

Every symptom follows, including the ones that made it look like a code bug:

- **`Tree 5` is `meta_response`**, confirmed by building a fresh generation from
  the dictionary and reading `sqlite_master.rootpage`. It is the table
  `universe_seed` writes hardest, so it is where mismatched frames land first —
  and it retires the note that "the damage reaches an early table".
- **Identical 2,318,336 bytes on two runs** — deterministic interleaving, not a
  deterministic code path.
- **1,587 membership rows then ~1,001 `meta_response` rows** — the three list
  responses plus about a thousand of the 1,089 per-ticker reference calls.

### The fix

- **`assertNotRedirected`** (`@tradeanalyzer/core`) measures the redirect by
  writing a marker and going to look for it. That is the only honest test:
  `%APPDATA%`, `process.execPath`, `cwd()` and `import.meta.url` all read as the
  real thing from inside a container.
- **`ElectronCollectorHost.openGenerationDb()` calls it before `new Database(...)`**,
  as does the new exe's `openGeneration()`. Each checks the shared pointer's
  directory as well as the generation's, because `dataRoot` is configurable and
  the pointer is not.
- The guard previously existed **only** in `queue-job.mjs` and
  `diagnose-generation.mjs` — the two places that could not destroy anything —
  while the applications that could had none. Both scripts now import the one
  implementation. Same shape as the portfolio cash snapshot and the E*Trade OAuth
  transport: a capability that must apply to every caller belongs in the function
  they all call.
- **`meta_open_handle`** (dictionary version 6) records which application opened
  the generation, with its resolved `db_path`. Both apps write a row on open, so
  "are the two looking at the same file" is answered by reading rather than
  inferring — the question that was answered wrongly several times on 2026-09-07,
  because a redirected process reads every path back exactly as it wrote it.
  `diagnose-generation.mjs` prints the rows and flags a disagreeing path or a
  lone entry.

### Tests

`packages/core/test/appdata-redirect.test.ts` (12) and `test/open-handle.test.ts`
(4). The redirect suite builds a **real fake container** — a junction whose
`LocalCache\Roaming` *is* the probed directory — so the guard is asserted to
**fire**, not merely to stay quiet. A guard that can only be tested for silence
is the own-at-strike band again: structurally incapable of firing and
indistinguishable from one nothing violates.

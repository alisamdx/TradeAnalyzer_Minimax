# v1.1.253 — 2026-09-16

`@tradeanalyzer/core` 0.6.14. Found by running v1.1.252's rewritten checks read-only against the real 2026-09-16 generation (`packages/core/scripts/gate-preview.mjs`) before they sent an email.

## What the preview showed

- QC-410: 81 of 495 tickers fired. The large gaps were the real finding (LOPE 19.1 %, AMG 18.1 %, ECG 17.3 %, AIZ 12.0 %, ITT 10.3 %, MIDD 9.5 %, FERG 7.4 %). But a group of dividend payers fired with Greeks that matched the chain: EIX implied 54.72 on a 54.81 chain with parity at 53.00; CMCSA 23.73 on 23.73, parity 23.46; CLX 85.29 on 84.86, parity 84.04.
- QC-414: did not fire (every contract reachable). QC-407: 549 tickers evaluated, none disagreeing — it had evaluated zero before v1.1.252. QC-008: 3 capped windows, none fired.
- QC-009: still 1,641 on `raw_edgar_fact`, plus 330 on `raw_earnings_event` and 322 on `raw_analyst_estimate`.

## Fixes

- **QC-410's reference is the chain `underlying_price`.** Put-call parity `S = C − P + K·e^(−rT)` has no dividend term, so it reads low by the present value of any dividend before expiry — exactly the tickers above. The chain price is cross-checked by QC-407 and is what `greek-consistency.ts` in the existing app compares against, so both apps now apply one definition. Pinned-delta detection models at the chain price too. Parity is still computed and reported, and no longer required (a ticker with fewer than 3 usable pairs is now evaluated).
- **QC-009 reads the current dictionary version.** `meta_dictionary` keeps a row set per version; `SELECT DISTINCT table_name, natural_key` across all of them evaluated v16's `raw_edgar_fact` key alongside v17's, so the `period_start` fix could never clear the finding.
- **QC-009 groups by `source_response_id`.** The capped Finnhub window stores its rows and its uncapped halves store them again. That is what QC-008 requires, not an idempotence bug. One response producing a key twice still fires.

## Tests

`greek-checks.test.ts`: a chain whose quotes sit 3 % below the chain price with Greeks at the chain price does not fire. `events.test.ts`: QC-009 ignores a superseded dictionary version's key (built from the live `meta_dictionary` column list, after a hand-typed list failed on a column that does not exist), and does not fire on one earnings row captured by two responses. All three fail on v1.1.252. Core 552 passing.

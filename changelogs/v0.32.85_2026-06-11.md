# v0.32.85 — 2026-06-11

## Fix: rationale max_tokens sized for 75 candidates, not 25

### What the validation run showed

First live run after v0.32.84 (brief id 221–225, 2026-06-12T02:06Z):

- `runMeta.aiError`: "rationale response hit max_tokens — salvaged 38/75" — the
  v0.32.81 visibility fix worked exactly as intended (previously this was silent).
- Final picks got 15/25 rationales: wheel/bullish/bearish were salvaged; income and
  buy (last in the JSON array) were past the truncation point.
- `earningsFallback: {updated: 1, skipped: 46, failed: 2}` — the v0.32.82 per-pick
  E*Trade fallback worked (DELL got its missing earnings row).

### Root cause

Stage 5 sends **all stage-4 candidates** to the rationale call — up to 15 per
strategy (75 total), not the final 5×5 — because the liquidity gate runs at
assembly, after synthesis. The v0.32.81 sizing assumed 25 picks; 75 × ~90 tokens
≈ 7K output > 4096.

### Fix

`max_tokens: 4096 → 16384` with a comment documenting the real request volume.
(Claude Sonnet 4.6 supports up to 64K output tokens; only actual output is billed,
~$0.10/run at 7K.)

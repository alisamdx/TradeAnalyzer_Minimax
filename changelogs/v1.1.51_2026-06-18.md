# v1.1.51 — 2026-06-18

## IBKR combo pricing: price from the legs, not the BAG

### The gap (found in live Phase 7 calibration)
With the IBKR paper account connected and an options market-data subscription active, the first
live `priceCombo` call returned **no bid/ask**. Diagnosis (`scripts/ibkr-md-diagnose.mjs`):
single-leg option data flows fine (AAPL 280P → 1.90/2.00), but IBKR returns **nothing for the
smart-routed BAG combo**. This is a known IBKR behavior — combo NBBO over `reqMktData` is
unreliable/empty.

### The change
`IbkrExecutionBroker.priceCombo` no longer subscribes to the BAG. It now requests top-of-book for
**each leg** (a short streaming subscription per leg, resolved when bid+ask arrive or after a
timeout) and nets them into the combo quote via a new pure helper:

```
comboQuoteFromLegs(legs, perLegQuotes):
  sold leg  → adds its premium (credit)
  bought leg → subtracts its premium (debit)
  bid  = Σ(short.bid) − Σ(long.ask)   // conservative: sell low, buy high
  ask  = Σ(short.ask) − Σ(long.bid)
  mid/netCredit = Σ(short.mid) − Σ(long.mid)   // ratio-aware
```

A leg with no quote raises a clear error (`no market data for … (options data subscription?)`).

### Validated live
`scripts/ibkr-price-from-legs.mjs` on the paper account:
`SELL 280P (1.90/2.00) / BUY 275P (1.30/1.41)` → **bid $0.49 / mid $0.59 / ask $0.70** per share
(~$60 credit/contract, max loss ~$441). Matches a hand-check.

### Requires
An options market-data subscription (OPRA add-on) on the account — order placement/fills don't
need data, but pricing proposals does. The paper account now has it (US Equity and Options Add-On
Streaming Bundle + the Snapshot base bundle), shared with the paper account.

### Tests
`tests/ibkr-execution-broker.test.ts`: `comboQuoteFromLegs` — credit spread nets correctly, lone
short put (CSP), net-debit case, leg ratios. Full suite: **604 passing**.

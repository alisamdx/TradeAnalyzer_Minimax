# v1.1.58 — 2026-06-22

## Unattended paper operation (spec 08, Part A)

The execution engine can now run a **full unattended paper trading day**: leave the app running and
it regenerates entries from today's brief, manages and exits positions, and reports what it did — no
clicks. Implements Part A of `Requirements/v2-execution/08-unattended-operation.md` (#2). The Trading
Desk visual redesign (tabs/timeline) and the lean intraday batch (#4) remain deferred.

### The arm switch
`exec_config.automation_mode` — a single control with three stances:
- **Off** (`semi`) — approve each entry (current behavior).
- **Dry-run** (`dry_run`) — run the **full** cycle (pull today's brief, evaluate entries + exits)
  but **place nothing**; would-be decisions go to the new `exec_dry_run_log`, deduped per ET-date +
  ticker, with **no audit pollution** (gate evaluation passes `audit:false`).
- **Armed** (`unattended`) — **auto-approve entries** + **auto-fire discretionary exits**
  (protective exits were already auto). No clicks.

**Auto-entry is PAPER-ONLY** — `ExecutionEngine.tryGenerateEntries` auto-approves only when
`executionMode === 'paper'`; live always stays semi-auto (human + type-to-confirm), regardless of
`automation_mode`. The UI's Armed button is disabled in live too (defense in depth).

### Cycle loop driver (was unwired)
`ExecutionCore.startLoop` existed but nothing called it. The engine now starts the management/entry
loop when it goes running (`enableCycleLoop`, set by index.ts) at `cycle_interval_sec` (default
120s), and `ExecutionCore.stopEngine` stops it. Tests omit `enableCycleLoop` so no real timer leaks.

### Brief-freshness gate (#3, safety prerequisite)
`loadBriefPickInputs(db, strategies, now, requireToday=true)` returns picks only from a brief
generated **today (ET)** — never the prior-day after-close brief. The engine passes `requireToday`;
stale brief ⇒ the engine no-ops. Kills the 10:00–10:15 stale-brief window.

### Notifications (spec §2.5)
- **Per-action** (`notify_per_action`): on each entry, exit, and kill-switch trip → OS push (gated
  by `notify_push`, via Electron `Notification`) + email (via the existing `EmailService` when SMTP
  is configured).
- **End-of-day digest** (`notify_eod_digest`): one summary email built on the market open→closed
  transition, **only when armed**, deduped once per ET-day.
- A pluggable `ExecNotifier` is injected into the engine (no-op default for tests); index.ts wires
  the concrete email+push sink.

### Keep-awake (spec §2.6)
While **armed** (running + unattended + paper), index.ts starts
`powerSaveBlocker('prevent-display-sleep')`; released on disarm/stop. The engine raises an
`onArmedChange` callback when the armed state flips.

### UI
- **Trading Desk:** new **Automation (arm switch)** panel (Off / Dry-run / ⚡ Armed, with the
  paper-only guard) + prominent header pills (`⚡ ARMED` / `DRY-RUN`).
- **Execution Settings:** new **Automation & notifications** section (automation mode, cycle
  interval, per-action, push, EOD digest).

### Schema / API
- Migration **058**: `exec_config` columns `automation_mode`, `cycle_interval_sec`,
  `notify_per_action`, `notify_push`, `notify_eod_digest`; new table `exec_dry_run_log`.
- `ExecConfig` + `ExecEngineStateView` (`automationMode`, `armed`) + new `ExecDryRunRow` type;
  governor get/update mapping; `execution:get-dry-run-log` IPC + `window.api.execution.getDryRunLog`.

### Validation (FR-SEY-5)
Validation-exempt by construction: nothing changes which trades are selected or how they're
sized/exited. Auto-entry only removes the human click on already-selected picks (every auto-entry
passes the full re-priced risk gate); the freshness gate only *prevents* acting on stale picks; caps
(1/day, 3/week, concurrent, per-ticker/sector, capital) and the kill switch bind unchanged.

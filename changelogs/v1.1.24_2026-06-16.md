# v1.1.24 — 2026-06-16

**Daily Brief accuracy audit (2026-06-16 brief) — unbounded-risk reporting fix.**

Follow-up to v1.1.23. The audit found that the bearish brief's top structures carried hidden unlimited risk.

## Reverse lizards reported a tiny bounded max loss instead of unbounded

`reverse-big-lizard` and `reverse-jade-lizard` are a **short put spread + a NAKED short call**. The naked call makes the upside loss unlimited. But `buildSetup`'s P&L classifier matched them on the `callSell && putSell && putBuy` signature and computed `maxLoss = −(putSpreadWidth − credit)` — the *bounded, protected* put side — ignoring the naked call entirely.

Live impact on the 2026-06-16 brief (3 of 5 bearish picks were reverse-big-lizard):

| Pick | Reported maxLoss | Reported annualized return | Reality |
|---|---|---|---|
| FLUT | −$11.25 | **100,248%** | unbounded (naked call @ $110, spot $108.98) |
| LBRDK | −$17.50 | 15,154% | unbounded |
| ARE | **+$43.75** (a *positive* max loss) | 7,658% | unbounded |

### Fix
The single-expiration P&L logic is now a pure, exported `classifySingleExpiryPnl(legs, dollarCredit, netCreditPerShare)`. Any naked-short-call structure (naked call, strangle/straddle, and the reverse lizards) returns `maxLoss = null` = **unbounded**, alongside the already-correct bounded branches (naked put, verticals, iron condor, jade/big lizard). With `maxLoss = null`, `annualizedReturn` is also `null` (return-on-capital is undefined when capital is unbounded) — killing the absurd 100,000% figures. The renderer/email already handle null maxLoss/return (income strangles produce them), so no display change was needed.

### Ranking is unchanged (no FR-SEY-5 gate)
The structure's lab `premiumScore` reads `capital = |maxLoss|`, falling back to `shortPutStrike × 100` when `maxLoss` is null (existing logic, line 614–616). For these structures that fallback yields the same premium-score band (e.g. FLUT ~9% return on the put-strike basis → still ≥1.5% → 25/25), so the grade and the bearish structure ranking are unchanged. This is purely an honest-risk-display correction; it does not alter which tickers or structures the brief surfaces, and the v2 execution engine is inflection-only/defined-risk-only and never trades these. Validate-before-ship (FR-SEY-5) therefore does not apply — there is no trade-selection change to validate.

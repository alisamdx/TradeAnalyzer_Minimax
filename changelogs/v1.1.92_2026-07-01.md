# v1.1.92 — 2026-07-01

## Fix: evening batch chain no longer halts on a dormant E*Trade token

### Symptom
The 17:00 orchestrator slot failed at Daily IV Update with
`E*Trade connectivity check failed: terminated` on **8 of the last 10 trading days**
(2026-06-18 → 07-01), stopping the whole evening chain. The user manually re-ran at
~18:30–22:00 ET — which worked *without re-authenticating*, and also meant the daily
brief measured option-chain liquidity on extra-stale post-close quotes (see
NEW_FRONTIER §11's measurement-time artifact).

### Root cause
A **dormant token (inactive >2h)** — idle since the ~10:40 morning slot — does not
reliably fail as a clean 401. E*Trade kills/hangs the response stream and undici
surfaces `TypeError: terminated`. The connectivity check only attempted `renewToken()`
when the error message looked auth-shaped (`401|token|auth|oauth`), so for `terminated`
it **never tried the renewal that would have fixed it** and failed the job. The
orchestrator's own pre-wake renewal (`_checkEtradeToken`) swallowed all errors
silently, hiding the problem. (Same quirk family as the documented "dormant token
silently yields an empty chain".)

The manual evening runs succeeded because opening the app triggers `withRenew` paths
(v1.1.48) that revived the token before the batch ran.

### Fix
- `daily-iv-capture.ts` connectivity check: **unconditionally renew-and-retry once on
  ANY probe failure** (renewing an active token errors harmlessly and is caught). Only
  when the retry also fails does it classify: auth-shaped error → "token expired,
  reconnect" CTA (true midnight-ET hard expiry — the only case still needing a human),
  anything else → genuine connectivity failure (message now includes
  "after token renew + retry").
- `batch-orchestrator-job.ts` `_checkEtradeToken`: pre-wake renewal failures are now
  logged (`console.warn`) instead of silently swallowed.

### Operational effect
The away-at-work dormancy case is now fully automatic — no manual evening re-runs.
Manual re-auth remains only for the true midnight-ET token expiry. The evening brief
should run at its designed ~17:05 ET slot, on quotes ~1.5–5h fresher than the recent
manual re-runs.

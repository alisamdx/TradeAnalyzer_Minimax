# v1.1.97 — 2026-07-02

## Save filter results to a watchlist

### Why
The user runs filter templates (especially **Wheel Opportunity** over a full universe) to
hunt for candidates — e.g. good-foundation, premium-selling names under $50 — then wants to
carry that result set into other tools (Analysis, LEAPS+CSP, other filters). Navigating from
a filter run into per-ticker screens one at a time was clunky. A watchlist is the app's
natural "reusable basket," and the Screener already had a **Save as Watchlist** action
(FR-2.4) — the Filter Templates view did not.

### What
The results header of **every** filter template now has a **⭐ Save to Watchlist** button:

- Saves **all current matches** in one action (not per-row — the whole result set).
- Target is either a **new** watchlist (type a name) or an **existing** one (dropdown).
- Duplicates already in the target list are skipped and reported:
  `Saved 12 tickers to "Sub-$50 Wheel", 3 already present`.
- After saving, the watchlist list refreshes so the new list is immediately selectable as a
  filter **source** and everywhere else watchlists are used.

### Implementation
- Renderer-only change in `src/renderer/src/views/FiltersView.tsx`:
  - `handleSaveToWatchlist` orchestrates `watchlists.create` (new) then
    `watchlists.items.addBulk`, or `addBulk` straight to an existing id.
  - Inline form in the shared results header, so it appears for all templates automatically.
  - `loadWatchlists` extracted from the mount effect and reused after a save.
- No new IPC or types — both `watchlists.create` and `watchlists.items.addBulk` already
  existed in the preload bridge.

### Notes
- Bulk save uses the full `results` set (all matches), independent of the current sort.
- Scoped intentionally to bulk save-all. Per-row cherry-pick into a watchlist was left out to
  keep the change tight; easy to add later if wanted.

# v1.1.55 — 2026-06-18

## v2 execution trades Iron Condors (income) + per-strategy composite floors

Step 2 of the multi-strategy book: the neutral, high-IV, two-sided theta workhorse.

### Iron condor (income)
- New `iron-condor` `ExecStructure` (4-leg). Income picks map to the lab's iron-condor setup
  (`brief-entry-source` `IRON_CONDOR_STRATEGIES`).
- **Budget-width extended to the condor**: `iron-condor` added to `BUDGET_WIDTH_SLUGS`, so each long
  wing is sized to the per-trade budget by the **existing per-wing selector** (each long leg already
  matches its same-side short in the build loop). Each wing ≤ budget ⇒ the condor's max loss ≤ budget
  (conservative — the other wing's credit further offsets it). Today's income condors were
  $2.7k–$12.6k max loss; budget-sized they land ~$400.
- **Exit/order/sizing reused unchanged** — the exit policy is credit + DTE based (no per-strike
  logic), the order path is an N-leg BAG, and sizing is on `maxLossPerContract`. The engine was
  already structure-agnostic.

### Per-strategy composite floors
A single global `min_composite_score` is wrong for a book — composites aren't comparable across
strategies. New `exec_config.min_composite_by_strategy` (JSON `{strategy: floor}`) overrides the
global floor per strategy; absent strategies fall back to it. Income scores on a lower scale (replay
picks all < 50) and composite isn't predictive for condors, so the inflection 50 floor would gate out
**every** income pick — income's floor is 0 (the validated population). `RiskGovernor` parses/persists
the JSON; `EntryPolicy.filterPick` uses `byStrategy[strategy] ?? globalFloor`.

### Validation (FR-SEY-5)
`scripts/fr-iron-condor-study.mjs` — budget-sized iron condor (0.16Δ shorts, 30 DTE, 50% PT / 2× stop)
over 1,397 income replay picks:

| | win | return / max-loss | avg max loss |
| --- | --- | --- | --- |
| **income iron condor** | **82.3%** | 5.7% | $403 (sizeable) |
| baseline (entry −180d) | 75.4% | 1.9% | $414 |

Beats baseline by +6.9 pts win / +3.8 pts return — a real selection edge, and the highest win rate of
any strategy (two-sided/neutral). Income composites are all < 50 in the sample, so the per-strategy
floor (income = 0) ships the validated population. Migration 057 enables income + adds the floor map.

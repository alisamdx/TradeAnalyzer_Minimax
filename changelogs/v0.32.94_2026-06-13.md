# v0.32.94 — 2026-06-13

## Daily Options Premium History — durable premium capture for future ROC analysis

### Why

Premium-based strategies (income, wheel) had **no durable, queryable history of quoted
option premium**. Wheel premium lived only as JSON blobs in `analysis_snapshots`
(latest ~20 read; single strike per ticker), and income structures were captured only
for the ~25 daily-brief final picks in `daily_briefs` — which is pruned at 90 days. So a
year out we still could not compute **true** income/wheel return-on-capital; Brief Replay
was stuck with the stayed-above-strike proxy.

### What

- **Migration 040** — new `options_premium_history` table: one row per
  `(as_of_date, ticker, strategy)` with `structure` (CSP/CC), `last_price`, `strike`,
  `expiration`, `dte`, `delta`, `bid`, `ask`, `premium`, `annualized_return`, `iv`,
  `iv_rank`, `open_interest`, `breakeven`, `captured_at`. Indexed on date and on
  `(ticker, strategy, as_of_date)`. **Never pruned.**

- **New batch job** `daily-options-premium-history` (`daily-options-premium-history-job.ts`),
  registered **last** in `index.ts` → highest `sequence_order` (bottom of the batch list),
  and included in the orchestrator's job list. Runs after the 06:00 wheel snapshot.
  - **Wheel** rows reuse that same-day wheel global snapshot (`loadTodayWheelSnapshot`) —
    zero extra E*Trade calls. Guarded: only used if the snapshot's `run_at` is today (ET).
  - **Income** rows fetched live via `analyzeTicker('options_income', { forceCache: true })`
    over the S&P 500 + Russell 1000 universe (highest-IV first) — the genuinely-missing data.
  - Persisted with `INSERT OR REPLACE` (idempotent within a day) in a single transaction.
  - Config (`config_json`): `callDelayMs` (200–2000, default 1100), `maxTickers` (1500),
    `captureWheel` (true), `captureIncome` (true).
  - `runOnStartup: false` — heavy E*Trade pass; driven by orchestrator / manual trigger.
    Default schedule 07:00 ET (disabled by default; the orchestrator drives it).

### Notes / scope

- Captures the **recommended structure** per ticker (one strike/expiry), not the full
  chain — sufficient for income/wheel ROC, not arbitrary historical structures.
- Directional strategies (bullish/bearish) are not captured yet; the `strategy` column
  is generic so they can be added later.
- Pure mappers `wheelResultToRow` / `incomeResultToRow` are exported and unit-tested.

### Tests

- `tests/options-premium-history.test.ts` — result→row mappers (CSP/CC, bid/ask/OI/iv
  handling) and migration 040 (columns + `UNIQUE(as_of_date, ticker, strategy)`
  REPLACE-not-duplicate). Full suite: 266 passing.

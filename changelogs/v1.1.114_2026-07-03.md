# v1.1.114 — 2026-07-03

## Filters: "All" universe + nightly prefill batch job

Two related features requested together: an **All** universe for the Filters screen, and a batch job that precomputes every filter overnight so the screen opens pre-populated.

### 1. "All" universe option

- The Filters universe dropdown gains **All (S&P + Russell + ETFs)** — `getConstituents('all')` returns the deduplicated union of `sp500` + `russell1000` + `etf` (~1,000 stocks + the curated ETF list).
- `'all'` was added to the shared `Universe` type but is only offered by the Filters view (the Screener, LEAPS, and Opportunity universes are unchanged).
- **Per-ticker ETF calibration**: the filter service previously treated ETF-vs-stock as a universe-wide flag (`universe === 'etf'`). In a mixed All scan that would have mis-calibrated one side — ETFs use compressed IV thresholds (IVR 30 = elevated vs 70 for stocks), skip the fundamentals gate, and get a lower vetted-wheel yield floor (8% vs 15%). `TickerSource` now carries `isEtf` per ticker (from ETF-list membership), so stocks and ETFs are each judged by their own calibration inside one scan. ETF rows are labeled `ETF` in the source context.

### 2. Filters Prefill batch job (`filters-prefill`)

- New job registered **last in the batch sequence** (highest `sequence_order`), `afterCloseOnly` — it runs once per trading day at the end of the after-close chain and is skipped in the lean ~10:15 intraday slot. Deliberately last: it consumes what the chain produces (fresh `quote_cache` / `fundamentals_cache`, `iv_history`, `technical_signals`, `earnings_calendar`) and its Wheel (Vetted) / Assignment Risk legs fetch live E*Trade option chains.
- Runs all 8 filter templates with `source='universe', universe='all'` and stores each result set in the new **`filter_template_runs`** table (migration 065): one row per template, `INSERT … ON CONFLICT DO UPDATE` (latest-only, no history), with `ran_at`, `universe`, `result_count`, `results_json`, and `shape_version`.
- **Shape versioning**: rows are stamped with `FILTER_RESULTS_SHAPE_VERSION` (new shared constant in `src/shared/filter-templates.ts`, replacing the renderer-only `CACHE_VERSION = 5`); `getSavedRuns()` ignores rows from an older shape so a schema/gate change never renders stale columns or pre-gate results (the v1.1.110 lesson, now enforced on both cache layers from one constant).
- **Failure isolation**: a template that throws is recorded in the run notes and the loop continues — one bad scan can't starve the other seven, and the job only reports `failed` (halting the orchestrator chain) if *every* template fails. `runTemplate` gained an optional `AbortSignal`; an aborted scan breaks out without overwriting a stored run with partial results.
- Progress streams to the Batch view (one event per 25 tickers).

### 3. FiltersView integration

- On mount the view loads all batch runs via new IPC `filters:get-saved-runs` (`window.api.filters.getSavedRuns()`).
- Each template card shows a **match-count badge** (precomputed matches, tooltip explains).
- Clicking a card shows the **freshest cached data instantly**: today's manual localStorage run or the batch run, whichever is newer; a live scan runs only when neither exists. Applying a batch run sets the source selector to Universe/All and the template's default sort.
- The header stamp distinguishes origins: `ran HH:MM` (fresh) / `today's run HH:MM` (restored manual) / `batch ran <date time>` (prefill — date shown when not today, since batch results are displayed indefinitely rather than day-expired). The zero-match state also shows the batch stamp so an empty vetted list is distinguishable from "never ran".
- **↻ Re-run** always fetches live (note: after viewing a batch run the selection is Universe = All, so Re-run performs the full ~1,600-name live scan).

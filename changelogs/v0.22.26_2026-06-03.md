# v0.22.26 — 2026-06-03

## Daily Options Snapshot + Daily Intelligence Brief: graceful skip on auth failure

### Problem
Both jobs use the configured `OptionsProvider` which may be E*Trade. When the
E*Trade OAuth token is expired (midnight ET rollover or 2h inactivity), the
first live options chain call hangs indefinitely. With the v0.22.25 timeout fix,
this meant 300 × 30s = 150 minutes of timeouts before the job "completed" with
300 failures — not useful, very slow.

### Fix
Both jobs now probe `optionsProvider.getOptionsExpirations('SPY')` at the start
of `run()` before any real work begins. On auth failure (or any connectivity error),
they return `status: 'skipped'` with a human-readable message immediately.

**`DailyOptionsSnapshotJob`**
- Added `OptionsProvider` constructor arg
- Probe check at top of `run()` before loading screener candidates
- `index.ts` updated: `new DailyOptionsSnapshotJob(db, analysisService, optionsProvider)`

**`DailyIntelligenceBriefJob`**  
- Already had `OptionsProvider` in constructor
- Probe check added before Stage 1 — avoids wasting time on scoring/screening
  only to fail at Stage 4 (Strategy Lab live chain calls)

### Behaviour when E*Trade is disconnected
| Job | Before | After |
|---|---|---|
| Options Snapshot | Hung forever / 150min timeouts | Skipped in < 5s |
| Intelligence Brief | Hung at Stage 4 | Skipped before Stage 1 |

When E*Trade reconnects (user re-authenticates in Settings), both jobs resume
normal operation on the next scheduled run or manual trigger.

# v1.1.10 — 2026-06-14

## v2 execution subsystem — Phase 5c/d (control panel UI), completing Phase 5

The Electron control surface for the (mock-backed) execution engine. A new **🤝 Execution**
sidebar section with two views, both driving the engine entirely through
`window.api.execution.*`. The whole product is now demonstrable end-to-end without IBKR.

### 🤝 Trading Desk (`src/renderer/src/views/TradingDeskView.tsx`)

- **Master header:** PAPER/LIVE badge (from `config.executionMode`) + engine-state pill
  (running / stopped / paused / kill-tripped, colour-coded).
- **Engine panel:** Start / Pause / Stop (master Stop = hard stop), broker-connected +
  health + last-cycle readout.
- **Kill switch panel:** armed/tripped status (+ reason), Trip / Clear.
- **Capital panel:** deployed-vs-ceiling gauge, day P&L (realized + unrealized), the
  daily-loss trip threshold.
- **Proposals queue:** pending entry/exit proposals with Approve / Reject. **Paper =
  1-click approve; live = type-to-confirm** (must type the ticker) to guard against
  fat-finger live orders. Reject asks for confirmation.
- **Open positions** table (qty, entry credit, mark, P&L, status) and an **activity log**
  off the audit trail.
- Live-updating: subscribes to `window.api.execution.onEvent` and polls every 15 s as a
  fallback; refreshes after every action.

### 🎚️ Execution Settings (`src/renderer/src/views/ExecutionSettingsView.tsx`)

A plain editor over the single `exec_config` row (`getConfig` / `updateConfig`), grouped
into **Mode** (execution mode + eligible strategies), **Risk limits**, **Entry policy**,
and **Exit policy**. Dirty-tracking with Save / Revert; switching to **live** mode is
confirmation-gated. The governor re-reads config each gate, so changes take effect on the
next cycle.

### Wiring (`src/renderer/src/App.tsx`)

New `Execution` sidebar section (after Intelligence) with **🤝 Trading Desk** and **🎚️
Execution Settings**; `View` union + `renderEntry` cases extended.

### Notes

No new automated tests (renderer views; the engine/IPC layers they call are already
covered — full suite green, 441). There are **no auto-generated entries yet** — the
brief→`PickInput` source lands with the IBKR integration (Phase 6) — so the proposals
queue is driven only by future entries; the desk otherwise reflects live engine state.

# v1.1.127 — 2026-08-04

## Wheel `optionLiquidityScore`: null when unmeasured, 0 only when measured-and-illiquid

### Origin

Investigating why a GLW wheel CSP in the 2026-08-04 intraday brief showed `optionLiquidity` **0/10**
while the Strategy Lab rated the same contract **9/15**. The two numbers turned out to be measuring
different strikes at different times, but the audit surfaced a real defect underneath.

### The defect

`analyzeWheel` initialised `let liquidityScore = 0` and only raised it inside `if (chain) { … }`.
When `findSuitableChain` resolved nothing in the 30–45 DTE / 0.20–0.30 delta window, that unset `0`
was persisted to `analysis_snapshots` as `optionLiquidityScore: 0` — a positive claim of
"measured, and illiquid" for a ticker whose options were never looked at.

On the 2026-08-03 full-universe snapshot:

```
1,029 tickers
  695 (68%)  recommendedStrike = null  → no chain resolved → fabricated 0
  334 (32%)  chain resolved
              of which 270 scored a genuine 0
```

So **94% of the snapshot read `0`**, and only ~26% of those zeros were real measurements.

The same rows also picked up `explanation: "… Low option liquidity."`, because that string was
appended on `liquidityScore < 5` without checking whether a chain existed.

### The fix

Scoring is extracted to a pure, exported helper (same pattern as `breakevenDistancePct`,
`expectedOneSigmaMove`, `popWeightedPremiumScore`):

```ts
export function wheelOptionLiquidityScore(contract | null): number | null
```

It returns `null` when there is no contract to score, and 0–10 otherwise (OI ≥50 → +4, relative
spread ≤5% → +4, volume ≥50 → +2).

- `WheelResult.optionLiquidityScore` → `number | null`, in **both** declarations — `analysis-service.ts:68`
  (the live one, imported by `scoring-service`, `daily-options-snapshot-job`,
  `daily-options-premium-history-job`) and the dead duplicate at `src/shared/types.ts:315`.
- `emptyWheel()` returns `null` rather than `0`.
- The "Low option liquidity." explanation is gated on `chain &&`.
- `AnalysisView` renders `—` rather than `0/10` for an unmeasured row.

### Scope: this changes no score, on purpose

`ScoringService.scoreTicker` computes:

```js
if (!missing) { weightedSum += normalized * sig.weight; }
totalWeight += sig.weight;          // ← unconditional
```

A missing signal contributes 0 to the numerator **and its full weight to the denominator** — which
is arithmetically identical to a measured 0. FR-SE-03 "missing signal contributes 0" means missing
is penalised exactly like zero; the `missing` flag is bookkeeping, not scoring. Composites,
rankings and pick selection are therefore **bit-identical** before and after this fix.

Two consequences worth stating explicitly:

- **Not FR-SEY-5-gated.** No trade selection, sizing or exit changes.
- **Critic unaffected.** `checkCriticalSignalMissing` inspects only the **top-2** weighted signals.
  `optionLiquidity` ranks 5th in both configs (wheel 9, behind ivRank 22 / premiumYield 19; income
  13, behind ivRank 30 / premiumRiskRatio 22), so flipping it to `missing` raises no new flag.

The only thing that would make missing-vs-zero actually move a composite is excluding missing
signals from the denominator — precisely what the (default-off) `ETF_AWARE_WHEEL_SCORING` branch
does for its two signals via a `continue` before `totalWeight +=`. Generalising that is a real
scoring change and a separate, FR-SEY-5-gated piece of work.

### Known issue recorded, not fixed here

`BriefReplayService` sets `optionLiquidityScore: null` — along with `annualizedReturn` and
`suitabilityScore` — for **every** ticker, because replay has no options data. Under the arithmetic
above that means replay scores every ticker as if liquidity were zero, while the live path scores it
up to **9 (wheel) / 13 (income)** points higher for the ~32% of tickers that do resolve a chain.

- Brief Replay therefore **cannot A/B this signal** — an on/off test shows a flat zero.
- The deflation is **not uniform**: it only hits chain-having tickers, so replay systematically
  distorts the ranking between chain-having and chain-lacking names relative to live. Any past
  wheel/income conclusion drawn from replay inherits that.

Better instrument: `analysis_snapshots` retains **66 wheel snapshots, 2026-05-14 → 2026-08-03**
(~1,029 tickers each) carrying the real live `optionLiquidityScore` and `recommendedStrike` — enough
to reconstruct both scorings on true live-path values and settle differing picks on real forward
prices.

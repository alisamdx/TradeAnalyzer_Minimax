## A "not reuse" ruling on a QC-209 finding now sticks

### Problem

v1.1.276 gave QC-205 a durable "not reuse" ruling. Resolving a step `false_positive` makes the check evaluate that key as not fired from then on, because a historic step fires every night and would otherwise reopen the resolution as a recurrence. QC-209 (dormant symbol resumes) asks the same question of the same step but never read the ruling, so the same decision on a QC-209 finding lasted one run.

### Fix

`withNotReuseRulings` in `qa/checks/bars.ts` applies the rulings to both checks' evaluations. `notReuseRulings` reads `false_positive` resolutions on QC-205 **or** QC-209. The ruling is about the step, and both checks key it `TICKER yyyy-mm-dd`, so a ruling made on either finding holds for both. The step is still measured (`evidence.ruledNotReuse`) so the distribution stays whole. A new step on the ticker is a different key and still fires. QC-209 now declares `qa_exception` in `readsTables`.

# v1.1.355 — 2026-10-13

## E*Trade "no options" answers cost one call instead of three

**Why.** Following up the 2026-10-13 collector check on PSKY/WBD calls. The collector's share of those is small and ends by itself: both left the universe on 10-12, and their chain-subset membership closes as `delisted` once their `recommended_by_legacy` pins expire (WBD 10-23, PSKY 11-06). The old app's API log showed the bigger cost. Every failed E*Trade chain call appeared twice, milliseconds apart, and the day held 91 renew calls on a token that never went dormant.

Cause: `ETradeDataProvider.withRenew` renews and retries after **any** error. That rule is right for dormancy, which can surface as a killed stream rather than a 401. But it also re-sent answers that can never change on a retry:

| code | message | 2026-10 responses |
| --- | --- | --- |
| 10032 | No options are available for this symbol. | 694 |
| 10033 | The symbol entered is invalid. | 296 |

So each answer cost the original call, a renew, and an identical retry. On 2026-10-13 that came to 136 failed chain calls plus 89 renews. They came from daily-options-snapshot, options-premium-history and spread capture (both slots), all asking for MDT, DDS, WTM, UI, LEN.B, NVR, SEB and PSKY, about 3–5 expirations each.

**What changed**
- `etrade-errors.ts` (new) holds the message `etradeGet` throws (`etradeApiErrorMessage`) and its parser (`etradeApplicationErrorCode`), so the format and its reader cannot drift apart.
- `withRenew` rethrows an **HTTP 400 carrying a numeric E*Trade `<code>`** unchanged. E*Trade sends one only after accepting the OAuth signature, so it is an answer about the request and never dormancy. This is an exemption for a positively identified answer, not a gate on an auth-shaped message. A 401, a killed stream, a timeout, a 5xx and a 400 without a code (e.g. an HTML body) all still renew and retry.
- 10032 and 10033 answer for the whole ticker, so the provider remembers the ticker until the ET date changes. Later chain or expiration calls for it, from any job, any expiration and either letter case, throw the same error with no network call. 10031 (no chain for one expiration) is about the date and is not remembered.
- **Basis for the day-long skip:** across 21 trading days of `logs/api` (2026-09-14..10-13), no symbol that drew 10032/10033 returned a 200 chain on the same day.

**Not changed:** `EtradePortfolioService` has its own `withRenew` for account endpoints and is untouched. The collector does not use this provider.

**Expected effect:** about 225 E*Trade calls a day become about 20, one per affected ticker per day.

## Tests

`tests/etrade-dormant-token-renew.test.ts`, using error bodies copied from `logs/api/api_2026-10-13.jsonl`:
- the parser accepts 400 + `<code>` and rejects a 401 quoting a code, a 400 with an HTML body, and a killed stream;
- 10032: no renew, one call, then no further call for another expiration, another method or lower case; other tickers unaffected;
- 10033 is remembered through 23:59 ET and asked again at 00:01 ET;
- 10031: no retry, but the ticker is not skipped;
- a 400 without a code and a 401 quoting a code still renew and retry.

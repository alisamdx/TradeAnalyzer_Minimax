# v1.1.346 — 2026-10-09

## Four study scripts read through the API instead of opening the database

`fr-expiry-liquidity-study`, `fr-expiry-realized-ab`, `fr-liquidity-slot-comparison` and `fr-wheel-liquidity-calibration` opened `%APPDATA%\trade-analyzer\trade-analyzer.sqlite` with `new Database(...)`. From Claude Code's shell, which is MSIX-redirected, opening a WAL database can move it (CLAUDE.md, "Opening a WAL database from a redirected shell MOVES it"). From a normal terminal they also needed `rebuild:node`. Same fix as the spread study (v1.1.338) and the settled-CSP panel (v1.1.267).

### New read-only routes

- **`GET /api/v1/diagnostics/brief-history-panel?strategy=&liquidityLog=1`** (`services/brief-history-panel.ts`). Returns every `daily_briefs` row, oldest first, with `picks` as the stored JSON text: unparsed, so the scripts still skip a malformed row themselves. With `liquidityLog=1` it adds `structure_liquidity_log`, which is `null` (not `[]`) when the table cannot be read.
- **`GET /api/v1/diagnostics/price-series?tickers=A,B&from=&to=&iv=1`** (`services/price-series-panel.ts`). Returns `[date, close]` per ticker within [from, to]. With `iv=1` it adds `iv_history` rows with `atm_iv > 0` as stored. `maxPx` is MAX(date) across the table. An asked ticker with no rows comes back as `[]`, never absent. At most 2,000 tickers per request.

### Scripts

- `scripts/lib/app-api.mjs`, a shared client: token and port from `~/.tradeanalyzer`, a clear message when the app is not running, `loadBriefHistory`, and `loadPriceSeries` (batched 200 tickers per request).
- Each script's SQL is replaced by a call that returns rows of the same shape, so the analysis loops are unchanged. In `fr-expiry-realized-ab`, stage 2 now fetches the whole panel plus SPY in one pass, and takes the trading days from SPY's bars. The calibration script's ticker sample uses `/analysis/snapshots/latest?mode=wheel`.

### Tests

`tests/brief-history-price-series-panel.test.ts` covers ordering, the unparsed picks, the strategy filter, the liquidity log (only when asked, `null` when unreadable), bars inside [from, to], an empty-but-present ticker, and IV filtering. A source scan (comments stripped) fails if any of the four scripts imports `better-sqlite3` or names the database file again.

About 50 other `scripts/*.mjs` still open the database directly. Move each onto the API before running it from the Claude shell.

# v1.1.117 — 2026-07-03

## Critic: fix the dead `checkScoreConcentration` check

Fourth fix from the brief-pipeline audit (following v1.1.116's earnings/VIX/trend fixes). Chosen as the next priority because, like the trend-alignment fix, it's a genuine logic bug rather than a scoring-weight or threshold design decision — it doesn't require Brief-Replay validation under FR-SEY-5 since it's an info-severity, non-gating advisory check, so it was safe to fix directly.

### The bug

```ts
private checkScoreConcentration(pick: BriefPick): CriticFlag | null {
  let topKey = '';
  let topContrib = 0;
  for (const [key, v] of Object.entries(pick.signals)) {
    if (v.missing) continue;
    const contrib = (v.normalized * v.weight) / 100;
    if (contrib > topContrib) { topContrib = contrib; topKey = key; }
  }
  if (topContrib > 50) { ... }  // <-- never true
  return null;
}
```

`contrib` for a single signal is `normalized × weight / 100`, which is bounded by that signal's own `weight` (since `normalized` maxes at 100). The highest baseline signal weight across all six strategy configs is 30 (inflection's `breakoutDecisiveness`); most are in the teens/twenties. So `topContrib` can **never exceed ~30**, and the `> 50` comparison was structurally unreachable — this "single-factor thesis" warning has never fired since it was written, on any pick, ever.

The check's own description text already speaks in share terms: `"X of Y composite points"`. The intended comparison was clearly *what fraction of the total composite did this one signal drive* — not an absolute points threshold.

### The fix

```ts
if (pick.compositeScore <= 0) return null;
const sharePct = (topContrib / pick.compositeScore) * 100;
if (sharePct > 50) {
  return { key: 'score_concentrated', severity: 'info', description: `... (${sharePct.toFixed(0)}%) ...` };
}
```

Sanity check: when only one signal is present (all others missing), `topContrib` exactly equals `compositeScore` (both derive from the same single `weightedSum` term), so `sharePct` correctly reaches 100% — the maximal-concentration case. When contribution is spread evenly across several signals, no single share crosses 50% and the check correctly stays silent.

### Why this was safe to fix without a replay validation

- **Info-severity only** — the critic system prompt explicitly tells the LLM "a pick whose only flags are info-severity can still merit 'pass'"; this flag alone cannot flip an LLM verdict to `caution`/`flag`.
- **Non-gating** — the v2 execution engine's entry gate (`entry-policy.ts`) accepts both `pass` and `caution` critic verdicts; only `flag` rejects. The rule-based fallback verdict (used only when the LLM call itself fails) does shift from `pass`→`caution` when this flag newly fires, which is the intended, more-conservative behavior for a degraded critic pass, not a regression.
- **No change to which trades are scored, ranked, or selected** — this only adds an advisory note to the brief/critic output for a human reader.

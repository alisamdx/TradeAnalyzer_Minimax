# v1.1.264 — 2026-09-17

## The root package build never built TradeAnalyzer 2

v1.1.263 changed `packages/next/src/main/exceptions.ts` — QC-210 in `REUSE_CHECKS`, the
extracted `reuseCandidateFor`. `npm run package` succeeded, `check-core-built` passed, and
the exe reported `1.1.263.0`.

`packages/next/release/win-unpacked/TradeAnalyzer2.exe` was still **0.4.8, built
2026-09-12**. The change was in no binary.

The root `package` script builds TradeAnalyzer only; TradeAnalyzer 2 has its own
`package` script under `packages/next`, and nothing in the root chain calls it. This is
the shape v1.1.250 recorded for `packages/core/dist` — *a workspace package compiled
separately, and the version stamped on the main exe says nothing about it* — one directory
over, and it survived the guard built for that one, because `check-core-built` checks
`core`'s `dist/`, not TA2's bundle.

It surfaced only because a ruling that was supposed to have been made left **no trace in
the generation**: no `ticker_change` membership row, 66 exceptions still `open`, and
`qa_exception_event` holding nothing but `gate` and `escalation` actors — no operator
action ever recorded. `meta_open_handle` then gave the reason: TradeAnalyzer 2 last opened
the generation at 2026-09-16 21:16 and closed it at 00:36, on **`dictionary_version 15`
while TA1 was on 18**.

Two corollaries worth keeping, both in `CLAUDE.md` now:

- **A stale TA2 runs stale `core`.** It bundles `@tradeanalyzer/core` as of its own build,
  so the five-day-old exe also predates v1.1.261's `entityStartDates` and v1.1.262's
  cascade. Rebuilding TA1 does not fix TA2.
- **`packages/next` has its own version, which the root bump does not touch.** v1.1.263
  bumped `core` 0.6.20 → 0.6.21 and left `next` at 0.4.8 while changing its source, so a
  rebuilt TA2 would have called itself 0.4.8 — and `meta_open_handle.app_version` records
  exactly that string, naming the wrong build in the one place a later diagnosis would
  look. Bumped to **0.4.9** here.

## And the root `npm test` is not the full suite

`packages/next`'s `workspace-versions.test.ts` had been failing for weeks —
`package-lock.json` recorded `packages/core` at **0.6.9** and the root at **1.1.245** —
and nothing surfaced it, because the root `npm test` runs only `tests/**`. `npm run
test:all` runs the workspaces. Fixed in v1.1.263 with `npm install --package-lock-only`;
recorded as a quirk here, because the gap is what let it sit.

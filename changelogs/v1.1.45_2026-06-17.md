# v1.1.45 — 2026-06-17

## v2 execution — Phase 6a: the IBKR adapter

### Context
Phases 0–5 built the whole execution engine — governor, loops, policy, control API, and the
🤝 Execution UI — and ran it end-to-end against the deterministic `MockExecutionBroker` (through
v1.1.10). Phase 6 is "the wall": it needs a real broker account. The IBKR account is now approved
and a live **TWS** paper session connects, so the last mile begins.

### The change
A live `ExecutionBroker` implementation, `src/main/execution/ibkr-execution-broker.ts`, talking to
a locally-running **TWS or IB Gateway** over the TWS socket API via `@stoqey/ib`. It slots in behind
the existing seam with **no engine/UI changes**:

- **Lifecycle** — `connect()` resolves on `nextValidId`; connection-level IBKR errors (1100/502/504)
  flip session state fail-closed; benign data-farm notices (2104/2106/2158/…) are ignored.
- **Reference / pricing** — `qualifyContract` (reqContractDetails → conId/multiplier),
  `priceCombo` (BAG snapshot mktData → net bid/ask, credit-positive), `getBuyingPower`
  (reqAccountSummary → AvailableFunds/NetLiquidation).
- **Orders (idempotent on COID)** — `placeOrder` builds a BAG combo from qualified legs and submits
  a net LMT order; a repeated `clientOrderId` never creates a second broker order. `cancelOrder`,
  `onOrderStatus` (from `orderStatus`), and `onFill` (incremental fills off `orderStatus`, deduped by
  cumulative count, commission attributed from `commissionReport`).
- **Truth** — `getOpenPositions` (reqPositions, option legs regrouped per underlying) and
  `getOrders` for reconciliation.

The **combo net-price sign convention** is centralised in `comboLimitOrderParams()` /
`ibkrFillToNetCredit()`: our seam is credit-positive; IBKR reads a *negative* BUY limit as a net
credit received. This is the single place to confirm against real paper fills.

### Broker selection
New `src/main/execution/broker-factory.ts`:

- `resolveBrokerSettings(mode, env)` — pure: chooses `mock` (default) vs `ibkr`
  (`TA_EXEC_BROKER=ibkr`), and resolves host/port/clientId. Port precedence: `TA_IBKR_PORT` →
  Gateway/TWS table keyed by `executionMode` (paper/live). `TA_IBKR_GATEWAY=1` switches to Gateway
  ports.
- `createExecutionBroker(settings)` — constructs the chosen broker (no connection on construction).
- `index.ts` reads `exec_config.executionMode`, resolves settings, constructs the broker via the
  factory, and logs `[execution] broker=… mode=…`. **IBKR is strictly opt-in** — existing installs
  keep the mock until the operator sets `TA_EXEC_BROKER=ibkr`.

### What's verified now vs Phase 7
- **Live-verified against the paper account** (no options permission needed): TCP handshake +
  `nextValidId`, `reqAccountSummary` (AvailableFunds $1,000,000 / BuyingPower $4,000,000 /
  NetLiquidation $1,000,000), and `reqPositions`. These are exactly the calls `getBuyingPower()` and
  `getOpenPositions()` make.
- **Calibrated on paper in Phase 7** (needs options-spread approval): `priceCombo`, combo
  `placeOrder`, and the fill/commission pipeline. The combo conventions are coded per IBKR docs and
  isolated in one helper for confirmation against real fills.

### Account note
The paper account is a **margin** paper account, so credit-spread paper validation is possible there
even though the *live* account is currently **Cash** (a live credit spread needs a Reg-T margin
upgrade + options-spread approval).

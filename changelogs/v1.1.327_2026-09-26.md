# v1.1.327 — 2026-09-26

TradeAnalyzer only. BPS-10: testing the bull put spread's ranking. No selection rule changed.

## The problem

Spread mode ranks each run's eligible candidates by net credit ÷ max loss and keeps the top 5. The rule
has never been validated (08 §3.6).

Until recently it barely mattered, because the pools were starved. On 2026-09-26 the shadow report
showed that had changed. The cut bound on **7 of 8 `premium` runs** and dropped **23 names**, as many as
7 in one run. So the untested rule was choosing most of that arm's sample.

**The data that could test it was being thrown away.** Each cut name was stored as a bare rejection,
`ranked below the top 5`, with no strikes, credit or expiry. None of the 23 can ever be settled. This is
the shape CLAUDE.md already warns about: when a ranking's quality is in question, the losers are the
data you need, and pipelines habitually discard exactly those.

## Real quotes, from now on

- **Stored with legs.** `computeSpreadMode` keeps the cut candidates (`rankedOut`), each with its full
  construction and the rank it would have had (6, 7, …). The stored row stays `outcome = 'rejected'`
  with the same reason, so every reader of the funnel is unchanged. It now also carries the strikes,
  quotes, credit, max loss and return on risk. No migration was needed.
- **Tracked to expiry.** Capture tracks a cut name's series until it expires, as it does for a pick.
  Entry series were already re-quoted for 21 days, so this adds only the last week or so of each series.
- **Settled as a counterfactual.** The report adds `rankingTest`, per pool:
  - the picks of every **binding** run, against those runs' cut names, both settled by the same rules;
  - the median entry return on risk of each side, which shows how far apart the metric put them;
  - `cutAlsoPicked`: a cut name the same pool picked within the 14-day episode window is one bet, and it
    is left out of both sides.

  The comparison never reaches the §4 gate or the position list. It shows in
  `scripts/spread-shadow-report.mjs` and in 🪜 Spread Shadow under the BPS-10 section. Names cut before
  this version have no legs and are excluded by the query.

## History, now

`scripts/fr-bull-put-spread-study.mjs` §8 ranks each replay day's eligible set by the mode's profile:
30 DTE, Δ0.30, 5% wing, 50% target, no stop, cost ≤ 25%. It compares four rules:

- return on risk (the mode's rule);
- its inverse;
- the brief's rank;
- ATM IV.

For each rule it reports the top-5 lift over that day's mean against **500 random choices of 5 on the
same days**. Because the null is built on the same days and candidate sets, day-to-day overlap in names
inflates both sides equally. It also reports the top and cut sides' win rate and max-loss rate, so a
lift bought with a fatter tail is visible. The whole section repeats at skew 0, 3 and 6.

**Know what this can answer.** With a Black-Scholes wing and a flat skew, return on risk is almost
entirely ATM IV (the section reports the within-day Spearman). So it tests "does ranking by IV pick
better", not the metric on real quotes. The shadow counterfactual is the real-quote test.

It was added to the #43 script, not copied into a new one, so it uses the same simulator the rest of
the study is built on. Self-test: 6 new checks, all passing. The rule must clear the band when richer
credit really wins, reverse in an inverted world, stay inside the band when credit carries no
information, and report no test days when no day has more than 5 candidates.

## Tests

- `tests/spread-mode.test.ts`: the cut's losers are stored with legs and their would-be rank (6, 7), and
  every other rejection stays bare.
- `tests/spread-chain-capture.test.ts`: a cut name with legs is tracked to expiry, and a pre-v1.1.327
  bare one is not fetched.
- `tests/spread-mode-settle.test.ts`: `rankingTest`. Only binding runs count as "top". A cut name picked
  within 14 days is excluded from both sides. A cut row without legs is ignored. The counterfactual
  never enters the position list.

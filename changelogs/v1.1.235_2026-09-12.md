# v1.1.235 — 2026-09-12

## The batch note was readable to character 60 and no further

Reported from use, one version after v1.1.234 made that note the thing worth reading.

### The text was never lost — only unreachable

Every layer stored and carried it whole:

| layer | state |
|---|---|
| `migrations/020_batch.sql` | `notes TEXT` — no length constraint |
| `batch-service.ts` | `result.notes ?? null`, written entire |
| `BatchRun.notes` (`shared/types.ts`) | `string \| null` |
| `BatchView.tsx:821` | **`run.notes.slice(0, 60)`** |

The cell put the remainder in a `title` attribute. **A native tooltip cannot be
selected, scrolled or copied** — and on Windows it wraps a long string awkwardly and
dismisses itself on a timer. So the full note existed in the renderer's own memory and
there was no path to it.

That is a different failure from the one it sat next to. v1.1.234's truncated split list
was data we never fetched; this is data we held and would not show.

### It cut away exactly the part worth reading

The collector one-shots write a whole gate summary into that field, and every operative
number in it falls past the cut:

```
backfill_bars: 1293548 bars for 1089/1089 tickers, 1000 spli…
                                                            ↑ character 60
```

The verdict and the finding count — `RED, 512 finding(s) awaiting a ruling` — are both
beyond it. The one line that most needed reading was the one the preview served worst,
because the interesting part of a job summary is at the end.

### The fix

The Notes / Error cell is a click target now (dotted underline, pointer cursor) and opens
a modal holding the full text: `white-space: pre-wrap`, `word-break: break-word`,
`user-select: text`, and a `maxHeight` with its own scroll. A **Copy** button writes the
note to the clipboard and confirms for 1.5s; when a run has *both* an error and a note it
copies both, labelled. Escape closes it, as does a click on the backdrop.

It reuses what this file already had rather than inventing alongside it — the `EditModal`
overlay convention (`inset: 0`, `rgba(0,0,0,0.7)`, `zIndex: 10000`, a `#1e2535` panel) and
the `void navigator.clipboard.writeText(...)` idiom from the Live Activity copy button.

**Deliberately a modal, not an inline expander.** The run-history pane is a fixed 160px
scroll region with the comment *"Fixed height ≈ 4 rows — constant regardless of state"*.
Expanding a row in place would fight a constraint chosen on purpose, and would have to
either grow the pane or scroll the expansion out of view.

### The test, and the trap it avoids

`tests/batch-run-notes.test.ts` pins the split between the two functions: `notePreview`
truncates, `runNotesText` is lossless. Both are exported plain functions rather than logic
buried in JSX, because this repo has no `@testing-library` and a node-environment vitest
cannot render a component — so testable behaviour has to be reachable without one.

The fixture is the **real** 2026-09-11 backfill note, and the first assertion is
`expect(LONG_NOTE.length).toBeGreaterThan(60)`. Without it every truncation assertion
below would pass on a short string for the wrong reason — the same vacuity trap that the
zero-paired-day overlap check and the conviction band that could never fire both fell
into. Two assertions state the motivation directly: the preview must **not** contain
`RED` or `512`.

### Not added to Known quirks, and why

A `title` tooltip being uncopyable is a UI affordance mistake — visible the instant anyone
tries to use it, which is exactly how it was found. The quirks list earns its length by
holding traps that produce *silently wrong behaviour*, and diluting it with things that
announce themselves makes the genuine entries harder to find.

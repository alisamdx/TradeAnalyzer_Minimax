# v1.1.66 — 2026-06-23

## Run the spread-permission preflight in paper mode too (fail-closed, not silent)

### Root cause (the whole day's "armed but nothing trades")
The IBKR **paper** account (`DUQ795672`) does **not** have options **spread** (multi-leg) trading
permission. The engine's entire book is defined-risk multi-leg combos (the wheel bull-put vertical,
inflection vertical, income condor), so IBKR **rejected/cancelled every order** with a
"no trading permission" reason. Confirmed from TWS after v1.1.65 made the reason visible.

The engine never told anyone, because `startEngine()` ran the fail-closed spread-permission
preflight in **LIVE mode only** — paper was skipped on the assumption (stated in spec §2.13 and
CLAUDE.md) that an IBKR paper account always has full permissions, incl. Level 3. That assumption is
false for this account. So the engine armed in paper and silently submitted combo after combo, each
rejected by TWS — the multi-hour rabbit hole behind today's v1.1.62→v1.1.65 fixes.

### Change
`ExecutionEngine.startEngine()` now runs the permission preflight in **both paper and live**:
connect the broker, then `checkSpreadPermission()` (the IBKR adapter probes with a non-transmitted
whatIf combo on a reference vertical; an `OrderState` ⇒ permitted, an order error ⇒ not permitted).
If it fails, the engine **refuses to start** with reason `spread_permission:<code>` and audits
`preflight_permission_failed` — it never arms into silent rejections. The Trading Desk already shows
a refused start as `Engine refused to start: spread_permission:no_spread_permission`.

The mock broker grants permission by default (now drivable via `MockOptions.spreadPermission` for
tests), so tests/dev are unaffected.

### Why this is the right call
A fail-closed safety change, strictly more conservative: it won't arm an account that physically
can't place the engine's defined-risk spreads. No change to which trades are selected, how they're
sized, or how they exit. It converts a silent, hours-long failure mode into a one-line message at
the moment of Start.

### Validation (FR-SEY-5)
Validation-exempt: a fail-closed arming guard; no selection/sizing/exit logic changed.

### Operator action required
This change makes the engine *report* the blocker; it does not grant the permission. To actually
trade on paper you must enable options **spread** permission on the IBKR account:
**Client Portal → Settings → Trading Permissions → Options** → request the spread-enabled level
(paper mirrors live; restart TWS after approval). Until then, Start will refuse with
`spread_permission:no_spread_permission` — which is now the correct, honest behavior.

# v1.1.147 — 2026-09-01

## fix: the transactions endpoint is slow per call — v1.1.146's premise was wrong

### v1.1.146's fix rested on a hypothesis that turned out to be false

v1.1.146 assumed the 120-second stall came from the 8-month query span and sliced the range
into ~30-day windows. The next run disproved it:

```
01:16:16.960  None  30003ms  {"startDate":"01012026","endDate":"01312026","count":"50"}
      ERR: The operation was aborted due to timeout
```

A **31-day** slice stalled just as badly. Narrowing the range does not speed this endpoint up.
Worse, v1.1.146's own 30-second timeout then *guaranteed* failure on an endpoint already
observed taking 120 seconds — the fix made the symptom deterministic.

### What is actually true

The endpoint is slow per call, independent of range: **120,250 ms** for a YTD query, **>30 s**
for 31 days. Every other E*Trade call in the same sessions finished in **~300 ms**, which is
what the default timeout was tuned to.

### Fixes

**1. `ETRADE_SLOW_TIMEOUT_MS` (180 s), applied per call.** `etradeGet` now takes an optional
`timeoutMs`; the transactions call passes the slow budget. Everything else keeps the 30 s
default, still generous against a 300 ms norm.

**2. Single re-sign retry on `oauth_problem=nonce_used`.** The nonce is baked into the
Authorization header at signing time, so a transport-level retransmission replays it and
E*Trade rejects the duplicate. The app sends each request once — verified in the API log — so
re-signing is the only recovery. Guarded to exactly one retry so a genuinely repeated nonce
cannot loop, and scoped to `nonce_used` only: a `token_rejected` 401 is a dead token and
re-signing would not help.

**3. Slicing kept, rationale corrected.** The stall justification was false and the code comment
now says so plainly. Slicing survives for a different, still-valid reason: it bounds each
response and its pagination so one oversized window cannot swallow the whole import, and a
failure localises to a month rather than the year.

### Tests

`tests/etrade-api-logging.test.ts` +4 (11 total): nonce_used triggers exactly one retry carrying
a **different** Authorization header; repeated nonce_used does not loop; a `token_rejected` 401
is not retried; a per-call timeout override reaches `AbortSignal.timeout`.
`tests/etrade-transactions-slicing.test.ts` +1 (4 total): the transactions call gets the slow
budget. Suite: 1002 passed.

One test-side note worth recording: the slicing suite's `vi.mock` factory had to gain
`ETRADE_SLOW_TIMEOUT_MS`. A missing named export throws inside `fetchTransactionLegs`, and
`syncClosedPositions`' per-account `try/catch` swallows it — so the suite reported *zero calls*
rather than an error. That is a misleading failure mode: a swallowed exception looks exactly
like "the code never ran".

### Still open

`etrade-portfolio-service.ts` calls `etradeGet` with no `withRenew` on any of its three paths,
unlike every other E*Trade consumer. Not the cause here (the token was valid; `accounts/list`
returned 200), but a dormant token on this path still fails outright instead of renewing.

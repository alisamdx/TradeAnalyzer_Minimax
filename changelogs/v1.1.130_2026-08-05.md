# v1.1.130 — 2026-08-05

## `scripts/fr-wheel-monthly-first-ab.mjs` + first live validation run

Market-hours validation harness for `WHEEL_MONTHLY_FIRST_EXPIRY` (v1.1.128). **The flag remains
default OFF** — see the conclusion.

### Why a bespoke harness

`WHEEL_MONTHLY_FIRST_EXPIRY` cannot be validated the usual way:

- **Brief Replay is blind to it.** Replay nulls `optionLiquidityScore` for every ticker, so an
  on/off A/B returns a flat zero (`REPLAY_BLIND_SIGNAL_KEYS`, v1.1.129).
- **The `analysis_snapshots` panel holds the OLD measurements**, and recomputing the new ones
  historically needs option chains that were never stored.

So validation is necessarily forward-looking and must run during RTH — outside market hours
E*Trade returns `bid/ask/volume = 0` and two of the score's three components are unmeasurable.

### Design

- Implements **both** policies in the script and prices them in the **same pass**. Given how
  strongly time of day moves option liquidity (the intraday-vs-after-close thread), measuring arm
  A now and arm B later would be worthless. One instant, both arms.
- Reads chains through the app's own API server (`127.0.0.1:7432`), so E*Trade auth, the rate
  limiter and the provider seam are all production. **No app restart, no `WHEEL_MONTHLY_FIRST`
  env var, no DB writes** — the app just has to be running.
- Replica of `findSuitableChain` + `wheelOptionLiquidityScore` + `fillPrice` +
  `annualizedReturn`, same pattern as the other `fr-*-study` scripts; constants pinned at the top.
- Guards: market-closed (majority `bid = 0`), early-session (per-strike volume accrues through the
  day, so a 09:53 run understates the +2 component), and score-stays-near-constant.

```bash
node scripts/fr-wheel-monthly-first-ab.mjs --limit 40
node scripts/fr-wheel-monthly-first-ab.mjs --tickers AAPL,WMT,PG --out run.json
```

### Conclusion: necessary, not sufficient — flag stays OFF

The flag does exactly what it was built to do. It fixes *which contract* gets measured: OI up
~50×, spread halved, zeros 79% → 10%.

But the score still does not discriminate. Clearing ≥5/10 went **0% → 8%**, because the OI
component (+4) does all the work while `spread ≤5%` and `volume ≥50` almost never fire. The signal
moves from *near-constant 0* to *near-constant 4* — better, still not a discriminator.

The sharpest illustration: **WMT, open interest 13,824, spread 5.2%, scores 4/10** — missing the
`≤5%` gate by 0.2 percentage points.

So the remaining defect is **threshold calibration** (`OI ≥50` / `spread ≤5%` / `volume ≥50`,
`docs/formulas.md#liquidity-score`). A 5% *relative* bid-ask on a 25-delta put is institutional-
grade tight and essentially unreachable for any name; the Strategy Lab's own `liquidityScore`
grades spread across 8 points instead of using a binary gate, which is why it rates the same
contracts sanely. That is the next piece of work, and it is separable from this flag.

The flag is **not** enabled: FR-SEY-5 asks for realized outcomes, and this harness measures the
signal, not trades.

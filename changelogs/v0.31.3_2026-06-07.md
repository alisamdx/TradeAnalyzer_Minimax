# v0.31.3 — 2026-06-07

## Fix: Earnings Refresh no-data for all tickers

### Root cause
`EarningsService.estimateFromPolygon()` contained a dead placeholder SQL query:

```sql
SELECT MAX(period_of_report_date) AS report_date
FROM (
  SELECT DISTINCT period_of_report_date
  FROM constituents
  WHERE 0  -- placeholder
)
```

`constituents` has no `period_of_report_date` column. SQLite validates column
names at `prepare()` time — even `WHERE 0` doesn't bypass the schema check — so
every call threw `no such column: period_of_report_date` before the real
fallback (analysis_snapshots daysToEarnings) could run.

### Fix
Removed the dead placeholder query entirely. `estimateFromPolygon` now goes
straight to the analysis_snapshots fallback that was always the intended path.

### Files changed
- `src/main/services/earnings-service.ts` — removed dead constituents query

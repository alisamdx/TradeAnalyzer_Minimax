## Defect 1 — the importer read the new generation

`src/main/services/jobs/collector-oneshot.ts` opened `const db = host.openGenerationDb()` for the queue, then called

```ts
runLegacyImport(host, { legacyDb: db as never, tradingDate });
```

`tableExists(legacyDb, 'watchlists')` and every other source lookup ran against gen-002, found nothing, and each table was logged with the rejection "not present in the legacy database". A report of all-absent tables is a success by design (an install may lack a table), so nothing flagged it. The adjacent comment claimed "the old app's own connection is handed straight in".

**Fix:** `OneShotDeps.legacyDb: SqliteLike`, passed from `index.ts` as this app's `db`; the branch uses `deps.legacyDb`. No cast.

## Defect 2 — a column that never existed

`CONFIG_SOURCES` `etf_list`: `SELECT * FROM constituents WHERE universe = 'etf'`. `constituents` has `index_name` (migration 002); the ETF list is `index_name = 'etf'`, exactly as `collector-host/universe-sources.ts` reads it. Unreachable while defect 1 held; fatal (throw inside the import transaction) the moment it was fixed.

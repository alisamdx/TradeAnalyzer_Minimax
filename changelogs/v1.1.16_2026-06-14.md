# v1.1.16 — 2026-06-14

## Inflection up-breakout-only by default (configurable) — strategy layer

Acts on the FR-SEY-3 follow-up finding: on authoritative spread P&L
(`simulateSingleSpread` replica over 1,358 replay picks), down-breakout/bear-call
inflection is a **net loser** (−1.4%/trade, 66.6% win) while up-breakout/bull-put is
solidly profitable (**+6.1%/trade, 76% win**), and no ATR%/IV slice rescues the down side.
See `Requirements/v2-execution/06-seykota-risk-extensions.md` (FR-SEY-3 UPDATE).

### Setting

New **`inflectionDirection`** app setting: `'up'` (default) / `'down'` / `'both'`. Controls
which inflection breakout sides the scoring engine surfaces.

- `ScoringService.hasBreakout` now honours it (up → allowed unless 'down'; down → allowed
  unless 'up'; no breakout → always 0). Refreshed once per scoring pass, so runtime changes
  apply without a restart.
- Because the **Daily Brief** job and **Brief Replay** both score through
  `scoreFromSignalData`, both inherit the gate automatically — the brief stops recommending
  the losing bear-call side, and replay matches.
- Wired through `AppSettings` + `settings:get-all`/`set-all`; editable in
  **⚙ Settings → General** ("Inflection breakout direction").

### Why default `'up'`

The down side is validated as a structural net loser that no filter fixes; defaulting to
up-only enacts the improvement while leaving `'both'`/`'down'` available for the operator.

### Tests

`tests/inflection-scoring.test.ts`: default gates down-breakouts to 0; `'both'` re-enables
them; `'down'` gates up-breakouts to 0. Full suite **457 green**. typecheck + lint clean.

# v1.1.29 — 2026-06-16

**Critic-context completeness** — found in the fresh assessment of the re-run brief (ids 265–270, all v1.1.23–28 fixes confirmed working). Two issues where the critic reasoned from *incomplete* data and produced muddled analysis / a phantom flag.

## Finding A — critic saw only the short strike, not the full structure

The advocate gets the complete leg list (v1.1.23), but the critic's LLM context still passed only the single short-leg `strike`. On multi-leg structures the critic misread the trade:

- **LBRDK** (put zebra, buy 2×\$37.5 / sell \$35): critic said *"structure data shows a single \$35 strike… short put leg already in-the-money"* and flagged *"an inconsistency… the advocate cites a \$37.5/\$35 put zebra"*. The \$35 is just the zebra's financing short leg.
- **EL** (put zebra): same — *"short strike exactly at-the-money."*

### Fix
The critic context now carries `structure.legs` (e.g. `["buy 2× put $37.5", "sell put $35"]`), and the prompt instructs it to judge the whole structure from the legs and not treat one leg in isolation. To prevent a second drifting formatter, a single **`formatStructureLegs`** (in `src/shared/strategy-structures.ts`) is now used by both the advocate (`summarizeRelevantStructure`) and the critic — it shows leg quantity so ratio bodies (zebra 2:1, butterfly 1-2-1) are unambiguous (the advocate previously dropped the `2×`). The single short strike remains as `shortStrike` / `strikeOtmPct`.

## Finding B — critic mistook the advocate's "recent volatility" for an IV discrepancy

**ASTS** income got a `flag` largely on a phantom: *"the advocate cites an IV of 138.7% but the live feed shows impliedVolPct 111.6% — that discrepancy is unexplained."* The advocate said *"recent volatility of 138.7"* — the **realized-vol** scoring signal, correctly labeled, not an IV claim. The critic had `impliedVolPct` (111.6) but not the realized figure, so it couldn't reconcile the advocate's number. (Residual of the v1.1.20 IV-conflation class, from the advocate-number side.)

### Fix
`extractVolatilityContext(labResult, realizedVolPct?)` now also surfaces `volatility.realizedVolPct` (the `recentVolatility` signal). The prompt states it is recent **realized** vol — a momentum signal that is *expected* to differ from implied vol — so the critic must not treat the gap as a discrepancy or red flag. Returns null only when neither IV nor realized vol is available; when IV is unmeasured but realized vol exists, `impliedVolPct` is null (and the prompt skips expected-move reasoning) while realized vol is still shown.

Critic-context completeness only — no hidden risk, no changed recommendation; removes muddled reasoning and ~1 phantom flag. Persisted briefs keep the verdicts from their generation run; re-run to get verdicts from the improved context.

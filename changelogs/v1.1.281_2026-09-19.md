## The gate closes QC-404's and QC-409's stale findings itself

### Problem

The 2026-09-18 gate email reported "RED (23 blocking)" in its subject, but its BLOCKING section listed **1,067**: 23 raised by the run and 1,044 still open from earlier runs. Nothing would ever close the 1,044. The largest groups came from checks that have since been corrected:

- **QC-404 ×519.** v1.1.251 changed the bound from "ask ≤ 3× the underlying" to "ask ≤ 3× the most the contract can be worth" (the strike, for a put). Every finding the old bound raised on a correct deep in-the-money put stayed open. It was not being raised any more, and a finding that stops firing without a remediation stays open by design (P9). "Clean today" would not have justified closing it anyway: an option's quote changes daily, so today's clean quote says nothing about the quote that fired.
- **QC-409 ×417.** Keyed on the pin symbols that the v1.1.248 (space padding) and v1.1.269 (class-share dot) repairs closed and re-opened correctly. The check evaluates open pins only, so it never looks at those keys again.

### Fix

**QC-404 re-judges its own findings** (`rejudgeOpenFindings`). For each open finding it takes the quote the finding recorded (bid, ask, underlying), reads the right and strike from the symbol's fixed tail (older evidence did not store them), and applies the current rule. If the current rule would not fire on that exact quote, the verdict came from the old rule, and the evaluation carries `closesAs: rule_changed` with the arithmetic in the note, e.g. *"ask 83.45 is 0.79x the strike 105, within 3x"*. A finding the current rule still fires on is left alone, whatever today's quote says. A re-judged key not quoted today is added without a `value`, so the distribution stays today's quotes.

**QC-409 declares `keyShape`**: `^(?=.{21}$)[A-Z0-9]{1,6}-{0,5}\d{6}[CP]\d{8}$`, the symbol exactly as E\*Trade sends it and as `osiSymbol` builds it. v1.1.273's retirement then closes the stopped findings whose keys the check can no longer produce. Any pin still carrying an old spelling when the gate runs would make the check produce a stray key, and by v1.1.273's rule that retires nothing and raises `key_shape_violation`. The chains phase runs `repairStickyOsiPadding` before the gate, so on a live run that cannot happen unless the repair itself breaks, and then the violation says so.

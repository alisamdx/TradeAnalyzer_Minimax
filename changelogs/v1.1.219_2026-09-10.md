# v1.1.219 — 2026-09-10

`@tradeanalyzer/core` 0.4.0 (dictionary v11), `@tradeanalyzer/next` 0.2.1. **NewApp B9b.**

## Every collector capture now records how it was parsed

The daily collector this app hosts writes a **recipe** for each response: which
parser, built with which arguments. Until now the archive held every response's
bytes but not those arguments — the rule's expiration selection, the sticky set,
the order fingerprints and transaction ids already stored, the earnings universe
filter — and several of them are database state at the moment of capture. A
replay without them would have had to reconstruct them, and a reconstructed
replay that reports "equal" cannot fail on the case it exists for.

- `captureResponse` takes the recipe and **builds the parser from it**, so what
  is recorded is by construction what ran.
- Recipes are **content-addressed** (`meta_ingest_recipe`): the Form 4 parser's
  ~1,089-entry CIK map and the earnings sweep's universe list are stored once,
  not once per response.
- **The account key is never recorded.** All four account parsers only ever
  hashed it, so the recipe carries the digest the rows already store.
- `meta_response.capture_rule_id` is new too: it had only been on the rows a
  response produced, so a response that produced none could not say which rule
  asked for it.

The generation upgrades itself on open — two nullable columns, one new table.
Both columns deliberately carry no `REFERENCES` clause: columns are added with a
bare `ALTER`, and a declared FK would have left `meta_response` reported as
drifted on every open. A test builds a populated v10 table and asserts plain
growth.

## `collector-oneshot` executes `replay`

The fifth implemented one-shot, queued from TradeAnalyzer 2's Jobs view like the
others. It re-runs today's parsers over one daily run's archived responses into a
scratch database and compares the result with what is stored, per response, over
every column except the primary key and the reference columns (`observed_at` is
also excluded on derived rows, where it is the derivation's own clock).

- **It runs here** because account archive lines are encrypted with this app's
  safeStorage key and only this app can read them back.
- `ElectronCollectorHost.openScratchDb` creates the scratch file under
  `gen-NNN/replay/`. It can never become a generation: no `meta_generation` row,
  no pointer names it, it refuses a name that already exists, and it goes
  through the same redirect guard as the generation. Deleted when the replay is
  equal; kept as evidence when it is not.
- A `different` verdict is a **successful** batch result — the diff is the
  deliverable, the same rule as a red gate.
- Coverage is always reported, and **zero replayed is `nothing_replayable`,
  never `equal`**. Every run captured before this version is in that state,
  correctly: the first replayable run is the next daily run.
- `reset` is still refused here; TradeAnalyzer 2 performs it itself.

`1,261` tests here, `420` in `core`, `48` in `next`.

# v1.1.360 — 2026-10-14

## EDGAR facts: read an omitted filing's own XBRL instance (`core` 0.6.73)

**Why.** SEC's companyfacts aggregate dropped most 10-Qs filed 2026-07-28/29, and 70+ days later it still lacked them. Verified live on 2026-10-14: AEP has no fact filed after July, Citi has no 2026 10-Q at all, and AVTR, BIIB and CDNS stop at their Q1 reports. Every such filer went stale under QC-701 and escalated to blocking. The weekly companyfacts retry could not fix it, so the operator had to re-accept the same findings every few weeks. The filings themselves carry inline XBRL, and SEC publishes each one's extracted instance (`{primary}_htm.xml`) in the archive.

**What changed**
- **New sub-phase `runEdgarFilingFacts`** (phase 8, right after `runEdgarFacts`). It reads each omitted filing's instance and writes the rows companyfacts would have produced. A filing is due when it has no fact from any source and companyfacts was read at least `COMPANYFACTS_OMITTED_AFTER_DAYS` (14) after the filing, the same definition QC-704 uses. Newest filing first, up to `FILING_FACTS_PER_RUN` = 20 a run. Each filing takes two requests: `…/{accession}/index.json` to find the instance, then the instance. Both are captured, so a filing with no XBRL is on record and waits the weekly cadence instead of being asked every night. `events_facts` counts both sources.
- **New parser `makeFilingFactsIngest`** (recipe `edgar_filing_facts`, replayable). It keeps facts in a context with no dimension, from a standard taxonomy (identified by namespace URI, never by prefix), numeric and non-nil. Each repeated inline tag is kept once. `fy`/`fp` come from `dei:DocumentFiscalYearFocus`/`…PeriodFocus`. `form` and `filed_date` come from the filing row. `frame` is null, its declared meaning: SEC's cross-filing frame exists only in the aggregate. A 200 with no `<xbrl>` root is a parse failure.
- **QC-704** now asks which source delivered a filing's facts. It fires only while neither companyfacts nor the filing's own instance has. A filing recovered from its instance closes `data_corrected`, and one SEC later adds closes `provider_fixed`. Before this change, a recovery would have been reported as "now in SEC companyfacts", which would have been false.
- `COMPANYFACTS_OMITTED_AFTER_DAYS` moved into `collector/facts-queue.ts`, so QC-701, QC-704 and the fallback read one definition.

**Validated against what SEC's aggregate says.** On three filings companyfacts does include, the parser's output matched it row for row and value for value, fy/fp/form included:
- AVTR 10-Q `0001628280-26-028141`: 244/244.
- AEP 10-Q `0000004904-26-000034`: 348/348. This is a multi-registrant filing; the subsidiaries' facts carry `dei:LegalEntityAxis` and are correctly left out.
- Citi 10-K `0000831001-26-000011`: 923/923.

**Rehearsed live on the 2026-10-14 snapshot** (`rehearse-gate.mjs`, the real generation untouched). The fallback ran against SEC in 24.5 s:
- 35 filings queued, 69 calls, 0 failures, 13,538 facts stored. 34 instances were read (1.0–17.9 MB).
- The 35th is BWXT's Q2 10-Q, whose archive directory holds no XBRL at all, so it correctly stays a QC-704 warning.
- QC-701: 15/230 → 0/230. QC-704: 35/1,422 → 1/1,422.
- Email subject: `RED (8 blocking)` → `RED (0 blocking)`. The remaining blocking-severity findings are all accepted.

## Tests

`packages/core/test/filing-facts.test.ts` (11). The fixture is a verbatim excerpt of AVTR's real instance, asserted against the companyfacts points SEC publishes for the same accession, never against a fixture written from the parser:
- exactly companyfacts' rows: dimensional, nil, text-block and extension facts are dropped, and repeated tags are counted once;
- an instant has a null `period_start`;
- the taxonomy comes from the namespace, not the prefix;
- an HTML 200 is a parse failure;
- finding the instance in a directory listing (inline, plain, none, ambiguous);
- end to end: two calls to the right archive URLs, QC-704 closes `data_corrected`, QC-701 stops blaming SEC, and neither queue asks again;
- not queued before companyfacts has had 14 days;
- a filing with no XBRL is recorded and retried after 7 days;
- a refused listing and an HTML instance are both failures;
- SEC adding the filing itself closes `provider_fixed`.

`recipes.test.ts` gains the new module's sample. The full core suite passes (735).

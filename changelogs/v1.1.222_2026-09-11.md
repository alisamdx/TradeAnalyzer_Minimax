# v1.1.222 — 2026-09-11

## Four collector checks that fired on every run (`core` 0.6.1)

The existing app is bumped because the collector's quality gate runs inside it. Full write-up in
`NewApp/CHANGELOG.md`; spec rows patched in `NewApp/requirements/03` (QC-001, QC-008, QC-409).

gen-001's first full daily run (2026-09-10, run 3) was **red on three blocking checks**, and all three
were defects in the check or the phase rather than findings about the data. Each fires on every run,
so the pilot's clean-day streak could not have started.

| Check | Fired on 9/10 | Cause | Fix |
|---|---|---|---|
| QC-001 provenance (blocking) | 1 table | read `derived_iv30_daily`, whose `source_response_id` is null by definition | parsed layers only: `raw`, `ext`, `legacy` |
| QC-008 provider cap (blocking) | 16 of 20 EDGAR filers | every `filings.recent` list at 1,000 flagged, though EDGAR drops the OLDEST and the phase keeps only filings since its lookback | `submissionsAtCap(body, since)`: flagged only when the oldest kept filing is on/after `since` |
| QC-409 pins honoured (blocking) | 141 pins | phase 7 walked subset members only, so a pin on a non-member was never fetched | pinned tickers always fetched; a non-member at its pinned expirations only, the rest recorded `outside` |
| QC-207 bar gap (warning) | 1,083 tickers × 17 days | counted every window day without a bar, including days before the series began | only days between the first and last bar in the window |

Not changed, and worth knowing: the chain subset admits almost nothing until gen-001 has 20 bars per
ticker (the rule is a 20-day average dollar volume), and the 9/10 run's Finnhub calls returned
~34-byte non-2xx bodies (earnings stored 0) and Polygon short interest an 18-byte non-2xx body. Both
are warnings only and are not addressed here.

# v1.1.1 — 2026-06-14

## v2 execution subsystem — Phase 1 (broker seam + mock)

Second increment of the execution build. Establishes the broker abstraction that the
whole engine sits on, plus a deterministic mock so Phases 2–5 are buildable and testable
with **no IBKR account**. Still dormant — wired to nothing yet.

### `ExecutionBroker` interface — `src/main/execution/execution-broker.ts`

The seam over the execution venue (01-architecture §1.4): lifecycle (`connect`,
`isConnected`, `onConnectionState`), reference/pricing (`qualifyContract`, `priceCombo`,
`getBuyingPower`), orders (`placeOrder`, `cancelOrder`, `onOrderStatus`, `onFill`), and
truth for reconciliation (`getOpenPositions`, `getOrders`). Plus the supporting types
(`LegSpec`, `QualifiedContract`, `ComboQuote`, `OrderRequest`, `OrderAck`,
`OrderStatusUpdate`, `Fill`, `BrokerPosition`, `BrokerOrder`, `BuyingPower`, `ConnState`).
Implementations must be **idempotent on `clientOrderId`** (§2.8). These types are
main-process internal (the renderer talks to the core's control API, not a broker).

### `MockExecutionBroker` — `src/main/execution/mock-execution-broker.ts`

A deterministic, fully controllable in-memory broker — the backbone for offline
development and tests:

- **Deterministic pricing**: default pricer = 2% of strike per leg, so a short vertical
  yields a positive net credit proportional to width (injectable via options).
- **Controllable fills**: `fillMode` `auto | manual | partial | reject`, plus drive
  methods `fillOrder`, `rejectOrder`, `cancelOrder`.
- **Controllable environment**: `setConnectionState`, `setBuyingPower`, `setMark`.
- **Idempotent** on `clientOrderId`; **fail-closed** when disconnected (refuses to place).
- Tracks orders + positions; a closing order (reversed legs) matches and reduces/removes
  the position it opened (signature ignores leg action — a ticker holds ≤1 structure).

### Tests

`tests/mock-execution-broker.test.ts` (12 tests): connection/state, deterministic spread
pricing, contract qualification, auto-fill status sequence + fill + position, idempotency
(no duplicate on repeated COID), not-connected refusal, reject mode, manual mode + driven
fill, partial-then-complete, close reduces/removes position, driven mark, cancel.

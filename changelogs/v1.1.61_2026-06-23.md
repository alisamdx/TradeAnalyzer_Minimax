# v1.1.61 — 2026-06-23

## Execution control API wired into boot (live state readout)

`ExecutionControlApi` — the headless Fastify control server on `127.0.0.1:7433` — was built back in
Phase 3b but never actually started by the app. It's now launched at boot and stopped on
`will-quit`, so an external operator/agent can read live engine state and drive control (start /
pause / stop, kill switch) **while the Electron window is closed**.

The motivating use case: confirming the three switches for an unattended paper day are all set —
**broker = ibkr** (not the default mock), **engine-state = running**, **automation_mode = unattended
(armed)** — without reading console log lines or eyeballing UI pills.

### `/exec/state` enriched
Previously returned `{ engineState, killSwitch, executionMode, health }`. Now also carries:
- **`broker`** — `'mock'` or `'ibkr'` (from the broker factory's resolved settings).
- **`automationMode`** + **`armed`** + `drawdownPct` — via the engine facade's `getState()`, wired
  through new optional `ControlApiOptions.getStateView` / `brokerKind`.

```
GET http://127.0.0.1:7433/exec/state
    Header: X-Agent-Token: <contents of ~/.tradeanalyzer/agent.token>
→ { engineState, killSwitch, executionMode, automationMode, armed, drawdownPct, health, broker }
```

The token-auth, health probe (`/exec/health`, public), config/risk/positions/audit reads, engine
control, brief-ready handoff, and SSE event stream are all the same routes as before — they just
weren't reachable until the server was started.

### Back-compat
The endpoint still works constructed from core+governor alone (the test path) — `broker` defaults to
`'mock'` and `automationMode`/`armed` are simply absent. No engine or trade-logic change.

### Validation (FR-SEY-5)
Validation-exempt: a read/control surface, no change to trade selection, sizing, or exits.

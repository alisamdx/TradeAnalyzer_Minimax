# v0.32.53 — 2026-06-09

## Fix: critic column blank for all brief dates except today

### Root cause (two bugs)

**Bug 1 — critic fallback missing on LLM failure**
In `daily-intelligence-brief-job.ts`, when the Anthropic `synthesizeVerdict` call threw (rate-limit, transient API error, expired E*Trade token mid-run), the single `catch` block only logged a warning and left `pick.criticVerdict = null`. The `else` branch (no API key → always sets a rule-check verdict) was fine, but the `try` path had no analogous fallback. Stored nulls in `daily_briefs.picks` → Brief Trend showed "—" for all picks on those dates.

**Bug 2 — fragile date match in getBriefPickDrilldown**
`getBriefPickDrilldown` loaded critic data via:
```sql
WHERE DATE(generated_at) = ?  -- UTC date vs ET date in paper_trades.brief_date
```
While this works for typical 4:30 PM ET runs (UTC date = ET date), it is fragile — any transient UTC/ET difference (DST edge, late run) would silently miss all critic data for that date.

### Fix

**`src/main/services/jobs/daily-intelligence-brief-job.ts`**
- Separated `runRuleChecks` and `synthesizeVerdict` into nested try-catch blocks.
- On `synthesizeVerdict` failure: falls back to rule-check-only verdict (`confidence: 'low'`, `rationale: null`) so `criticVerdict` is never stored as null when rule data is available.

**`src/main/services/paper-trading-service.ts`**
- Replaced `DATE(generated_at) = ?` with a `brief_id` FK join:
  ```sql
  WHERE db.id IN (
    SELECT MAX(brief_id) FROM paper_trades
    WHERE brief_date = ? AND brief_id IS NOT NULL
    GROUP BY brief_strategy
  )
  ```
  Uses the direct FK already written by `autoCapture`. `MAX(brief_id)` picks the latest run per strategy when the brief was re-run on the same day.

### What this does NOT fix
Existing `daily_briefs` rows for June 3-8 that already have `criticVerdict: null` in their picks JSON cannot be retroactively backfilled — the brief job always uses "today" as the date. Those dates will continue showing "—" in the Critic column.

# v1.1.144 — 2026-09-01

## feat: log E*Trade API calls — the provider was completely dark

### The gap

`logs/api/` has instrumented Polygon since the logger existed. **E*Trade wrote nothing.**
Measured 2026-09-01: 17,200 Polygon entries for the day, **zero** E*Trade. `logs/errors/` was
empty too.

That made every E*Trade failure invisible after the fact, and it is what blocked diagnosing
why **Sync Closed Positions** imports nothing. `insertClosedPosition` always writes an
`exit_price`; no row in the database has one, so it has never inserted a record — the failure
is upstream at the fetch or the transaction match. With no log there was no way to tell which,
or even whether the request was made.

That matters beyond convenience: the closed-position sync is what replaces estimated marks
with real fills, and without it the wheel book's realized P&L is inference. The stored figures
are out by **$4,954** against a hand-reconstruction (a −$3,736 assignment booked as a loss when
it was a conversion into stock, and a covered call booked at −$463 when it expired worthless).

### Change

`etradeGet` — the single choke point for E*Trade calls — now writes an `ApiLogEntry` with
`provider: 'etrade'` on every outcome:

- **success** — status, latency, response size
- **non-2xx** — plus `errorMessage` and a 300-char `responseBodyPreview` carrying E*Trade's own
  error envelope, which is exactly what diagnosis needs
- **network fault** — `responseStatus: null` plus the thrown message. A dormant E*Trade token
  can terminate the stream instead of returning 401 (CLAUDE.md), and that previously left no
  trace whatsoever.

### Three deliberate safety properties

1. **Success bodies are never written to disk.** They carry positions, balances and quotes, and
   the log is plaintext with 30-day retention. Only *failure* bodies are previewed.
2. **The account key is masked**: `/v1/accounts/{accountIdKey}/transactions` logs as
   `/v1/accounts/{acct}/transactions`. The call's shape is preserved, the brokerage identifier
   is not.
3. **Logging can never break an API call.** All four sites go through a `safeLog` wrapper that
   swallows logger exceptions. The logger touches the filesystem and Electron's userData path,
   so without this a disk error would turn every E*Trade request into a hard failure — trading
   the blind spot for something strictly worse.

Only the caller's query params are logged, scrubbed via the existing `scrubObject`; the OAuth
Authorization header is never included.

`ApiLogEntry` gains optional `errorMessage` and `responseBodyPreview`; the Polygon path is
untouched.

### Tests

New `tests/etrade-api-logging.test.ts` (6): success logged without the response body; account
key masked out of the endpoint; provider error envelope captured on a 400; network fault
recorded with a null status; real params preserved while credentials and the OAuth header never
appear; and a throwing logger does not break the call.

One note on the leak assertion — it uses distinctive canary credentials. Short values like
`'at'` collide with ordinary JSON keys (`"responseStatus"` contains "at"), which would have made
the test fail for a reason unrelated to leaking. Suite: 993 passed.

### What this unblocks

Next time Sync Closed Positions is run, `logs/api/api_<date>.jsonl` will contain the E*Trade
transactions call — or show that it was never made. Either way the cause becomes visible instead
of inferred. The three candidate fixes (missing `withRenew` on the portfolio path, a rejected
request, or the open/close transaction matcher) are mutually exclusive, so the log decides which
one to make.

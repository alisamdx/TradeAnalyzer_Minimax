# v0.22.5 — 2026-06-01

## Fix: Daily IV Update — all tickers "no-data"

### Root causes

**Bug 1 — null `underlyingPrice` (the "no-data" cause)**

`etrade-options.ts` `getETradeOptionsChain` extracted the underlying stock price with:
```ts
const underlyingPrice = num(resp['currentPrice'] ?? resp['CurrentPrice']);
```
E*Trade v1 `OptionChainResponse` actually puts the underlying price in `nearPrice`, not `currentPrice`. So `underlyingPrice` was always `null` for every ticker.

`captureFromEtradeChain` guards `if (!underlyingPx || contracts.length === 0) return` — so it bailed out on every ticker without writing any IV row, producing the "no-data — Could not compute ATM IV from chain" message.

**Fix**: check `nearPrice`/`NearPrice` first, fall back to `currentPrice`/`CurrentPrice`.

**Bug 2 — IV stored as decimal fraction instead of percentage**

`OptionContract.iv` is a decimal fraction (0.285 = 28.5%) as documented in `etrade-data-provider.ts`. A wrong comment in `captureFromEtradeChain` claimed it was "already a percentage" and passed it directly to `computeAtmIv` without converting — so stored `atm_iv` values would have been ~100× too small (0.285 stored instead of 28.5).

**Fix**: multiply `c.iv * 100` when mapping contracts before calling `computeAtmIv`.

### Files changed

- `src/main/services/etrade-options.ts` — `nearPrice` added to `underlyingPrice` extraction
- `src/main/services/iv-history-service.ts` — `c.iv * 100` in `captureFromEtradeChain` mapping; comment corrected

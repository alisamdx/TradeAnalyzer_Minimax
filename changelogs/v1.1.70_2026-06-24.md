# v1.1.70 — 2026-06-24

## Settings-driven broker selection + Tradier execution adapter (skeleton)

### Why
IBKR has become a dead end for this account: the live Options upgrade was approved only to **Level 2**
(long calls/puts — no spreads), with a 30-day cooldown before another L3 attempt, and the paper
account never had spread permission either. The engine's entire book is defined-risk multi-leg combos
(L3), so IBKR can place none of them. Per `Requirements/v2-execution/07-broker-alternatives.md`,
**Tradier** is the only remaining venue that offers a *real* sandbox/paper environment **and**
production on the **same REST API** with native multi-leg orders — restoring the "soak then go live
on one adapter" property the v2 design wants. (E\*Trade can't paper at all — its sandbox is canned
data.) IBKR stays fully supported behind the seam and is a dropdown away if L3 is ever approved.

This ships the two pieces that don't depend on a funded Tradier account: the **§3 settings substrate**
(needed by every path) and the **Tradier adapter skeleton** (pure, tested mapping helpers + a
fail-closed network shell to fill in against the sandbox once tokens arrive).

### §3 — per-mode, settings-driven broker selection
- **Migration 060** adds `exec_config.paper_broker` / `live_broker` (`mock | ibkr | tradier`).
  Default **`mock`** — preserves today's opt-in behaviour exactly (no install silently connects to a
  real broker after upgrading).
- `ExecConfig` gains `paperBroker` / `liveBroker` (+ new `ExecBrokerKind` type); `RiskGovernor`
  get/updateConfig map and **validate** them (unknown → safe `mock`).
- `broker-factory` is now config-driven. Resolution precedence: explicit **`TA_EXEC_BROKER` env**
  (dev/test override) → persisted `{paper,live}_broker` by mode → `mock`. The active venue +
  Tradier env are logged at boot (`[execution] broker=tradier mode=paper @ sandbox`).
- **Execution Settings** gains a **Paper broker** and **Live broker** dropdown in the Mode group;
  changing the **live** broker to a real venue requires a confirm gate (same as switching to live).
- The fail-closed spread-permission preflight (§2.13) and the type-to-confirm live gate are
  broker-agnostic, so Tradier (and any future venue) inherits them automatically.

### Tradier adapter (`TradierExecutionBroker`) — skeleton
- **Pure, unit-tested mapping helpers** (offline, no account needed): OCC/OSI `option_symbol`
  build + parse, Tradier order sides, `class=multileg` payload (parallel indexed arrays + COID
  `tag`), net debit/credit/even **sign convention** (+ inverse for fills), status mapping, combo
  pricing from per-leg quotes, and a fail-closed order-preview classifier for the permission probe.
- **Network methods** implemented to Tradier's documented REST shapes — Bearer auth, sandbox vs
  production base URL by mode, **polling**-based order status/fills (no local gateway to babysit),
  positions/orders/balances reads, idempotency on `clientOrderId` via the order `tag`, and a
  fail-closed `connect()`/401 → `reauth_needed`. Every endpoint/field is marked **`// VERIFY`**:
  these are written from the docs and **not yet calibrated against a live sandbox** (pending L3
  approval + tokens), mirroring how the IBKR adapter was written before paper calibration.
- Tokens come from env for now (`TA_TRADIER_TOKEN_SANDBOX` / `TA_TRADIER_TOKEN_PROD` /
  `TA_TRADIER_TOKEN`, `TA_TRADIER_ACCOUNT_ID`); a secure-settings UI for token entry is follow-up
  work for when the account clears.

### What's left for live Tradier trading (when the account + L3 land)
1. Generate sandbox + production tokens; wire token storage into secure-settings + a settings field.
2. Calibrate every `// VERIFY` endpoint/field against the live sandbox (quotes, balances, order
   preview/place, orders/positions payload shapes, commission surfacing).
3. Wire chain-discovery for `checkSpreadPermission`'s reference probe (currently fail-closed without
   a supplied probe).
4. Live canary (1 contract, smallest spread) before normal sizing.

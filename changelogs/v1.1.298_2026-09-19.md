# v1.1.298 — 2026-09-19

TradeAnalyzer only. Layout fix.

## The Spread Shadow page scrolls

Reported by the operator: the page had no scrollbar, so everything past the window height was unreachable.

`section.main` is a flex column with `overflow: hidden`, so **each view must scroll itself**; one that does not is clipped at the window edge. The long views do this through their own class (`.daily-brief-view`, `.retro-view`, `.trade-scoring-view`, each `flex: 1; min-height: 0`), and `SpreadShadowView` shipped as a plain padded `div` with neither.

New shared class `.view-scroll` (`flex: 1 1 auto; min-height: 0; overflow-y: auto; padding: 16px`) — `min-height: 0` is the part that is easy to miss, because without it a flex child will not shrink below its content and `overflow-y` never engages. Applied to:

- **SpreadShadowView** — the reported page. Its positions table also had `maxHeight: 520`, a second scroll box that would have trapped the wheel inside the table once the page itself scrolled; it is now sideways-only, and the page scrolls as one.
- **RollAnalyzerView** and **ConstituentsView** — the same padded-root shape, clipped the same way on a short window. Neither was reported; both are fixed while the cause is in hand.

## Tests

`tests/spread-shadow-ipc.test.ts`: `.view-scroll` declares `overflow-y: auto` **and** `min-height: 0`, and the view uses the class.

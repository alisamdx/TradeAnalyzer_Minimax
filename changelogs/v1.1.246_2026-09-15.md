## Constituents refresh repaired, a "warning" batch status, universe seed reports closures

### Why

The first `scripts/day-report.mjs` run showed:

- **`constituents-refresh` has failed on both sources in every run since about 2026-09-08** and still reported `success`. Its notes on 2026-09-08, 09-11 and 09-14 all read `refresh FAILED — kept existing list`.
  - Vanguard: `Unexpected token '<', "<!doctype "... is not valid JSON`.
  - Wikipedia: `returned only 0 rows`.
- Before that, Vanguard succeeded but reported "no changes" on Aug 24 and Sep 1, weeks after EA delisted on Aug 4.
- The operator's `universe_seed` after v1.1.245 read "1083 tickers, 0 memberships opened, 0 reference rows", which looks like nothing happened. The seed does close departures (`reconcileMembership`), but the note never said so.

VONE gives `size=1024` with the same shape.
- **Wikipedia S&P 500:** `<table class="wikitable sortable mw-collapsible sticky-header" id="constituents">` has 504 rows, every one an attributed `<tr id="mw…">`, and 0 bare `<tr>`. EA and WBS are absent and VMRK is present.
- **Wikipedia Russell 1000:** no constituents table remains; the only wikitables are highs and annual returns.
- **iShares holdings CSV** (IVV/IWB): HTTP 200 `text/csv` whose body is an HTML page. Not usable as a replacement.

### Changes

1. `constituents-service.ts`:
   - Vanguard base URL is now `/vmf/api/{fund}/portfolio-holding/stock`.
   - A JSON parse failure is rethrown as "did not return JSON — the API has probably moved".
   - `asOfDate` is carried as `ConstituentsRefreshOutcome.asOf`.
   - The Wikipedia row regex accepts attributes.
2. `constituents-refresh-job.ts`: returns `warning` when any index refresh failed, and the note includes "(holdings as of YYYY-MM-DD)".
3. `BatchJobResult.status`, `BatchRun.status` and `BatchJob.lastRunStatus` gain `warning`, which is:
   - stored and mapped by `BatchService`
   - raised as a warning notification
   - logged at WARNING by the run logger
   - counted as a completed run for `last_success_date`
   - not treated as a recent success by the orchestrator's resume skip
   - continued by the orchestrator, and counted in its note
   - shown as a yellow `StatusBadge`
   - flagged in the day-diagnostics attention list
4. `collector-oneshot.ts`: the `universe_seed` note reports `membershipsClosed` and any failed lists.

- `tests/batch-run-log.test.ts`: a warning run is stored, mapped and logged as warning.

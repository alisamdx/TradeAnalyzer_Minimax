# v1.1.9 — 2026-06-14

## v2 execution subsystem — Phase 5b (activation)

The first **non-dormant** step. The execution engine is now instantiated in the running
app (against the deterministic `MockExecutionBroker`, engine `stopped`) and exposed to the
renderer over IPC. No real orders, no broker connection, no auto-entries — but the
subsystem is live and drivable. The Electron Trading Desk / Settings UI lands next
(Phase 5c/d).

### Activation (`src/main/index.ts`)

`ExecutionEngine` is constructed with a `MockExecutionBroker` after the Brief Replay
service. Constructing it is inert: the engine starts `stopped`, opens no broker
connection, and places no orders. Its event stream is forwarded to the renderer via
`webContents.send('execution:event', …)` so the future UI updates live.

### IPC surface (`src/main/ipc/ipc-execution.ts`)

New `registerExecutionIpc(engine)` — a thin pass-through to the engine facade:

- **reads:** `execution:get-state`, `:get-config`, `:get-risk-state`, `:get-positions`,
  `:get-proposals`, `:get-audit`
- **config:** `execution:update-config`
- **control:** `execution:start` / `:stop` / `:pause`, `:kill-trip` / `:kill-clear`
- **approvals:** `execution:approve-proposal` (routes entry→order-manager,
  exit→management) / `:reject-proposal`

### Preload bridge (`src/preload/index.ts`)

New `window.api.execution.*` namespace (34th) mirroring the IPC surface, plus
`onEvent(cb)` subscribing to the `execution:event` stream (returns an unsubscribe fn).

### Types (`src/shared/types.ts`)

Renderer-facing facade shapes: `ExecEngineStateView`, `ExecEngineHealth`,
`ExecEngineEvent`, `ExecPositionRow`, `ExecProposalRow`, `ExecAuditRow`,
`ExecApproveResult`, `ExecStartResult`. Reads come straight off the SQL selects, so
positions/proposals/audit are the raw snake_case rows; the UI maps as needed.

### Tests

No new tests — the facade is already covered by `tests/execution-engine.test.ts` (6) and
the IPC layer is a pure pass-through. Full suite green (441).

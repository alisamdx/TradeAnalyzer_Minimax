# v1.1.218 — 2026-09-09

`@tradeanalyzer/core` 0.3.8, `@tradeanalyzer/next` 0.1.4. **NewApp B8 complete.**

## `collector-oneshot` executes `legacy_import`

The fourth implemented one-shot. It copies Q19 categories 1 (user-authored
config) and 5 (stored decisions, marked `pre_collector = 1`); categories 2, 3
and 4 have **no code path at all** — not a flag, not a disabled branch. A
category that cannot be copied by accident beats one guarded by a boolean
somebody flips.

- **No ATTACH.** 04 §7.4 drafted one, "write-capable but read-only in intent",
  to work around the Windows WAL problem. But this job runs *inside* the app
  that already holds a write-capable handle to the old file — so the handle is
  passed in, and the problem the workaround existed for does not arise.
- **An inverted conviction band is rejected, not carried** — the case Q19 names
  by hand. It never throws; it just computes the wrong zone, and it fed wrong
  Buy-zone alerts for three weeks. Every rejected row is **listed with its
  reason** in `legacy_import_log.rejection_report_json`, not counted: a count
  says the import dropped something, the list says what and why.
- The operator's line reports rejections as the **deliverable**, not an error.
- An absent source table is recorded with zero counts rather than skipped, so
  "this install had no payoff strategies" and "the importer forgot payoff
  strategies" do not look the same in the log.

## A re-run guarantee that was never there

04 §7.4 promised "a second run writes nothing already present (natural keys)".
**`naturalKey` is metadata only** — the DDL generator emits no unique index
from it — so the `INSERT OR IGNORE` written against that promise had nothing to
conflict on and dedupped nothing. It would have read as protection while
providing none.

The two halves want different behaviour and both are now explicit:

- **Configuration is versioned per import.** `import_run_id` is part of its
  declared natural key, so each import is a distinct event — and that answers
  something a deduplicated table could not: what the configuration looked like
  at each import.
- **Decisions are deduplicated** by an explicit natural-key check. Their key
  carries no import id, so without it a second import would have duplicated the
  entire brief history.

`import_run_id` is also an **INTEGER foreign key to `meta_run`**, not the
composite string I first assumed — which cost one round of foreign-key
failures.

## What was read is archived

Each source table's rows are archived as a `host_app` response
(`legacy/import/<table>`). `legacy_config_import.source_response_id` is NOT
NULL, and for a moment that looked like the `derived_iv30_daily` problem, where
nothing honest could be named. It is the opposite case: the rows read out of
the old database **are** the source, so archiving them makes the claim true
rather than convenient — and it preserves the rejected rows, which is the only
way a disputed rejection can be re-examined.

## The Legacy view

Rows handed over live carry every candidate the brief scored; rows imported
backwards are survivors-only. **The split is the first thing on the screen**,
because pooling a biased sample with an unbiased one is exactly what
`pre_collector` exists to prevent. A run's *rejected* count leads the table,
and a zero there on an imported run reads **"not recorded"** rather than "it
rejected nothing" — opposite facts.

AC-13 caught three more real collisions (`slot`, `mode`, `survived`, all
dictionary columns) and none was exempted: the DTO fields are `phase`,
`strategy`, `picked`. Five renames across two views today, zero exemptions.

`1,256` tests here, `381` in `core`, `29` in `next`.

# v1.1.306 — 2026-09-22

## An alias ruling is data, and now it has somewhere to live

### The finding

QC-909 fired for the first time on 2026-09-21, seven times. Finnhub had answered
a recommendation request for a different symbol than was asked:

| asked | answered | |
|---|---|---|
| GOOG | GOOGL | Alphabet C / A |
| BRK.B | BRK.A | Berkshire B / A |
| NWS | NWSA | News Corp B / A |
| GFL | GFL.TO | GFL Environmental, Toronto listing |
| JHX | JHX.AX | James Hardie, Australian listing |
| **LLYVA** | **FWONA** | **Liberty Media Formula One — a different company** |
| **LLYVK** | **FWONA** | **the same, under a second Liberty Live class** |

The first five are other listings of one company. The last two are not: LLYVA
and LLYVK were both carrying Liberty Media Formula One's analyst counts —
identical numbers under two tickers that are not that company.

`provider_symbol` (v1.1.257) recorded what came back, so nothing was lost and
the check could see it. What was missing was anywhere to put the **answer**.

### What shipped

`ref_provider_symbol_ruling` (dictionary **v21**) — provider, asked ticker,
answered symbol, `same_issuer` / `different_issuer`, note, who and when. Seeded
idempotently in **preflight**, before it is read, alongside `ref_trading_day`
and `ref_macro_series`, for the reason those are: a reference table that exists
only if somebody remembered to seed it is one that will be missing on the day it
matters.

- **The recommendations ingest refuses a `different_issuer` answer.** LLYVA and
  LLYVK stop carrying FWONA's ratings from the next weekly sweep, and read as
  having no analyst coverage — which is **true**, and which QC-905 will report
  as the gap it is.
- **QC-909 no longer fires on a ruled pairing** and closes the open finding as
  `rule_changed`, naming the ruling. A standing answer is not an open question,
  and leaving seven settled rows in the report made an unruled eighth harder to
  see, which is the whole point of the check.

Verified on a copy of the live generation: all 7 fired before seeding, none
after, all 7 closed `rule_changed`, and exactly the two FWONA pairings became
refusals.

### Fail-open, in the opposite direction from the calendar

`ref_trading_day` fails open by treating an unknown date as a **trading day** —
a needless run costs calls, a skipped one costs a day. This table fails open the
other way: an **unruled** mismatch is still stored and still reported.

That asymmetry is the design. Dropping a row on no evidence would hide a feed
gap behind silence, and QC-909 exists precisely to keep a pending decision
visible. Only an explicit `different_issuer` ruling stops a write.

### The refusal rides in the recipe

Same reasoning as v1.1.305's Form 4 widening, and worth stating because the
direction is reversed: **a parser that stores FEWER rows breaks replay equality
(AC-4 / QC-951) exactly as one storing more does.** A ruling made today must not
retroactively change what a response captured last week parsed to.

So `refusedSymbols` is a recipe argument, omitted when empty so an unruled
ticker keeps its exact digest. A pre-ruling response's stored recipe has no such
key, `parseStoredRecipe` rebuilds the parser without it, and its replay
reproduces the rows it produced then.

### What was NOT done, deliberately

**The 28 rows already stored under the ruled tickers stay.** Deleting them would
destroy the evidence of what Finnhub answered, and this project has ruled on
that shape before: `repairStickyOsiPadding` closes the mispadded ranges and
opens corrected ones rather than rewriting in place, *because the old symbol is
the evidence for the findings it caused*. Every one of those rows carries
`provider_symbol = 'FWONA'`, which is the column's declared purpose — a reader
that sums recommendations without checking it was already wrong, and still is.

Nothing reads `raw_analyst_recommendation` yet, so there is no live consumer to
correct. If the rows should go, that is a one-line follow-up and a separate
decision.

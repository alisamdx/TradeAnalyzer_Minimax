# v1.1.180 — 2026-09-03

## fix — the balance snapshot ran on only one of two sync paths

v1.1.179 shipped capital utilisation, and the operator synced and still saw *"no balance synced
yet"*. **The API log for that day contained zero `/balance` calls** — the snapshot never ran.

### What was wrong

There are two ways a portfolio sync happens, and only one was instrumented:

| path | route | snapshotted? |
|---|---|---|
| scheduled batch job | `PortfolioSyncJob.run` → `syncPortfolio` | yes — the job called `syncBalances` itself |
| **the Sync button** | `portfolio:etrade:sync` IPC → `syncPortfolio` | **no** |

The manual button goes straight to `syncPortfolio`, which knew nothing about balances. The
snapshot would have appeared eventually on the next scheduled run, which is exactly the kind of
"works, just not when you look" that wastes an evening.

### The fix, and why it is this fix

Patching the second call site would have left the same trap for the third. The snapshot now lives
**inside `syncPortfolio`** — the one function both paths call — so it cannot be forgotten by a
caller again. `syncBalances` also takes the account list as an argument instead of re-fetching it,
so moving it inside costs one `/balance` call per account and **no extra `/accounts/list` round
trip**.

The job's separate step is removed; it gets the snapshot through `syncPortfolio` like everything
else.

### Pinned by tests

`tests/etrade-balance-sync.test.ts` (6 tests) asserts the property that failed, not just the code
path: a balance row appears **as a consequence of syncing the portfolio**. Also covered —

- the required query params are sent (`instType=BROKERAGE`, `realTimeNAV=true`; E\*Trade rejects
  the call without the first and returns previous-close values without the second)
- a failing balance call **does not** become a sync error — the position book is the real payload
- a missing field stores **null, not 0**
- a same-day re-sync replaces rather than duplicates
- exactly **one** `/accounts/list` call, guarding the round-trip saving above

# v1.1.148 — 2026-09-01

## feat: preflight the transactions endpoint — diagnostic, and 18 minutes faster to fail

### What the last attempt established

The re-sign retry from v1.1.147 fired and still failed:

```
01:25:21.135  401  120525ms  nonce_used  → retrying once with a fresh signature
01:27:21.660  401  120565ms  nonce_used  (the retry, with a brand-new nonce)
```

**A fresh nonce cannot have been used before.** That kills the transport-retransmission theory
along with the earlier range-width one. Both attempts took ~120.5 s — essentially identical and
suspiciously round — which reads as a server-side timeout that E*Trade reports as
`oauth_problem=nonce_used`. The OAuth message is a mask, not the cause.

Everything else on the same credentials, same account key and same signing code works:
`accounts/list` 308 ms, `accounts/{key}/portfolio` 371 ms, 26 market calls ~300 ms, all 200.
Only `transactions` hangs, and it hangs identically for 31 days and for 8 months.

### Change

A **preflight probe** before the sliced loop: one minimal request with **no date range**
(E*Trade defaults to a recent window), 45 s budget.

It answers the open diagnostic question — *is this endpoint alive for this account at all,
independent of our date parameters?* — and it earns its place in production regardless. Without
it, a dead endpoint costs **9 slices × 120 s ≈ 18 minutes** of silent grinding before the import
gives up. Now it fails in under a minute with a message that names the likely owner of the
problem:

> E*Trade transactions endpoint did not respond to a minimal no-date request. Every other
> E*Trade call is working, so this is almost certainly server-side at E*Trade rather than a
> date-range or signing problem.

### Reading the result

- **Probe returns 200 quickly** → the endpoint is fine and our *date parameters* are the
  trigger; the fix moves to how the range is expressed.
- **Probe times out** → the endpoint is down for this account and no client-side change will
  help. Stop paying for it and settle closed positions from expiry prices instead.

### Tests

`tests/etrade-transactions-slicing.test.ts` +2 (6 total): the first transactions call carries
`{count}` only, no `startDate`, on a 45 s budget; and an unresponsive endpoint produces exactly
**one** call plus the descriptive error rather than nine timeouts. The existing slicing
assertions now filter the probe out by `startDate`. Suite: 1004 passed.

### Note on this sequence

Three theories have now been tested and falsified against the logs — range width (v1.1.146),
transport replay (v1.1.147), and with this probe, date parameters. Each was disproved by
evidence rather than argument, which is only possible because E*Trade calls became visible in
v1.1.144. Before that this failure had been silent for months.

# v1.1.94 — 2026-07-01

## Fix: on-demand E*Trade options path self-heals from a dormant token

### How it was found
While running an ad-hoc MRVL options-chain query against the live API server (to confirm
the §12 weekly-vs-monthly liquidity finding on one clean case), **every** expiry — including
SPY — returned an empty chain (`{"ok":true,"data":[]}`) even though the app was up and had
successfully fetched chains earlier the same evening. The token had gone dormant since the
~18:33 ET manual run and the on-demand path wasn't waking it.

### Root cause (same class as v1.1.92, different path)
`ETradeDataProvider.withRenew` guarded its renewal on an auth-shaped error:

```ts
if (!isEtradeAuthError(err)) throw err;   // isEtradeAuthError: 401|token|auth|oauth
```

A dormant token (idle > 2 h) does **not** reliably surface as a 401 — it kills/hangs the
response stream (undici `TypeError: terminated`). That misses the heuristic, so the renewal
never ran, the error propagated, and the options route's per-expiration `catch { continue }`
swallowed it into an empty chain.

This is the identical blind spot fixed for the batch connectivity probe in v1.1.92, but on
the **on-demand provider path** — which serves the API server (`/options/:ticker`), the
Strategy Lab, the TraderAgent scout, and the **v2 execution engine's entry-time re-pricing**.
That last one matters most: a dormant token would make a live combo re-price return empty at
the exact moment the engine is deciding whether to enter.

### Fix
`withRenew` now renews and retries once on **any** error:

```ts
try { return await fn(this.getCreds()); }
catch {
  try { await renewAccessToken(this.getCreds()); } catch { /* active-token renew is harmless */ }
  return await fn(this.getCreds());
}
```

Renewing an active token errors harmlessly (swallowed); a genuine non-auth error (bad symbol,
network down, or a token expired past midnight ET) simply fails again on the retry, surfacing
the real error to the caller. Removed the now-unused `isEtradeAuthError` helper.

### Files
- `src/main/services/etrade-data-provider.ts`
- `tests/etrade-dormant-token-renew.test.ts` — updated the two cases that encoded the old
  auth-only contract to the new any-error contract, plus a `terminated`-stream regression
  (dormant token kills the stream → renew+retry) and the renew-fails-then-retry-fails case
  (the retry's real error surfaces, not the renew error). 4 tests.

### Note
This fix takes effect on the next app launch. The dormant token in the *currently running*
1.1.93 instance still needs a manual wake (open the app's E*Trade view / reconnect) before the
pending live MRVL weekly-vs-monthly A/B can run.

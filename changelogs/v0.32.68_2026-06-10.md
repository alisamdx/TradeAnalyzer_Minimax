# v0.32.68 — 2026-06-10

## Changed

**Batch Jobs screen: stable three-panel layout** ([BatchView.tsx](../src/renderer/src/views/BatchView.tsx))

Root cause of the "dancing" layout: the live-log auto-scroll used `scrollIntoView`, which scrolls *every* scrollable ancestor — each progress event yanked the whole page down, pushing the Registered Jobs grid out of view. Additionally the Live Activity panel was conditionally mounted (appearing/disappearing shifts layout) and auto-cleared 3 seconds after a run finished, making failures impossible to copy.

- **All three panels fixed height**: Registered Jobs 300px (internal scroll, sticky header), Run History 160px (~4 rows, internal scroll), Live Activity log 200px. Constant page height — no layout shift, ever.
- **Live Activity always visible** with an idle placeholder; the log persists after a run (failures can be inspected/copied) and resets only when the next run starts.
- **⧉ Copy** button (full log to clipboard) and **✕ Clear** button added to the Live Activity header.
- **Auto-scroll** targets only the log container (`scrollTop = scrollHeight`), never the page.
- Sticky `thead` for all batch tables via shared CSS rule.

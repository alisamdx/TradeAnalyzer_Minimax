# v1.1.42 — 2026-06-17

## Portfolio E*Trade sync is a full sync (closes positions gone from the broker)

### The bug (user report)
After closing a position at E*Trade (e.g. NVDA), the local portfolio kept showing it as open.
`syncPortfolio` only **upserted** the positions E*Trade returned (keyed on `etrade_position_id`)
— it never removed positions that were in the local DB but no longer at the broker. So a closed
position lingered indefinitely.

### The fix
After a **successful** position fetch for an account, the sync now reconciles via the new
`closeMissingPositions`: any position that is

- `status = 'open'`, **and**
- E*Trade-sourced (`etrade_position_id IS NOT NULL`), **and**
- for the synced account (`etrade_account_id = …`), **and**
- whose broker id is **not** in the just-fetched set

is marked `status = 'closed'`. The row is preserved (notes, realized P&L, history); the portfolio
views show only `status = 'open'`, so the closed position drops off. The sync result gained a
`positionsClosed` count, surfaced in the status line ("Synced: N updated, M skipped, K closed").

Safety / correctness:
- **Runs only after a successful fetch** — inside the per-account `try`, after the upsert loop —
  so a fetch error or partial failure never closes positions.
- **Scoped to the synced account(s)** (and the single account when a target account is passed).
- **Never touches manual positions** (no `etrade_position_id`).
- The upsert UPDATE now also re-asserts `status = 'open'`, so a position the broker reports again
  (or after a transient empty fetch) self-heals back to open on the next sync.
- An account that is genuinely flat (empty fetch) correctly closes all its open broker positions.

# v1.1.146 — 2026-09-01

## fix: closed-position import died on a single YTD transactions query

### Diagnosis — the first thing the new E*Trade logging caught

`Import Closed (YTD)` had never worked. With E*Trade instrumented (v1.1.144), one click gave
the whole answer:

```
01:08:09.192  200      308ms  /v1/accounts/list
01:08:09.501  401  120250ms  /v1/accounts/{acct}/transactions
      params={"startDate":"01012026","endDate":"09022026","count":"50"}
      BODY: <Error><message>oauth_problem=nonce_used</message></Error>
```

**One** app-level request, stalled **120 seconds**, answered `oauth_problem=nonce_used`.

The nonce generator is `Math.random()`-based and unique per call, so the code was not reusing
a nonce. The duplicate came from a **transport-level retransmission**: the socket hung long
enough for undici to resend the already-signed request, so E*Trade saw the same `oauth_nonce`
twice and rejected the replay. Every other E*Trade call that session finished under 500 ms —
the stall was the 8-month span (`01012026` → `09022026`).

### Fixes

**1. Slice the query (`fetchTransactionLegs`).** The YTD range is now walked in ~30-day
windows instead of one span, keeping each response small enough to return promptly. That
removes the stall that triggers the replay. Slices are contiguous — each starts the day after
the previous ends — so no transactions are lost between them.

**2. Hard timeout on every E*Trade request (`ETRADE_TIMEOUT_MS`, 30 s).** Without one, a
stalled connection hangs until Node's default and gets retransmitted with the *same signed
header*. A retry has to re-enter `etradeGet` so it re-signs with a fresh nonce; aborting makes
that the only path. 30 s is generous by two orders of magnitude against the observed sub-500 ms
norm — it exists to fail fast and legibly, not to bound normal latency.

**3. Numeric paging markers.** `marker` was only followed when `typeof === 'string'`. E*Trade
returns it as a number on this endpoint, so paging silently stopped after the first page and
every transaction beyond it was lost. Both shapes are now coerced.

### Tests

New `tests/etrade-transactions-slicing.test.ts` (3): the year is split into windows of ≤31 days
rather than one YTD span; the slices tile the full range contiguously with no gaps and land on
`MMDDYYYY`; and pagination follows a **numeric** marker. Suite: 997 passed.

### Still open

`etrade-portfolio-service.ts` calls `etradeGet` with **no `withRenew` wrapper** on any of its
three paths, unlike every other E*Trade consumer. That did not cause this failure — the token
was valid, `accounts/list` returned 200 — but it remains a real gap: a dormant token on this
path fails outright instead of renewing. Left for its own change rather than folded in here.

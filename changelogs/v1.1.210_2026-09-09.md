## fix — a checkpoint that worked and a checkpoint that never ran looked identical

v1.1.209 gave `ElectronCollectorHost.close()` an explicit
`wal_checkpoint(TRUNCATE)` and logged a `WARNING` **only when it did not fully
apply**. That is warning-only instrumentation, and it reproduces one level up the
exact ambiguity the checkpoint was added to remove:

| what the log says | what actually happened |
|---|---|
| nothing | the checkpoint applied cleanly |
| nothing | `close()` was never reached at all |

Those are opposite readings of the test the whole investigation is now waiting
on. The next seed is a real test of the checkpoint fix — and if it comes back
clean with no checkpoint line in the log, the clean result says nothing about the
checkpoint, because the code path may never have run.

**Now every close writes a line**, with the number that gives it scale:

```
INFO    CollectorCheckpoint  checkpoint applied — walBytes=4193792 busy=0 log=1024 checkpointed=1024
WARNING CollectorCheckpoint  checkpoint did NOT fully apply — walBytes=4193792 busy=1 log=1024 checkpointed=0
WARNING CollectorCheckpoint  checkpoint threw — walBytes=4193792: <message>
```

`walBytes` is `-1` when there is no `-wal` to stat, which is reported as such
rather than as zero — "no write-ahead log" and "an empty one" are different
facts, and a fully applied checkpoint over an empty WAL is not the same evidence
as one over four megabytes.

The throw path is the third outcome and gets its own line; silence would have
collapsed it into the other two.

`packages/next` has logged every checkpoint unconditionally since it was written.
This is the host catching up — **a rule pinned in one implementation does not
constrain the second one**, which is the fourth time that shape has cost this
project something.

## Where to look

`logs/errors/errors_<date>.jsonl` in the existing app's `userData`, filtered on
`"errorClass":"CollectorCheckpoint"`.

## Test

`tests/collector-host.test.ts` — *reports the close-time checkpoint on success as
well as on failure*. A source assertion, like its neighbours: it pins the level
expression, `walBytes`, and the separate throw path. `1,248` tests.

## Not changed

`ElectronCollectorHost.polygonGet` still bypasses the rate limiter (spec 06 §5,
CLAUDE.md). Still deliberate: routing it through the limiter changes the
collector's write pace, and the pace is an experimental variable while the
corruption is open.

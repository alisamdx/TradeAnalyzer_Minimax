# v1.1.33 — 2026-06-17

## ADX arithmetic fix + removed from scoring (FR-SEY-5 validated)

### The bug
`analysis-service.computeADX` produced ADX ~`period`× (14×) too large: AMD read **648** (true
~46), MRVL 633 (~45). The final ADX step reused the Wilder running-**sum** helper used for the
smoothed TR/+DM/−DM. That's correct for the +DI/−DI **ratios** (the sums cancel), but ADX is the
Wilder **average** of DX — the code never divided by `period`. The impossible values saturated
the trend signals (ADX component pinned at its cap) and surfaced "trendNeutral score of 630" in
a brief rationale. The separate `daily-technical-signals-job.computeADX` was already correct
(it averages: `dx.slice(0,n).reduce(+)/n`, then the recursive average).

**Fix:** divide the smoothed DX by `period` (`smoothDX/period` is the exact Wilder ADX
recursion). ADX is now bounded [0, 100]. Unit tests in `tests/analysis.test.ts` now pin
`ADX ≤ 100` and trending > choppy (the old tests only checked `≥ 0`, so the 14× went unnoticed).

### The validation (FR-SEY-5)
The arithmetic fix *un-saturates* a weight-21 signal — so per FR-SEY-5 it had to be shown
at-worst-neutral before shipping on the live path. Brief Replay omitted ADX entirely
(`trendStrengthAdx: null`), so it was first made ADX-aware (point-in-time from the same bars it
already uses for ATR/breakout), then a full-year A/B (`tests/adx-replay-validation.test.ts`,
2025-05-01 → 2026-06-15) compared ADX-absent vs corrected-ADX on **re-ranked** picks:

| Strategy | n | ADX-off | ADX-on | Δ | HR |
|---|---|---|---|---|---|
| bullish | 1310 | 9.97% | 8.46% | **−1.50pp** | 64→63% |
| bearish | 1184 | 1.73% | 0.59% | **−1.15pp** | 59→54% |
| income | 1310 | 5.51% \|move\| | 5.95% | **−0.43pp** | 77→76% |
| buy / wheel / inflection | — | — | — | 0.00 | — |

Enabling the corrected ADX is **net-negative on every strategy that uses it** — strong-trend
(high-ADX) names mean-revert over ~21d. (An earlier tercile *proxy* suggested income would
benefit; the full re-ranking A/B — the gold standard — overturned it.) The live brief was
accidentally protected by the saturation bug, so naively shipping the arithmetic fix would have
silently degraded bullish/bearish/income.

### The change
- **`ScoringService.USE_ADX_IN_SCORING = false`** — ADX is no longer fed into the composite.
  `trendStrength` (bullish) / `downtrendScore` (bearish) fall back to their MA-stack component;
  income's `trendNeutral` goes missing. This is the validated-best state and ≈ prior behaviour
  (replay never used ADX; the live brief only did via the saturated bug).
- The corrected ADX is **retained for display** (Validate dashboard, Analysis view) — no more
  "ADX 630".
- Brief Replay matches the live brief (no ADX in scoring) by default; `REPLAY_WITH_ADX`
  re-enables the point-in-time computation for the A/B harness.

### Files

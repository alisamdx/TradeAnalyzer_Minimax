# v1.1.364 — 2026-10-15

## fix: Vanguard share-class tickers

- **Cause.** From the 2026-09-30 holdings file, Vanguard's VOO/VONE JSON writes share classes with a space: `BRK B`, `BF A`, `BF B`, `HEI A`, `LEN B`, `UHAL B` (read live 2026-10-15). `fetchVanguardHoldings` sanitised with `replace(/[^A-Z0-9.-]/g, '')`, which deleted the space.
- **Effect.** The 10:15 refresh reported `+[BFB, BRKB, ...] / -[BF.B, BRK.B, ...]` across both indices. Polygon answered 404 for each new symbol (snapshot and reference) and E*Trade answered 400, so six real constituents dropped out of every downstream job. It looked like index turnover and stayed under the 25% turnover gate.
- **Fix.** `normalizeVanguardTicker()` (exported) turns internal whitespace and `/` into `.` before stripping stray characters. The next refresh restores the dotted tickers and removes the dot-less ones. The restored rows get a new `added_at`, which is cosmetic.
- **Also.** `ConstituentsRefreshJob` counted a bootstrap that stored 0 bars as updated, so the note read "10/10" while six got 404s. Zero bars now counts as failed.
- **Not fixed.** Vanguard also sends Dillard's Class A with an empty ticker, so DDS left the Russell 1000 list in the same refresh. No ticker can be recovered from that row.
- Tests: `tests/constituents-refresh.test.ts` covers the live spellings, a refresh that keeps BRK.B and BF.B with no turnover, and the zero-bar bootstrap.

## fix: one sec.gov rate limiter

- **Cause.** `ElectronCollectorHost.httpGet` paced Finnhub and IVolatility but not EDGAR. `edgarFetch` (this app's fundamentals path) had no pacing either.
- **Effect.** At 18:51 ET on 2026-10-15 the collector's events phase made 23 sec.gov calls in one second. SEC allows 10/s per IP. 26 responses were HTTP 429: 20 filing `index.json` reads, 6 `.txt` filings, and `daily-index/2026/QTR4/form.20261015.idx`. 10-12 to 10-14 had none.
- **Fix.** `edgarLimiter` in `services/edgar-identity.ts` is one `TokenBucketRateLimiter` (480/min = 8/s, burst 2). Both `edgarFetch` and the host's `httpGet` acquire it when the provider is `edgar`. They share one IP, so they share one bucket.
- Tests: `tests/edgar-identity.test.ts` checks the rate, that `edgarFetch` acquires before calling, and that the host uses the same instance.

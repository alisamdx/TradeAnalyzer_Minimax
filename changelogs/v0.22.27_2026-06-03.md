# v0.22.27 — 2026-06-03

## Fix: Batch job stuck on "Running" / cancel does nothing

### Root cause 1 — stale DB state on restart
When a job was hanging and the app was killed or crashed, `batch_runs.status`
and `batch_jobs.last_run_status` stayed `'running'` in the DB forever. On next
launch the UI showed the job as still running even though no job was executing.

**Fix**: `BatchService` constructor now cleans up stale `running` rows on every startup:
```sql
UPDATE batch_runs SET status='failed', completed_at=?, error_message='Interrupted by app restart'
WHERE status = 'running'

UPDATE batch_jobs SET last_run_status='failed'
WHERE last_run_status = 'running'
```

### Root cause 2 — cancel never updated the DB
`cancelJob()` called `ac.abort()` (signalling the AbortController) but wrote
nothing to the DB. The DB update only happened inside `runJob()`'s `finally`
block — which only runs when the `await handler.run(...)` Promise settles.
If the Promise was hung (e.g. waiting on a network call with no timeout),
`finally` never ran, the DB was never updated, and the UI was permanently stuck.

**Fix**: `cancelJob()` now:
1. Calls `ac.abort()` as before
2. Immediately writes `status='cancelled'` to `batch_runs` and `batch_jobs`
3. Clears `runningJobId = null` so new jobs can start without waiting

A guard `if (ac.signal.aborted) return` in `runJob()` prevents the job's
eventual `finally` settlement from overwriting the cancelled DB state.

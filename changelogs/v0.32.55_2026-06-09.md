# v0.32.55 — 2026-06-09

## Fix: strikeOtmPct formula inverted + 2 new critic rule checks

### What changed

**`src/main/services/critic-service.ts`**

1. **`strikeOtmPct` formula corrected** (line in `synthesizeVerdict` structure-context block)
   - Old: `(price - strike) / price * 100` → negative for OTM short calls (strike > price)
   - New: `(strike - price) / price * 100` → positive for OTM short calls ✓
   - The system prompt already described this as "positive = OTM" — the formula now matches that description.
   - Impact: eliminates ~3 false bullish `flag` verdicts per brief run (e.g. COHR, ALAB, MRVL)

2. **New rule: `checkAnomalousMomentum`** → `data_anomaly_suspected` (severity: `info`)
   - Fires when `priceMomentumPct.raw > 500`
   - Scenario caught: SNDK (WD spinoff Feb 2025 @ $48.60; priceMomentumPct ~3837%) was appearing as a PASS when the LLM was rate-limited
   - Always in `criticVerdict.flags` regardless of LLM status

3. **New rule: `checkEarningsInWindow`** → `earnings_in_window` (severity: `warning`)
   - Fires when a known earnings date in `earnings_calendar` falls between today and the structure's expiry
   - Uses new private helper `getStructureExpiry` to extract the best relevant structure's expiry from `strategyLabResult`
   - Previously earnings were only in LLM context (`earningsInWindow` field) and disappeared on LLM failure
   - Now always in `criticVerdict.flags`; LLM continues to receive it as context too

### Helper added
- `private getStructureExpiry(pick, strategy): string | null` — shared logic to pull the best relevant structure's expiry from `strategyLabResult` (avoids duplicating the slug-lookup across methods)

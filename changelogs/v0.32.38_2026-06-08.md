# v0.32.38 — 2026-06-08

## ADX and support level added to DailyTechnicalSignalsJob

Fills the last two signal gaps that required watchlist analysis runs.

### trendNeutral (income strategy)
- **Root cause**: `trendStrengthAdx` (ADX value) was only populated from `analysis_snapshots`, which only exists for tickers a user has run watchlist analysis on.
- **Fix**: `computeADX()` added to `daily-technical-signals-job.ts` — standard Wilder 14-period ADX computed from `historical_prices` bars for every ticker with ≥28 bars.
- **Schema**: migration 035 adds `technical_signals.adx REAL`.
- **Scoring**: `loadTechnicalSignals()` fills `trendStrengthAdx` from `adx` when `analysis_snapshots` has no data. Income picks can now be range-bound filtered (`trendNeutral` signal, 15% weight).

### breakoutScore (buy strategy)
- **Root cause**: `entryZoneLow` (support zone) was only populated from `analysis_snapshots buy.entryZoneLow`.
- **Fix**: 20-day price low computed in `DailyTechnicalSignalsJob` as a support-zone proxy.
- **Schema**: migration 035 adds `technical_signals.support_level REAL`.
- **Scoring**: `loadTechnicalSignals()` fills `entryZoneLow` from `support_level`. The `priceNearSupport` component of `breakoutScore` now works for all batch-scored tickers.

### Note
After deploying this version, run **Daily Technical Signals** before regenerating the brief so `adx` and `support_level` are populated in the DB. On subsequent days both columns are populated as part of the normal 16:30 chain.

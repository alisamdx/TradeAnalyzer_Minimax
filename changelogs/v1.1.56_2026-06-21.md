# v1.1.56 — 2026-06-21

## Per-strategy composite floors editable in Execution Settings

The per-strategy composite-floor map (`exec_config.min_composite_by_strategy`, shipped v1.1.55)
was settable only via migration. It now has a UI editor in **Execution Settings → Entry policy**,
directly under the global **Min composite score**.

### What changed
- New `StrategyFloors` editor in `ExecutionSettingsView`: one number input per **eligible strategy**
  (derived live from the Eligible strategies field), plus any existing override key that is no longer
  eligible — shown flagged **"(not eligible)"** so a stale override can be removed.
- **Blank = inherit the global floor** (rendered as the input's placeholder); a value overrides it.
  Matches `EntryPolicy.filterPick`'s `minCompositeByStrategy[strategy] ?? minCompositeScore`.
- Edits mutate a fresh copy of the map (no in-place mutation), so the dirty-tracking / Save / Revert
  flow works unchanged. Persists through the existing `getConfig` / `updateConfig` round-trip
  (`RiskGovernor` already JSON-encodes the field).

### Why
A single global floor is wrong for a multi-strategy book — composites aren't comparable across
strategies (income's validated population is all < 50, hence its floor of 0). Making the map editable
lets the operator recalibrate any strategy's floor without shipping a migration.

### Scope
UI-only (renderer). No engine, schema, or behavior change — the field and its consumption already
existed. The liquidity gate (`max_combo_spread_pct`) remains in the same section and **off** by
default per FR-SEY-5 (not backtestable).

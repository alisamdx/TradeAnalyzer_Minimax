# v1.1.160 — 2026-09-02

## fix: portfolio-sync was seeded with its own schedule and would have run twice a day

Caught by the operator immediately after v1.1.159 shipped: *"I turned off the schedule for this
new job step, since all the steps are orchestrated by the first step."* That was not a
preference — it was a real defect.

### What was wrong

`registerJob` defaults `dailyScheduleEnabled` to **true**, and v1.1.159 registered
`portfolio-sync` without overriding it. Verified against the live table:

```
batch-orchestrator     sched_enabled 1     ← the only one that should be
constituents-refresh                 0
daily-market-sync-…                  0
…all other sub-jobs                  0
portfolio-sync                       1     ← wrong
```

Only `batch-orchestrator` is meant to carry a schedule; every other job is driven by the chain
in `sequence_order`. Left as-is, this job would have run **twice a day** — once on its own 17:45
timer and once inside the after-close chain.

Not merely wasteful. A second unattended run writes to the **real position record**, and
`position_audit` would show two sets of writes per day with no obvious cause — the audit log
added one release earlier would have been reporting a phantom.

### Fix

`dailyScheduleEnabled: false` on the registration, with a comment stating why, since the
defaulting is easy to miss (`constituents-refresh` and `filters-prefill` already pass it
explicitly; the rest were disabled by other means).

**Migration 074** corrects any install that already seeded it enabled. `INSERT OR IGNORE` never
re-seeds an existing row, so fixing the code alone does nothing for a machine that already ran
v1.1.159 — the same frozen-column trap as `config_json` (v1.1.121), `after_close_only`
(v1.1.123) and `sequence_order` (migration 067). That is now four separate defects from the same
root cause, and the pattern is documented in `CLAUDE.md`.

### Impact

**None — it never ran.** `batch_runs` shows 0 rows for `portfolio-sync` and `position_audit` is
empty, because the schedule was disabled before the first 17:45 fired. No cleanup required.

Suite: 1044 passed.

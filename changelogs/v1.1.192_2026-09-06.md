# v1.1.192 — 2026-09-06

## chore — npm workspaces for the rebuild (NewApp build step B1)

The existing app becomes the workspace root for the ground-up rebuild
(`NewApp/requirements/06 §4, §5`). This is change #1 of the seven the existing
app receives for stage 1, and it is deliberately the smallest one: no view, no
IPC handler, no service, no job, no table and no schedule is touched.

### Changed

- `package.json`: `"workspaces": ["packages/*"]`, and three additive aggregate
  scripts — `typecheck:all`, `test:all`, `lint:all` (`npm run <x> --workspaces
  --if-present` plus the root's own). **The existing `npm test`, `npm run
  typecheck` and `npm run lint` keep their current meaning — this app only.**
  Nothing about the existing workflow changes.
- `scripts/check-not-running.mjs`: now refuses a build while **either** exe is
  running, and names which one. Both are checked from either app's build,
  because in stage 1 they share a generation directory — this app hosts the
  collector (the writer) and the new exe holds the same database open (the
  reader). `Get-Process -Name` is not a wildcard here, so `TradeAnalyzer` does
  not match `TradeAnalyzer 2`.
- `eslint.config.js`: the ignore list gains `packages/*/{out,dist,release}`.
  Flat-config ignores are relative to the config file, so a root `eslint .`
  would otherwise walk into the new packages' build output. **No rule changed.**

### Verified

- `npm install` hoists cleanly: exactly one `electron` and one `better-sqlite3`
  at the root, the two packages symlinked, no nested `node_modules`. The
  ABI-swap script (`rebuild-better-sqlite3.mjs`) is untouched and still operates
  on that single copy — a second copy would be rebuilt for the wrong runtime
  silently, which is the failure CLAUDE.md warns about.
- `npm run typecheck:all` green. Existing app's build output (`out/`) untouched:
  the new package writes to `packages/next/out/`.

### Known, and pre-existing

`tests/etrade-transactions-slicing.test.ts` fails today on a calendar trigger,
not on this change — see the notes accompanying this release. It fails on
roughly twelve dates a year and passes on the rest.

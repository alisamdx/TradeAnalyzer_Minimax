# v1.1.57 — 2026-06-22

## Live preflight: broker spread-permission gate (fail-closed)

The engine's whole book is **defined-risk multi-leg spreads** (inflection vertical, wheel put
credit spread, income iron condor). A broker account without spread-level options permission
(e.g. IBKR **Options Level 1**, or a cash account) *accepts the connection and then rejects every
combo order* — leaving the engine live but unable to trade, silently. This adds a fail-closed
preflight so that can never happen.

### Context
IBKR approved the **live** account for **Options Level 1 only** (covered calls / protective puts),
which cannot place the engine's credit spreads. The live flip is deferred until the account is
upgraded to spread-level (Level 3); the operator is **staying paper-only** for now (the IBKR paper
account has full Level-3 permissions regardless). This gate is defensive insurance for the eventual
live flip — it does not unblock anything by itself.

### What changed
- **`ExecutionBroker.checkSpreadPermission(probe?)`** — new seam method returning a
  `PermissionCheck { ok, code, message }`. `code ∈ ok | no_spread_permission | not_connected |
  check_failed`.
- **IBKR adapter** probes with a **non-transmitted `whatIf` combo order**. The TWS API does not
  expose the options trading level directly, so we read the order response instead: an `OrderState`
  back ⇒ the account can place the spread; an order **error** ⇒ it can't. The whatIf never rests an
  order. Probe spread is discovered on a reference underlying (default **SPY**, two adjacent strikes
  on the soonest expiry — absolute moneyness is irrelevant since IBKR checks permission before
  margin). Pure helpers `classifyPermissionError`, `interpretWhatIfState`, `pickProbeSpread` carry
  the testable logic.
- **`ExecutionEngine.startEngine()`** runs the preflight **in LIVE mode only**, after connecting and
  before reconcile/start:
  - connect failure → `{ started:false, reason:'broker_connect_failed:…' }`;
  - permission not confirmed → `{ started:false, reason:'spread_permission:<code>' }`;
  - confirmed → proceeds to the normal `core.startEngine()` (reconcile-before-act).
  - Outcomes audited: `preflight_permission_ok` / `preflight_permission_failed` /
    `preflight_connect_failed`.
- **Mock broker** always grants permission (a simulator models no entitlement), so tests and the
  whole offline/mock path are unchanged.

### Fail-closed posture
Not connected, no probe buildable, a confirmed permission/eligibility error, an unrelated order
error, **or** a timeout all return `ok:false` and refuse the start. The default `executionMode` is
`paper`, so the preflight is skipped on the soak path — the renderer already surfaces any refusal
reason ("Engine refused to start: …").

### Scope
Main-process only. No schema change, no IPC/preload change, no UI change (the start path and its
reason display already existed). Paper-mode operation is unaffected; the broker still defaults to
mock with IBKR strictly opt-in (`TA_EXEC_BROKER=ibkr`).

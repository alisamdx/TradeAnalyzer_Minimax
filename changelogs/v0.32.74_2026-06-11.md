# v0.32.74 — 2026-06-11

## Fix: orchestrator second daily slot re-runs jobs instead of skipping all

### Problem
The skip rule was `job.lastSuccessDate === today`. After the 10:15 slot succeeded all
10 jobs, the 16:30 slot saw `lastSuccessDate = today` for every job and skipped them all
— making the second slot a no-op.

### Fix
Replaced date equality with a **90-minute time window** (`SKIP_WINDOW_MS`):

```
_isRecentSuccess(job, nowMs):
  job.lastRunStatus === 'success'
  && job.lastRunAt !== null
  && (nowMs - new Date(job.lastRunAt).getTime()) < 90 * 60 * 1000
```

### Behaviour now

| Scenario | What happens |
|---|---|
| 10:15 slot runs → 16:30 slot fires (6h gap) | All jobs re-run (outside 90-min window) |
| Orchestrator fails at step 5, re-triggered 3 min later | Steps 1–4 skipped (within window); steps 5–10 run |
| Manual re-trigger 2h after first run | All jobs re-run |

### Skip message updated
"skipped (already succeeded today)" → "skipped (succeeded Nm ago)" so the log is
informative about *why* a job was skipped.

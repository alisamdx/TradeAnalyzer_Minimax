# v1.1.18 — 2026-06-14

## Fixed — 🤝 Execution views now scroll

The **Execution Settings** form is taller than the window on shorter displays, and its
**Save / Revert** buttons (at the bottom) were unreachable — no scrollbar appeared.

### Cause

`.main` (the content area) is `display: flex; flex-direction: column; overflow: hidden`, so
each view is responsible for its own scrolling. The `TradingDeskView` and
`ExecutionSettingsView` root divs had only `padding`/`maxWidth` — no height or overflow
rule — so tall content was clipped instead of scrolled.

### Fix

Both view roots now fill the area and scroll:

```
flex: 1;
min-height: 0;     /* lets the flex child shrink below content height */
overflow-y: auto;
```

Same pattern as the v1.1.11 sidebar fix. CSS-only (inline styles); no automated test (visual
layout).

# v1.1.223 — 2026-09-11

## The collector's Finnhub calls carried no API key

**Symptom.** gen-001's first full daily run (2026-09-10) made 4 Finnhub calls — 3 × `calendar-earnings`,
1 × `recommendation` — and every one came back non-2xx with a ~34-byte body. `events_earnings` stored
0 of 3 expected, `events_recommendations` 0 of 1; QC-603 and QC-905 (warnings) fired with a tested
value of 9999, i.e. "never observed".

**Cause.** `core` builds the Finnhub URLs (`/calendar/earnings?from=…&to=…`,
`/stock/recommendation?symbol=…`) without a key, by design: credentials are the host's job, and a key
`core` could reach is one a fixture could leak. They go out through `ElectronCollectorHost.httpGet`,
which added a User-Agent and nothing else — and `ElectronCollectorHostOptions` had `getPolygonApiKey`
but no Finnhub equivalent, so there was no key it *could* have added. The existing app's
`EarningsRefreshJob` appends `&token=` itself and was never affected, which is why the key "worked"
everywhere the operator could see it.

**Why it was invisible.** `httpGet` wrote nothing to `logs/api/`. The one place that would have shown
the failure — and its error body — never received it. Same shape as E*Trade before v1.1.144 and the
E*Trade OAuth calls before v1.1.167.

### Fix

- `getFinnhubApiKey` on the host options, wired in `index.ts` from `secureGet(db, 'finnhubApiKey')`.
- `httpGet` adds it as the **`X-Finnhub-Token` header** for `finnhub.io` hosts — never `token=` in the
  query, so it cannot land in a URL, a log line or an archived request.
- No key configured → the call is **refused** (`status: null`, "Finnhub API key is not configured.")
  rather than sent unauthenticated.
- `httpGet` now logs every call via `logApiCall` (provider from the hostname: finnhub / edgar /
  treasury / fred), with a 300-character `responseBodyPreview` on failure only; success bodies are never
  logged. Logging is wrapped so a logger fault cannot fail a provider call.

### Not addressed

- `httpGet` has **no rate limiter**. Finnhub's free tier allows ~60 calls/min, and the weekly
  recommendations phase makes one call per chain-subset ticker. The subset is ~1 ticker today; once it
  fills (≈20 bars in, early October) a sweep of a few hundred tickers will run into 429s. Worth a limiter
  before then.

### Tests

`tests/collector-host.test.ts` (source assertions, like the rest of that file): the app hands the host
the key; it is sent as a header and `token=` appears nowhere in `httpGet`; `core`'s events phase never
names a key; a missing key is refused; every generic call is logged inside a try/catch. 1,267 app tests.

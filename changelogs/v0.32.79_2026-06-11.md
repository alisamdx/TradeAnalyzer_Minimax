# v0.32.79 — 2026-06-11

## Change: SEC EDGAR replaces Polygon /vX/reference/financials for fundamentals

### Problem solved

Polygon `/vX/reference/financials` (the endpoint that feeds `computeRatios()`) requires a
Developer plan ($199/mo). The current Stocks Starter plan returns HTTP 403. The v0.32.76
workaround surfaced a note in job history but still left fundamentals empty.

### Solution

Replace the Polygon financials call with the free SEC EDGAR XBRL API:
- `https://www.sec.gov/files/company_tickers.json` — ticker → CIK mapping, ~500 KB, cached per process
- `https://data.sec.gov/api/xbrl/companyfacts/CIK{padded10}.json` — full US-GAAP filing history
- No API key. User-Agent header required. Rate limit: 10 req/s.

### Concept selection algorithm

Companies sometimes switch US-GAAP concept names after accounting standard updates (ASC 606).
Example: Apple used `Revenues` through FY2018, then switched to
`RevenueFromContractWithCustomerExcludingAssessedTax`. Naively taking the "first found" concept
returns stale 2018 data.

Fix: collect all matching candidates for a role, sort by the **most-recent 10-K filing date**,
pick the winner. Same heuristic used and validated in the v0.32.77 Test API tab.

### Filing array layout

`computeRatios()` calls `sumTtm()` which sums `filings[0..3]`, `sumPriorTtm()` for `[4..7]`,
and `sumFiveYearAgoTtm()` for `[16..19]`. EDGAR's annual 10-K values are placed at:

| Slot | Content | Used for |
|------|---------|----------|
| `[0]` | Current annual 10-K (income statement + CF) + most-recent balance sheet (10-Q preferred) | TTM revenue/income/CF; current balance sheet |
| `[4]` | Prior-year 10-K | YoY revenue/EPS growth |
| `[16]` | 5-years-ago 10-K | 5Y CAGR |

All other slots hold an empty placeholder (`financials: undefined`) — `sumTtm()` skips them.
Array length is always 20 so the `filings.length < 20` guard in `sumFiveYearAgoTtm` passes.

### CapEx now included in FCF

EDGAR exposes `PaymentsToAcquirePropertyPlantAndEquipment`. Added `capital_expenditures` field
to `PolygonFinancials.cash_flow_statement`. `parseFinancials()` now computes capex via
`sumTtm()` instead of hardcoding `null`. `computeRatios()` already handles the case correctly:
FCF = operatingCF − |capex| when capex is available, else FCF = operatingCF.

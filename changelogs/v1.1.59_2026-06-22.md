# v1.1.59 — 2026-06-22

## Lean intraday batch (spec 08 §4, #4)

The morning batch run can now be **lean**: it regenerates the brief from the brief's full upstream
job closure but skips the post-brief housekeeping tail, so the brief is identical and the run is
faster — the lever for getting "trade-ready sooner" without moving the ~10:15 start that keeps the
breakout signals clean.

### The split
The daily brief is position 8 in the job sequence. Everything after it cannot affect today's brief:

| Lean (~10:15 slot) | After-close only (~17:00 slot) |
|---|---|
| iv-capture, market-sync (stocks + ETFs), screener, price-gap-fill, technical-signals, **brief** | options-snapshot, paper-snapshot, earnings-refresh, options-premium-history |

The after-close tail is options-API-heavy, so deferring it is a **free speedup with zero
brief-quality loss** (the lean brief uses the identical upstream closure).

### Mechanism
- Per-job flag **`batch_jobs.after_close_only`** (migration 059). Seeded `1` for the 4 tail jobs via
  the migration UPDATE (existing installs) + `registerJob({afterCloseOnly:true})` (fresh installs);
  user toggles persist (`INSERT OR IGNORE` never overwrites).
- The orchestrator applies a **per-slot lean filter**: `getSubJobs(...).filter(j => !lean ||
  !j.afterCloseOnly)`. Slot lean-ness via the pure **`isLeanSlot(slotTime, scheduleSlots, leanSlots?)`**:
  explicit `OrchestratorJobConfig.leanSlots` wins; else the default = **every slot except the latest**
  (the after-close slot runs everything). Manual/startup runs (no slotTime) always run full.
- `BatchService`: `registerJob` accepts `afterCloseOnly`; `updateJobConfig` toggles it; `BatchJob`
  carries `afterCloseOnly`; new `getBriefFreshness()`.

### UI (Batch view)
- A **Slot** column with a per-job **Lean / After-close** toggle (`batch:update-job` with
  `afterCloseOnly`); the orchestrator row shows its lean slots.
- A **brief-freshness banner** (`batch:brief-freshness` IPC): "✓ Today's brief committed …" vs
  "⚠ Latest brief is … (not today)".

### Validation (FR-SEY-5)
Validation-exempt: the lean brief is **bit-identical** (same upstream job closure) — only post-brief
housekeeping is deferred. Any future trimming *within* the upstream closure would not be exempt.

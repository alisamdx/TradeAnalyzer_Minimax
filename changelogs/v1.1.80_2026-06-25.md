# v1.1.80 — 2026-06-25

## Fix: reconstructed-position greeks were double-signed (CSP read as "bearish")

### Symptom
After v1.1.79 (Portfolio → Payoff shows the real position), running the Pre-Trade Validator on
a held NOW 80 CSP showed:

> ✓ Direction aligns with trend. Both bearish.

A cash-secured put is a **bullish** structure — it should read *bullish vs the bearish tape →
"against the trend (by intent)"* for a happy-to-own wheel. The verdict was still GOOD, but the
direction line (and the net θ/ν) were inverted.

### Root cause — unstable greek sign convention in the sync
The portfolio sync stores E*Trade greeks verbatim, and **the sign convention is not stable**:

| Sync | NOW / TSLA short put delta | Convention |
|------|---------------------------|------------|
| 2026-06-25 morning | δ ≈ **−0.25** (θ<0, ν>0) | raw / long-option |
| 2026-06-25 later   | δ ≈ **+0.27** (θ>0, ν<0) | position-signed |

`positionToPayoffLegs` passed the stored delta through as the *option* delta, and
`computePayoffMetrics` then applied the sell-side flip. With position-signed input (+0.27) that
flip happened a **second** time → net delta −0.27 → "bearish."

### Fix
`src/shared/position-payoff.ts` now normalizes greeks to **canonical raw by leg type** before
building the leg (`rawGreeks`): put δ = −|δ|, call δ = +|δ|; a long option always pays θ (−|θ|)
and is long vega (+|ν|). The Payoff engine then applies the side sign exactly once, so the
result is correct whichever convention the source used. A sold put → leg δ negative → net δ
positive → **bullish**; net θ positive (collecting), net ν negative (short vol).

Also updated the misleading `portfolio-service.ts` comment (commit 83f06b9 had asserted greeks
are "always raw / never position-signed" — that was based on one sync; the convention varies).

### Tests
`tests/position-payoff.test.ts` (8): normalization from **both** raw and position-signed input
yields identical canonical-raw output (put δ<0/θ<0/ν>0), plus the call case. Pure suite green;
typecheck clean.

### Known issue (open)
The **underlying data-integrity cause** — why the E*Trade sync stores different sign conventions
on different runs — is not yet fixed. Consumers now normalize defensively by type, but the sync
should be made deterministic, and the planned **Book Greeks monitor**
(`Requirements/v2-execution/09-book-greeks-monitor.md`) must normalize by type rather than trust
the stored sign (the spec's "raw, derive sign from positionType" assumption is updated to
"convention unstable → normalize by type").

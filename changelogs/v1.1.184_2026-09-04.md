# v1.1.184 — 2026-09-04

## fix — the emailed quote link resolved to "We couldn't find the symbol 'NULL'"

v1.1.183's quote link used `https://us.etrade.com/etx/mkt/quotes?symbol=MKC#/snapshot` — the URL a
signed-in session shows in its address bar, which is why it looked canonical. The ticker was being
interpolated correctly; the URL itself was the problem.

**What actually happens on a cold click.** That page requires a session. Without one, E*Trade
bounces to login carrying the destination as:

```
TARGET=https%3A%2F%2Fus.etrade.com%2Fetx%2Fmkt%2Fquotes%253Fsymbol%253DMKC
```

`%253F` is an *encoded* `%3F`, so one decode leaves a literal `?` character in the path rather than
a query separator. The page parses no symbol and renders **"We couldn't find the symbol 'NULL'"**.
The `#/snapshot` fragment survives untouched (fragments are never sent to the server), which makes
the link look as though it arrived intact.

This is the normal case, not an edge case: an emailed link is opened from a phone as often as not,
and a phone is where a brokerage session is least likely to be live.

**The fix — one public page, two tabs.** E*Trade's own Snapshot tab is on the same page the option
chain already used, with the `content` parameter selecting the tab:

| | URL |
|---|---|
| Snapshot (quote) | `/e/t/invest/quotesandresearch?sym=mkc` |
| Option chain | `/e/t/invest/quotesandresearch?content=3&sym=mkc` |

Both load with no session, the symbol survives, and the symbol is case-insensitive. Verified cold
on MKC and TSLA. The option-chain link is unchanged — it was always on the public page, which is
why it worked and the quote link did not.

## Tests

`tests/dice-email-builder.test.ts` asserts the new URLs and adds a negative: `etx/mkt/quotes` must
never appear in the HTML again.

## Note added to CLAUDE.md — Known quirks

A URL copied from a logged-in address bar is a session artefact, not a shareable link. Every
outbound link has to be tested from a cold session, because that is how the recipient opens it.

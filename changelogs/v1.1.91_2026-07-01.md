# v1.1.91 — 2026-07-01

## Automated S&P 500 + Russell 1000 constituent refresh

### Why
Index membership was a manual step — a Wikipedia "Refresh" button or CSV import that the
user had to remember to run. A stale list means the screener/scoring universe silently
drifts from the real index, and new index members (which often have fresh momentum) are
invisible to the whole pipeline.

### What
**New batch job `constituents-refresh`** — first sub-job in the orchestrator chain
(sequence 2, before Market Sync; migration `063_constituents_refresh_job.sql` shifted the
other jobs +1) so every downstream job sees today's membership.

- **Primary source: Vanguard fund holdings.** VOO (S&P 500) and VONE (Russell 1000) via
  Vanguard's free public paginated JSON API
  (`investor.vanguard.com/investment-products/etfs/profile/api/{fund}/portfolio-holding/stock`).
  Validated live 2026-07-01: 503 / 1,002 rows. The fund's published holdings *are* the
  constituent list.
- **Fallback: the existing Wikipedia scrape**, now gated identically.
- **Gates (both sources):** row-count floor (sp500 ≥ 480, russell1000 ≥ 940) and a ≤25%
  membership-turnover guard vs the stored list. A truncated or corrupt feed can never
  wipe a known-good list; the annual Russell reconstitution (~8-12% turnover) clears the
  guard comfortably.
- **Sector/company preserved** for carried-over tickers (Vanguard has no sector field);
  the whole swap is atomic via `withTransaction`.
- **New-member backfill:** the job diffs membership and fetches **1Y of Polygon daily
  bars** for added tickers that have no price history at all (tickers moving between
  lists or already tracked keep their bars). Quotes/fundamentals follow via Market Sync
  in the same orchestrator run; technical signals compute the same evening. `iv_history`
  can't be backfilled from Polygon — IV rank appears after 21 trading days of daily IV
  capture (scoring treats it as a missing signal until then), or run the manual
  IVolatility backfill for instant full history.
- **Outage semantics:** a refresh failure returns `success` with a "kept existing list"
  warning note (never `failed`) — the orchestrator halts the whole nightly chain on a
  failed sub-job, and a slightly stale constituent list is strictly better than skipping
  the brief. `tickersFailed` counts the failed indices.
- **Manual button upgraded:** `screen:refresh-constituents` (Screener UI) now uses the
  same gated Vanguard-first path. CSV import remains the manual override.

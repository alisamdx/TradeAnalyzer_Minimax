# v1.1.95 — 2026-07-02

## Index Constituents viewer + stable added-dates

### Why
The daily constituents-refresh job (v1.1.91) keeps the S&P 500 / Russell 1000 lists
current, but there was no way to *see* the lists or tell what the job had added. The user
asked for a viewer showing each ticker and when it was added, sortable by date, to spot new
members.

### The date-reset bug (fixed first)
`ConstituentsService.applyRefresh` replaces the index each run via delete + re-insert. It was
stamping **every** row with `strftime('now')`, so `added_at` tracked the last refresh, not when
a ticker actually joined the index — every refresh would have shown the whole index as "added
today," defeating the viewer. Fixed: `applyRefresh` now reads each existing row's `added_at` and
**preserves it for carried-over tickers**, stamping the current time only on genuinely new
members. Existing stored rows keep whatever date they currently have as the baseline; accurate
dates accrue from here forward. No migration needed — `added_at` is already NOT NULL with a
default.

### The viewer
`src/renderer/src/views/ConstituentsView.tsx` (Misc → 📇 Index Constituents):
- Two tabs: **S&P 500**, **Russell 1000**.
- Sortable grid: Ticker · Company · Sector · **Added** (click headers to sort; dates default
  newest-first).
- Ticker/company filter box; a header count; rows added in the last 7 days badged **NEW**.
- Shows the list's source (vanguard / wikipedia / csv / bundled) and last-refresh date.

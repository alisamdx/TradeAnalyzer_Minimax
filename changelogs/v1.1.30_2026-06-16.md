# v1.1.30 — 2026-06-16

## Inflection structure selection direction-locked (brief accuracy audit)

### The bug
Inflection — the v2 launch strategy, soon to trade real money — is a **directional credit
spread placed at a fresh breakout**:

- **up** breakout (`technical_signals.breakout_state = 1`) → **bull-put** (`short-put-vertical`)
- **down** breakout (`breakout_state = -1`) → **bear-call** (`short-call-vertical`)

Both verticals are always constructible on any options chain (you can sell an OTM put below
spot AND an OTM call above it). The shared structure selector `pickRelevantStructure` chose the
**higher-graded** of the two — assuming only the breakout-direction vertical would be viable.
That assumption is false.

On the **2026-06-16 brief**, `MCHP` was an **UP breakout** (`breakout_state = 1`, correctly
admitted by the up-only inflection gate). But its two verticals graded:

| slug | grade | totalScore | legs |
|---|---|---|---|
| `short-call-vertical` (bear-call) | A+ | **94** | sell call 105 / buy call 120 |
| `short-put-vertical` (bull-put)   | A+ | 93 | sell put 90 / buy put 82.5 |

The bear-call out-graded the bull-put by a single point, so the brief surfaced a **bearish
bear-call spread on a bullish breakout**. The advocate rationale itself flagged the
contradiction: *"notably this is a call-side structure, implying bearish inflection."* WDC and
AMKR were correct only by luck (their bull-put happened to grade higher).

This also diverged from the rest of the pipeline: **Brief Replay** records each inflection
pick's direction from the breakout sign, and **Backtest** (`simulateSingleSpread`) maps
`direction +1 → bull put / -1 → bear call`. The live brief recommendation contradicted the
structure the backtest validates.

### The fix
- New shared `relevantSlugsForPick(strategy, breakoutDirection)` narrows inflection to the
  single breakout-side slug (up → `short-put-vertical`, down → `short-call-vertical`); a no-op
  for every other strategy.
- `pickRelevantStructure` / `pickDisplayStructure` take an optional `breakoutDirection` and
  use the narrowed slug list. The old "higher-graded of the two verticals" special case is
  removed.
- `BriefPick.breakoutDirection` (`'up' | 'down'`) is persisted on each pick, set from
  `breakout_state` in the brief job, so the **advocate, critic, PDF/email report, and Daily
  Brief card** all resolve the SAME direction-matched structure (no per-consumer recompute
  drift).
- The brief liquidity gate (`getBestLiquidityScore` / `hasAdequateLiquidity`) is now
  direction-aware, so it scores the structure actually recommended.
- Defaults to `'up'` (the launch/default config; down breakouts are off by default) when
  direction is absent. If the breakout-side vertical is unavailable, the selector returns
  **null** (surface nothing) rather than the opposite-side trade.

### Impact / validation
- **Ticker selection is unchanged** (composite-driven, independent of lab grade) — only the
  structure shown per already-selected inflection pick changes. Neutral on Brief Replay by
  construction → no FR-SEY-5 replay gate required. The change brings the live brief into line
  with the direction-locked spread the backtest already simulates.
- Regression tests in `tests/strategy-structures.test.ts`: MCHP up-breakout lock,
  down-breakout lock, up-default, and unavailable-breakout-side → null. New
  `relevantSlugsForPick` coverage. Full suite: **526 passing**.
- The persisted 2026-06-16 brief still holds the old grade-locked structure for MCHP;
  **re-run the brief** to show its correct bull-put vertical.

# v1.1.339 — 2026-10-01

## The DTE-cost and monthly-rule harnesses read through the app

`scripts/fr-spread-dte-cost-study.mjs` (BPS-4) and `scripts/fr-spread-monthly-rule-study.mjs`
(BPS-19) loaded their data through `scripts/lib/spread-study-lib.mjs`, whose `openStudyDb` opened
`%APPDATA%\trade-analyzer\trade-analyzer.sqlite` directly. Both carried a "RUN from a normal terminal"
warning: from the Claude app's MSIX-redirected shell they would read a stale shadow copy (CLAUDE.md).

**Change.** Same pattern as v1.1.338's study panel:
- **`GET /api/v1/diagnostics/spread-capture-panel[?earnings=1]`** (`services/spread-capture-panel.ts`)
  returns exactly what the library's SQL selected: every `reason = 'entry'` row of
  `spread_chain_capture`, ordered by date, slot, ticker and DTE, and with `earnings=1` the
  `earnings_calendar` rows. An unreadable table is `null`, never `[]`.
- **`loadStudyData(argv, { earnings })`** in the library replaces `openStudyDb`, `loadRuns` and
  `loadEarnings`. A real run reads the route; `--db <file>` remains for the self-tests' synthetic
  fixtures only, and is now the only path that imports better-sqlite3 — so a real run needs neither
  the Node ABI nor `rebuild:node`. Run grouping (`groupRuns`) and every calculation are unchanged.
- Both harnesses' run notes now say they work from any shell with the app running.

Verified: `selftest-spread-dte-cost.mjs` 25/25 and `selftest-spread-monthly-rule.mjs` 19/19, end to
end through the fixture path. `tests/spread-capture-panel.test.ts` (3): entry rows only in run order
with exactly the columns the library reads, earnings only when asked, an unreadable table as `null`.

Not ported: `fr-spread-pool-selection-study.mjs` (BPS-2) still opens SQLite itself.

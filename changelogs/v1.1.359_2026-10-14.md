# v1.1.359 — 2026-10-14

## Premium vs cost basis on stock holdings (Bec's risk line), reporting only

**Why.** This is the third and last Tier-1 item in `docs/Bec/STRATEGY-SUMMARY.md` §10. Bec judges a holding she sells calls against by one test: every call sold lowers the cost basis, so the line only ever falls. We tracked realized P&L per position but never surfaced premium as a running reduction in basis.

**What changed**
- **Portfolio → Open tab: a "Premium vs cost basis" panel.** One row per ticker holding open stock: shares, share-weighted cost, premium kept per share, net basis, % reduced, the line verdict (**✓ only fallen** / **↑ rose N×**) and open short-option credit. A row expands to each closed option in date order, with the basis after it.
- `src/shared/premium-basis.ts` (pure), `services/premium-basis.ts` (DB read), IPC `portfolio:premium-basis`, and `GET /api/v1/diagnostics/premium-basis`. The route returns the same read, so a session can check the panel against the real book without opening the database.

**Which options count.** Short options on the ticker closed on or after the earliest open lot's acquisition, plus the put that assigned the shares. That put is found by expiry (0–7 days before acquisition) and a strike matching a lot cost, not by an "Assigned" note: the orders import has no order for an assignment, so that row usually carries the sync's estimate note instead.

**Three things it is careful about**
1. **Estimated rows are never taken at face value.** When a short option vanishes from the broker with no closing fill, the sync records realized P&L "estimated from last mark", which CLAUDE.md records as wrong by thousands on assigned puts (TSLA 350: −$3,736 recorded, +$499 real). One such row would push the line up by thousands. It is counted at the full credit if it vanished on or after expiry (expired or assigned, no buyback), and not counted at all if it vanished before expiry. Those are listed as unresolved, with a pointer to Sync Closed Positions.
2. **No double count of the assigning put.** Tax rules fold that put's premium into the shares' basis, and a broker may report the adjusted cost. I could not establish from code whether E*Trade does, so each holding decides from its own numbers: a lot cost nearer strike − credit than strike means the premium is already in, and it is shown but not subtracted again. A test caught the first version missing this whenever the credit exceeded the 1% strike tolerance, so the match now accepts either form.
3. **Open credit is not kept premium.** Credit on short options still open is shown in its own column and is not netted in, since a buyback could still cost more.

**To verify after install:** compare `GET /api/v1/diagnostics/premium-basis` with the real holdings. In particular, check whether E*Trade's cost on an assigned lot is the strike or strike − premium. That decides which branch of rule 2 your book actually takes.

## Tests

`tests/premium-basis.test.ts` (8):
- netting and date-ordered steps;
- a call bought back at a loss reads as the line rising;
- the assigning put is counted once, while an earlier cycle and a wrong-strike put are excluded;
- a broker-adjusted cost is not subtracted twice;
- the TSLA-shaped estimate counts the full credit, never −$3,736;
- a pre-expiry no-fill row is unresolved, not guessed;
- open credit is kept separate, and put-only tickers are ignored;
- cost is share-weighted across lots, with the window dated from the earliest lot.

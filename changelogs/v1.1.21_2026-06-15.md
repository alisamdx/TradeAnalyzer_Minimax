# v1.1.21 — 2026-06-15

Two follow-ups from the v1.1.20 daily-brief accuracy audit.

## VIX wired into the critic macro context (E*Trade)

The v1.1.20 audit documented that VIX was always null — nothing populated it and the only
fetch used Polygon's *stocks* snapshot, which can't serve an index. Now the brief job
fetches it from the connected E*Trade account and persists it where the critic reads it.

- **`getETradeLastPrice(symbol, creds)`** (`etrade-options.ts`) — last trade via E*Trade
  `/v1/market/quote/{symbol}`, fail-closed (returns null, never throws).
- **`DailyIntelligenceBriefJob.refreshVixQuote()`** — called just before the AI-critic
  stage: fetch VIX → sane-range validate (`[5,150]`, else ignore) → upsert into
  `quote_cache` (ticker `'VIX'`) via `withTransaction`. The value is recorded in
  `runMeta.vix`.
- `CriticService.getMarketContext()` reads `quote_cache`, so the two VIX rules
  (wheel/income caution at VIX>30, bearish complacency at VIX<14) and the "fear/
  complacency regime" macro context are now live.

**Fail-closed everywhere:** missing E*Trade creds, a fetch error, an out-of-range value,
or a wrong account index symbol all leave `quote_cache` untouched → the critic keeps its
safe null-VIX behavior (rules skip, macro context falls back to SPY-trend only).

**Live verification still required:** the E*Trade symbol for the CBOE Volatility Index is
`'VIX'` on most accounts but could not be verified offline. After the next brief run, check
`runMeta.vix` (or the Daily Brief view) against the real VIX. If it's null or wrong, the
account uses a different index symbol — change the symbol passed in `refreshVixQuote()`.

Tests: `critic-service.test.ts` (+3) — `getMarketContext` reads a populated VIX, the
wheel fear rule fires at VIX>30, and nothing fires (fail-safe) when VIX is null.

## Advocate rationale audited — no fabrication (no change)

The v1.1.20 F1 fix stopped the *critic* from inventing volatility figures. This checked
whether the upstream *advocate* (`aiRationale`) has the same problem. It does not:
`scripts/advocate-rationale-audit.mjs` found that across all 30 picks every number the
advocate cites maps to a real scoring signal it was handed (`0/30` cite a vol figure
without an IV/vol signal in their data).

It also resolves the v1.1.20 "140.8% IV" mystery: that number is the wheel
`recentVolatility` **signal** (140.8 = realized vol), which the advocate correctly states
as "recent volatility 140.8." The **critic** received the advocate's text via
`advocateRationale` and relabeled it as *implied* volatility — exactly the conflation F1
now prevents by supplying the real `impliedVolPct` and forbidding any vol figure not in
`volatility`.

# v1.1.256 — 2026-09-16

## Same-day gate rehearsal

**The problem.** From 2026-09-14 to 09-16 every validation round took a night: a fix shipped, the next nightly run showed what it did, and that run surfaced the next fault. Three of the faults found this way (QC-410's dividend false positives in both directions, QC-009's superseded dictionary key) were visible on data already stored, and were only found same-day because `gate-preview.mjs` happened to exist — which requires both apps closed, runs single checks, and renders no email.

**The loop now.**

1. `npm run build:core` so `packages/core/dist` holds the code being rehearsed, and `npm run rebuild:node`.
2. `node packages/core/scripts/rehearse-gate.mjs --date YYYY-MM-DD` (apps open):
   - `POST /api/v1/diagnostics/generation-snapshot` → the app runs `VACUUM INTO` on the connection it already uses, inside a read transaction, with the same SQLite library, so the copy is consistent even while TradeAnalyzer 2 holds the WAL. Refused (409) while `data-collector`, `collector-oneshot` or `collector-watchdog` runs — the same rule as the day report.
   - The script opens only that copy, applies the current dictionary (as the app does on open: new keys, new indexes), runs `runGate` with `checksFor(db)` for the day's latest daily run, and `buildStatusEmail`.
   - It prints: real vs rehearsed verdict; blocking and warning counts; checks that evaluated nothing; the email subject and byte size; every check whose fired or evaluated count changed; what still fires; the slowest checks, real vs rehearsed. The full email text is written beside the snapshot.
3. `--latest` reuses the newest snapshot; `--snapshot PATH` names one.

**Why it is safe.** The copy is a rollback-journal file under `~/.tradeanalyzer/rehearsal`, which is not under `%APPDATA%` (no MSIX redirect), and no application ever opens it, so none of the multi-process WAL hazards in CLAUDE.md apply. The script refuses any path under AppData or named `data.sqlite`. The rehearsal gate writes its report and exceptions into the copy; the real generation's consecutive-run counts are untouched.

**What it does not cover.** Collection. A change to what is fetched still needs a live run. A change to how responses are parsed is covered by replay (TradeAnalyzer 2's Jobs view), which re-ingests archived bytes into a scratch database.

# v0.22.23 — 2026-06-03

## Daily IV Capture: E*Trade → MarketData.app

### Problem
`DailyIvCaptureJob` depended on E*Trade OAuth tokens which expire at midnight ET
every day. When the user is away from the machine the token cannot be renewed,
so the job silently failed every night.

### Change
`DailyIvCaptureJob` now uses `MarketDataProvider` (static API key, $12/month starter
plan). The job is fully unattended — no auth check, no token renewal, no midnight expiry.

**Files changed**

`src/main/services/jobs/daily-iv-capture.ts` — full rewrite:
- Constructor arg changed from `ETradeDataProvider` → `MarketDataProvider`
- Auth check / `renewToken()` dance removed entirely
- Per-ticker: calls `getLiveChain(ticker, expiration)` (single API call using `?expiration=`)
- Expiration computed once per run via `nearestMonthlyExpFor30Dte()` (nearest 3rd-Friday
  monthly between 20–45 DTE, or closest to 30 DTE overall)
- ATM IV computed inline: MarketData.app `iv` is a decimal fraction (0.23 = 23%) —
  multiplied by 100 before `computeAtmIv()` so stored value is in percentage space,
  matching all other sources. see docs/formulas.md#atm-iv-storage
- IVolatility guard preserved: existing `source='ivolatility'` rows are not overwritten
- `source` written as `'marketdata'` for new rows

`src/main/index.ts` — one line: `optionsProvider as ETradeDataProvider` → `marketdataProvider`

### E*Trade preserved
All E*Trade code (`ETradeDataProvider`, `etrade-data-provider.ts`, `etrade-auth.ts`,
options provider wiring, E*Trade settings UI) is completely untouched. The `captureFromEtradeChain()`
method on `IvHistoryService` is also untouched — it will still fire as a side-effect
whenever the user manually fetches an E*Trade options chain in the app.

# v1.1.228 — 2026-09-11

## A hook called after an early return, and the lint run that hid it

### The bug

`RiskMatrixTable` (`PayoffView.tsx`) called **eleven** hooks on a render with no legs and **twelve**
once legs existed. The `legScenarios` `useMemo` sat below this guard:

```ts
if (strikes.length === 0 || legs.length === 0) {
  return <div>Add legs and a spot price to generate the risk matrix.</div>;
}
```

React matches hook state **positionally**, so the empty → populated transition shifts every hook after
the boundary by one slot: either "rendered more hooks than during the previous render", or the quieter
failure where a hook reads another hook's stored value.

This is not an edge case. The empty state is what the payoff screen shows *before the first leg is
added*, so the transition that breaks hook order is the ordinary path through the view.

**Fix:** the memo moves above the early return, beside `legStrikeSet`. Its inputs (`selectedCell`,
`strikes`, `colDates`, `legs`) are all defined there and its body already returns null when nothing is
selected, so it now always runs and behaves identically.

### Why it survived so long — the transferable half

`react-hooks/rules-of-hooks` had been reporting it. Nobody could see it, because `npm run lint` was
carrying **129 errors**, 51 of them a single false-positive rule (`no-undef` reading type space —
fixed in the same session). **A suite that always fails reports nothing.** The signal existed the whole
time and was buried under noise that had been tolerated for so long it had stopped being read.

Same shape as the test suite that went red twelve days a year on a date-arithmetic quirk and taught
people to ignore it, and as the ~70 identical RED gate emails that buried the one that mattered.

### Also in this build

- `no-undef` off for `.ts`/`.tsx` (typescript-eslint's own guidance — the rule cannot see type space,
  and `tsc` already refuses undefined identifiers in both spaces). Removed 51 false errors, three of
  them `NodeJS.Timeout`.
- `getApiKey`'s unused `catch (err)` binding → optional catch binding.

### Lint backlog, unchanged and deliberately untouched

77 errors remain, all long-standing: 25 `no-explicit-any`, 14 `react/no-unescaped-entities`, 13
`no-empty`, 12 `no-unused-vars`, plus a scattering. Worth scheduling as its own pass — until it is
cleared, `npm run lint` cannot gate anything, which is precisely how this bug stayed invisible.

### Not changed

The collector, the gate and every EDGAR/Finnhub/Polygon path are identical to v1.1.227. This is a
renderer fix plus lint configuration.

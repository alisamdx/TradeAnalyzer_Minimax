# v0.32.73 — 2026-06-11

## Fix: orchestrator false "token invalid" on active E*Trade sessions

### Root cause
`_checkEtradeToken()` called `renewAccessToken()` and treated any failure as "token invalid".
But E*Trade's `/v1/oauth/renew_access_token` endpoint is designed for **dormant** tokens
(inactive >2 hours). When you call it on an **active** (recently-used) token, E*Trade
rejects it — causing the orchestrator to abort with "E*Trade token invalid — renewal
failed" even though Settings shows "✓ Connected".

This is documented in `ipc-etrade.ts` lines 171–174:
> `renewAccessToken` is meant for DORMANT tokens (inactive > 2 h).
> Calling it on an ACTIVE token (just obtained) causes E*Trade to return
> an error, which would produce a false-positive "expired" result.

### Fix
The orchestrator now uses the same date-stamp gate that `checkConnection` (Settings page)
uses:
1. **Date check**: `etradeTokenDate` (written when the verifier succeeds) must match today's
   ET date. If it doesn't match (or is missing), the token is expired → `'invalid'`.
2. **Renewal attempt** (if date is valid): `renewAccessToken()` is called to pre-wake a
   dormant token. If it **fails** (expected for active/non-dormant tokens), the failure is
   silently ignored and the token is still reported as `'valid'`. Individual batch jobs will
   surface real 401s if the token is somehow broken.

### Changed files
- `src/main/services/jobs/batch-orchestrator-job.ts` — `_checkEtradeToken()` rewritten; constructor type updated to `EtradeCredsWithDate`
- `src/main/index.ts` — `getEtradeCreds()` now includes `tokenDate: secureGet(db, 'etradeTokenDate')`

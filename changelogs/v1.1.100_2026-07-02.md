# v1.1.100 — 2026-07-02

## E*Trade keep-alive heartbeat + live connection test

### Why
Even with the renew endpoint fixed (v1.1.99), two gaps remained that made E*Trade a daily
annoyance:

1. **The token still goes dormant.** E*Trade tokens lapse after ~2h of inactivity. The user's
   typical day is mostly Polygon-backed work (screener, filters, analysis), which never touches
   E*Trade — so the token would sit idle all afternoon and the after-close batch would hit a
   dormant token. Renewal now *works*, so the batch can self-heal, but it's better to never go
   dormant in the first place.
2. **"Connected" didn't mean the token works.** `check-connection` is a pure date-stamp check
   (token issued today → "ok") with no live call, so a dormant/dead token still read as
   connected until something actually used it (usually the 5pm batch, face-planting).

### What
- **Keep-alive heartbeat** (`index.ts`): every ~90 minutes (well inside the 2h dormancy window)
  the app calls `probeETradeConnection(db)` — a lightweight `/v1/market/quote/SPY` fetch with
  renew-and-retry. This counts as activity (resets the dormancy timer) and, if the token *had*
  lapsed, revives it. Only runs against a date-valid token; a midnight-expired token is left for
  manual re-auth (no log spam). The interval is cleared on `before-quit`.
- **Live connection probe** (`probeETradeConnection`, exported from `ipc-etrade.ts`): returns the
  *real* state — `ok` (live), `renewed` (was dormant, auto-revived), `expired` (crossed midnight
  ET, or renew+retry still rejected → manual re-auth), `error` (transient network/E*Trade issue),
  plus `no_token` / `no_credentials`. Renews on ANY first failure (a dormant token doesn't
  reliably 401 — it can kill the stream; see CLAUDE.md), classifying only after the retry.
- **IPC + preload**: `etrade:test-connection` / `window.api.etrade.testConnection()`.
- **Settings UI**: a **Test Connection** button (calls the live probe and reports
  live / auto-revived / needs-reconnect), and on mount a today-stamped token is now *verified*
  with a real probe rather than trusted on its date stamp alone.

### Effect
During a running session the token is kept warm and self-heals, so the evening batch and
on-demand options paths should stop hitting "token expired." The one case still needing a human
is a true **midnight-ET expiry** — renew can't revive that; the app shows it honestly and the
heartbeat leaves it alone.

### Notes / scope
- No dedicated unit test for `probeETradeConnection`: it lives in `ipc-etrade.ts`, which imports
  `electron` at module load, so exercising it in Vitest would require mocking `electron` +
  `secure-settings` + the dynamic `etrade-auth` import. The critical, previously-invisible bug
  (the renew URL) is covered by `tests/etrade-renew-endpoint.test.ts`; the probe is
  straightforward renew-and-retry orchestration mirroring the tested daily-iv-capture path.
- 90-minute interval is a deliberate margin under the 2h dormancy limit; one cheap quote per
  heartbeat, negligible rate-limit impact.

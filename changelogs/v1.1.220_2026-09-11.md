# v1.1.220 — 2026-09-11

## `GET /api/v1/analysis/snapshots/latest`, and the monthly-first harness stops opening the database

### Why

The `WHEEL_MONTHLY_FIRST_EXPIRY` flag (default off since v1.1.128) needs a market-hours
side-by-side before it can be considered. Its harness, `scripts/fr-wheel-monthly-first-ab.mjs`,
picked its ticker sample by opening the production SQLite file directly. Claude Code's desktop
shell is MSIX-containerised, and opening a WAL database from a redirected shell can move it
(CLAUDE.md known quirks). The API server could not serve the sample instead: the batch jobs save
the wheel panel as a **global** snapshot (`watchlist_id NULL`), and `/analysis/snapshots?watchlistId=N`
filters `watchlist_id = ?`, which never matches NULL.

### What changed

- `AnalysisService.getLatestSnapshotByMode(mode)` — newest row of a mode across all watchlists,
  NULL included; ties on `run_at` broken by `id`.
- `GET /api/v1/analysis/snapshots/latest?mode=<mode|all>` — same response shape as
  `/analysis/snapshots/:id`; 404 `NOT_FOUND` when none exists.
- `fr-wheel-monthly-first-ab.mjs`:
  - sample from the new route; no `better-sqlite3` import at all. Against an app older than this
    version the route falls through to `/:id` and answers 400 — the script refuses and says to
    pass `--tickers`.
  - **calendar-phase warning.** The two policies only differ when the next monthly is not the
    first Friday at ≥30 DTE. A 10-ticker live run this morning (Oct 16 monthly at 35 DTE) came
    back **9/10 identical, Δ composite +0.07** — nothing to measure. Differing days for the
    Oct 16 / Nov 20 cycle: Sep 17–18 and Sep 29 – Oct 14.
  - composite delta also printed under the live wheel config (optionLiquidity disabled since
    v1.1.135, so only premiumYield moves, renormalised /91).

### Tests

`tests/analysis-latest-snapshot.test.ts` — a global snapshot is returned (and `listSnapshots`
provably cannot return it); mode filter and `run_at` tie-break.

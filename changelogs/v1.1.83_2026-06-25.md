# v1.1.83 — 2026-06-25

## Fix: validator suggested the user's own trade back as a "better" structure

### Symptom
Re-validating the held NVDA 185 CSP (after the v1.1.82 butterfly fix), the suggestion read:

> LAB SUGGESTS INSTEAD — Short Naked Put (grade C) — sell put $185

…which is the **exact structure being evaluated**. Presenting a held position back as an
"alternative" is misleading on a real-money tool.

### Fix
The service now detects when the lab's best pick is effectively the user's own structure and
flags it (`PretradeSuggestion.sameAsCurrent`). The UI then shows **"LAB: NO BETTER ALTERNATIVE"**
plus a note ("the lab has no higher-graded structure than the one you're evaluating — shown for
context") instead of "LAB SUGGESTS INSTEAD." The genuinely useful information — the grade and
the IV-regime caveat ("consider waiting for higher IV or simply owning") — is kept.

Match is by **leg set** (buy/sell + put/call + strike), order-independent, via the new exported
`suggestionMatchesInput` (PayoffLeg `side`/`type` vs suggestion `action`/`side`).

### Tests
`tests/pretrade-suggestion-match.test.ts` (5): same CSP matches; different strike / different
structure (vertical vs naked) don't; 2-leg spread matches regardless of order; stock-only input
returns false. Full suite green; typecheck clean.

### Note / possible follow-up
The suggestion still surfaces the lab's *highest-graded* structure for the intent; it is not yet
**flag-aware** (e.g. when the trigger is a thin cushion, it could specifically suggest a lower
strike for more cushion). That targeted-improvement is a reasonable future enhancement — for now
the "no better alternative" framing keeps it honest.

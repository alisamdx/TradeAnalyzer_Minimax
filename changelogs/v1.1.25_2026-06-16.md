# v1.1.25 — 2026-06-16

**Defined-risk structure preference in the Daily Brief** (operator-requested follow-up to the 2026-06-16 audit).

## What changed

When a brief strategy has both an unbounded-risk and a defined-risk structure available for a pick, the brief now **presents the defined-risk one**. Real-money safety: never recommend an unlimited-risk structure (naked short call, strangle/straddle, reverse lizard) when a capped-risk alternative is viable.

Implemented in the shared `pickRelevantStructure` (`src/shared/strategy-structures.ts`): among a strategy's relevant, validated structures, partition into defined-risk (`maxLoss` finite) vs unbounded (`maxLoss === null`); present the best defined-risk one; fall back to the unbounded set only when no defined-risk structure is viable.

### Effect on the 2026-06-16 brief (same tickers, same order — only the structure per pick changes)

| Strategy | Effect |
|---|---|
| **income** | 4 of 5 flip: short straddle/strangle → **iron fly / iron condor** (RKLB→iron-fly A+, ASTS→iron-condor A+, ONTO→iron-fly B, ON→iron-fly B). MRVL was already a dynamic-width iron condor. |
| **bearish** | reverse-big-lizard → **long-put-vertical** — gated on v1.1.24 (the reverse lizards must carry `maxLoss = null`). Not yet visible in the *persisted* 2026-06-16 data, which predates v1.1.24; confirmed on the next fresh run. |
| **inflection / wheel / bullish / buy** | **no-op** — their relevant structures are already all defined-risk (CSP, big lizard = bounded naked-put downside, PMCC debit, put/call verticals). The v2 execution engine (inflection-only) is unaffected. |

## Selector unification

All four brief structure selectors now use the shared `pickRelevantStructure` / `pickDisplayStructure`:
- `critic-service.ts` (`selectRelevantStructure`) and the Stage-5 advocate already did.
- `DailyBriefView.tsx` `gradeOf` — was max-totalScore among relevant (didn't skip unavailable).
- `brief-report-builder.ts` (3 sites) — was first-relevant-in-array `?? scores[0]`.

These three had drifted in their selection logic, so the card, the email/PDF, and the critic could feature *different* structures for the same pick. `pickDisplayStructure` adds the display fallback (chosen valid → first relevant even if unavailable, to label it → top-overall) the UI/report need; the critic/advocate use the strict `pickRelevantStructure`.

## Why no FR-SEY-5 validation gate

The change swaps *which structure* is shown for an already-selected pick. It does **not** change which tickers are picked or their order — those come from the scoring engine's composite scores, independent of the lab structure/grade. Brief Replay outcomes are ticker-return-based, so they are unaffected; the change is neutral on the historical sample by construction. Verified empirically against the persisted 2026-06-16 brief: identical tickers and ordering across all six strategies, only the structure-per-pick differs.

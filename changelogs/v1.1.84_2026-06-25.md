# v1.1.84 — 2026-06-25

## Paper-tracking: score brief picks on real structure P&L

### Background
The Retrospect paper-tracking layer already auto-records **every brief pick** as a paper trade
(366 since 06-03, all 6 strategies) and snapshots each daily (`paper_trade_snapshots`). It is the
brief-performance history that `daily_briefs` doesn't retain. But it measured **`stock_return_pct`**
and decided win/loss by a crude stock-direction proxy:
```
income  → win if |stock move| ≤ 8%
bearish → win if stock fell
else    → win if stock rose
```
That mis-scores the premium-sellers — a wheel CSP "loses" if the stock dipped 1% even though the
short put expired worthless (a profit); an income iron condor's win is reduced to an arbitrary
±8% band that ignores the actual strikes/credit.

### Change
The tracker now marks the **actual option structure** from its `legs_json`:
- New pure `src/main/services/structure-mark.ts` (`markStructurePnl` / `structureReturnPct`),
  reusing `black-scholes.ts`. Both ends BS-priced at the **entry IV** (historical per-strike IV
  isn't available) so it isolates the underlying move + theta; **per-leg expiry honored**
  (PMCC/calendar). Day-0 P&L is exactly 0. `docs/formulas.md#structure-mark`.
- **Snapshot routine** now stores `structure_pnl` + `structure_return_pct` per daily snapshot
  (alongside the retained `return_pct` stock metric).
- **Close + auto-expire** compute realized `structure_pnl`, and the closed-trade **`outcome` now
  derives from its sign** (win > +$5 / loss < −$5 / breakeven), falling back to the stock-direction
  proxy only when legs can't be priced (e.g. missing IV / stock-only).
- Migration **062** adds the columns. `PaperTrade.structurePnl` threaded through; Retrospect
  History table gains a **Struct P&L** column (green/red, with the stock % kept beside it).

Not FR-SEY-5: this is **measurement/reporting**, not trade logic — it changes no entry/exit/sizing
decision. Tests: `tests/structure-mark.test.ts` (7); full suite 756.

### One-time backfill (operator step)
`scripts/backfill-structure-pnl.mjs` re-scores the existing 2,608 snapshots + closed trades and
re-derives their outcomes from structure P&L. **Run order matters:** launch the new build once so
migration 062 adds the columns, **close the app**, then `node scripts/backfill-structure-pnl.mjs`.
(The script refuses to run if the columns aren't present, and deliberately does *not* ALTER them
itself — doing so before the migration records as applied would break app startup with a
duplicate-column error.) It reports how many closed outcomes flip from the old stock-proxy to the
real structure P&L.

### Caveat
Marking holds IV at entry-IV (no historical per-strike IV), so it's accurate for the
direction + theta component but approximate across an event-driven vol crush (the same limitation
noted in the #1 brief-performance analysis). Good enough to make the brief scorecard reflect real
options outcomes instead of stock direction.

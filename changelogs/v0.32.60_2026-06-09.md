# v0.32.60 — 2026-06-09

## Fix: critic quality — breakevenDistancePct, low_liquidity severity, grade gate, LLM batching, income earnings penalty

### Changes

**`src/main/services/critic-service.ts`**

1. **`breakevenDistancePct` formula corrected (100× inflation)**
   - Root cause: `netCredit` from the Strategy Lab is per-contract (×100 shares); dividing by per-share `price` and then `× 100` gave 100× the true value. XOM showed 760.5% instead of 7.6%.
   - Fix: removed `* 100` — `Math.abs(credit) / price` already yields a percentage when credit is per-contract.
   - Added formula documentation: `docs/formulas.md#breakeven-distance`.
   - Impact: critic LLM was reading inflated values and (correctly) flagging them as data errors; now sees accurate breakeven distances for income picks.

2. **`low_liquidity` severity: `warning` → `info`**
   - Picks at liqScore=5/15 (the gate minimum) fired a `warning`-severity critic rule, which forced verdict to `flag` with no rationale when the LLM was rate-limited.
   - These picks already passed the gate — flagging them again at `warning` level is redundant and inflates the false-flag count.
   - Changed to `severity: 'info'` so borderline-liquid picks produce `caution` (LLM can still escalate to `flag` with rationale if warranted).

**`src/main/services/jobs/daily-intelligence-brief-job.ts`**

3. **`hasAdequateLiquidity`: gate out no-valid-structure picks**
   - Picks where the Strategy Lab ran but all relevant structures had `unavailableReason` set were passing via `best === null → return true` (e.g. VRT PMCC needing two expirations manually). These produce grade-F picks with no legs, no credit, no breakevens.
   - Fix: `if (!labResult) return true` (validation failed entirely, can't gate) / `if (best === null) return false` (lab ran but produced no valid structure).

4. **Critic LLM: 25-concurrent → strategy-batched (5×5)**
   - All 25 critic LLM calls were fired in parallel → ~50% failure rate from Anthropic rate limits.
   - Now processes one strategy's picks (≤5) in parallel, then awaits before starting the next strategy. Reduces concurrent calls from 25 to ≤5 per batch.

5. **Income earnings penalty: −20 pts for earnings within 45 days**
   - `loadIncomeEarningsPenalty()` queries `earnings_calendar` for tickers with a report date in the next 45 days (matching the 30–45 DTE income hold window).
   - Applied in Stage 3 alongside the filter-alert bonus. Income candidates with nearby earnings drop −20 composite points and fall below competitors without earnings unless no alternative exists.
   - The critic's `earnings_in_window` rule still fires for any surviving picks that have earnings in window.
   - Log: `[brief stage3] income: penalised N tickers for earnings within 45d`.

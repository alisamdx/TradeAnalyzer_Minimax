# v1.1.191 — 2026-09-04

## The signals half fails too, and for the same reason

v1.1.190 defaulted both halves of the critic-context change off, but only the **ownership** half had
been measured on its own. The signals half was off by association. It has now been isolated.

## The measurement

`RUN_CRITIC_AB=1 AB_ARM=signals AB_LIMIT=20` — 20 wheel picks, both arms identical except
`CRITIC_CONTEXT_SIGNALS`:

| | pass | caution | flag |
|---|---|---|---|
| before | **6** | 13 | 1 |
| after | **3** | 16 | 1 |

**20% stricter, 5% looser — half the dice-eligible picks gone.**

Every one of the four stricter flips cites the same thing:

```
2026-09-04  AAPL   pass -> caution
    "The weakest signal is `premiumYield` (normalized 23.7/100), meaning the $411.25 credit
     on a $310 strike represents a thin annualized yield..."
2026-08-27  AAPL   pass -> caution
    "The weakest signal is premium yield (normalized 20.7/100)... a thin 1.4% yield for 21
     days — modest compensation for assignment risk"
```

Same missing base rate as the ownership half, in a different costume: the model was told which
reading was worst and not told what "worst" normally looks like.

## And a normalization artefact that makes the idea unsound as built

Counting how often each signal actually *is* the weakest reading, across 250 wheel picks:

| signal | median normalized | weakest on |
|---|---|---|
| **`recentVolatility`** | **9.6** | **60%** |
| `premiumYield` | 52.9 | 18% |
| `optionLiquidity` | 50.0 | 11% |
| `leverageQuality` | 91.2 | 4% |
| `ivRank` | 73.7 | 3% |
| `notDowntrend` | 100.0 | 2% |
| `fundamentalScore` | 85.0 | 1% |
| `technicalNeutral` | 100.0 | 1% |

`recentVolatility` is `lower_better` against a normMax of 60, so ordinary realized vol of 30–50%
maps into single digits. It is the weakest reading on **three fifths of picks because of its own
normalization curve**, not because of anything about the pick.

**So "the pick's weakest reading" is a property of the normalization curves, not of the pick.**
Marking it invites the model to report a near-constant as if it were a finding. T6 separately
measured that same signal **mildly inverted**, so it does not even point the right way.

The one *looser* flip is the counter-example, and it is instructive: on DINO the model read
`recentVolatility` 37.2% against implied 47.7% as a **volatility risk premium in the seller's
favour** and moved caution → pass. Handled well — but n=1, and the 60% prevalence means most
appearances of that slot carry no information either way.

## F10 — a finding about the composite, not the critic

Recorded in `docs/wheel-parameters.md`. Under FR-SE-03 arithmetic a signal contributes
`normalized × weight` to the numerator and its **full weight** to the denominator. At weight 10–11
with a median normalized of 9.6, `recentVolatility` removes roughly **9–10 composite points from
essentially every wheel pick, nearly uniformly**.

That is a constant, not a signal. It shifts the whole distribution down without separating anything
within it.

**Deliberately not acted on.** Re-scaling `normMax` or flipping the direction changes every wheel
composite and therefore which picks the brief keeps — FR-SEY-5, needing a replay. It is recorded
because it silently defeated a different change (this one) and will defeat the next one that
assumes "weakest signal" means something about the pick.

**The transferable check, now in CLAUDE.md:** before using "the worst signal" as if it were
information, count how often each signal *is* the worst. If one dominates, you are reading the
normalization curves, not the picks.

## Harness fix — it would have reported a clean bill of health

When v1.1.190 split `CRITIC_CONTEXT_V2` into two flags, the A/B harness kept setting the old,
now-retired variable. Left alone it would have set **nothing**, compared two identical arms,
reported zero flips, and looked like a pass.

A harness whose control variable has gone stale reports "no effect" for the same reason a broken
thermometer reports "no fever". It now:

- takes `AB_ARM=signals | ownership | both`
- prints which flags the *after* arm sets
- **asserts the enabled set is non-empty before spending a single API call**

## Where this leaves the original defect

**Still real, still unfixed.** The reviewer genuinely is shown a filtered-favourable view of the
pick it is meant to attack — the worst-scoring signal reaches it on 8.3% of picks, and 24% of wheel
picks are passed clean while carrying a hidden sub-35 reading.

Both attempted fixes cost more than they gave, each measured separately. Re-opening either means
supplying the **base rate** alongside the fact — prevalence and the outcome table — so the model can
tell an unusual reading from a universal one. For the signals half it also means fixing, or routing
around, a normalization that pins one signal to the bottom on 60% of picks.

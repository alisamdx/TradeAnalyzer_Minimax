# v0.22.4 — 2026-06-01

## Batch Jobs sequence ordering

Jobs with the same schedule (startup delay or daily schedule time) now run in a user-defined sequence order.

### What changed

- **`migrations/021_batch_sequence.sql`** — adds `sequence_order INTEGER NOT NULL DEFAULT 0` to `batch_jobs`; existing rows are numbered 1..N in current insertion order via a window function.
- **`src/shared/types.ts`** — `BatchJob.sequenceOrder: number` added.
- **`src/main/services/batch-service.ts`**:
  - `BatchJobRow` gains `sequence_order`.
  - `registerJob` inserts `sequence_order = MAX(sequence_order) + 1` so new jobs always append to the end.
  - `_getJobRows` now orders by `sequence_order ASC, id` — startup and scheduled job loops both use this, so jobs run in the configured order.
  - `_mapJobRow` maps `sequenceOrder`.
  - New `reorderJobs(jobIds: string[]): void` — writes `sequence_order = 1, 2, 3…` for each ID in the provided array.
- **`src/main/ipc/ipc-batch.ts`** — new `batch:reorder` handler calls `batchService.reorderJobs(jobIds)`.
- **`src/preload/index.ts`** — `window.api.batch.reorderJobs(jobIds: string[])` exposed.
- **`src/renderer/src/views/BatchView.tsx`**:
  - Job table gains a `#` column showing 1-based sequence position.
  - Each row has ▲ (disabled on first row) and ▼ (disabled on last row) buttons.
  - Clicking a button optimistically reorders the local `jobs` array then calls `window.api.batch.reorderJobs` to persist.

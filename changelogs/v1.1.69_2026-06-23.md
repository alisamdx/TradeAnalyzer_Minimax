# v1.1.69 — 2026-06-23

## Fix the spread-permission preflight timeout (and the diagnostic's after-hours false-positive)

### Symptom
Validating whether the IBKR paper account now has Level 3 (spreads), the operator clicked Start. The
preflight did **not** return permitted/denied — it **timed out**:

```
preflight_permission_failed { code: "check_failed",
  message: "IBKR request 9000002 timed out after 12000ms" }
```

`brokerConnected` was true (TWS was reachable); the probe's own request just never came back.

### Cause
`IbkrExecutionBroker.discoverProbeSpread` requested the reference underlying's option contract
details with **only** `{ symbol: 'SPY', secType: OPT, right: Put }` — **no expiry, no strike**. IBKR
therefore tries to return the *entire* SPY put chain (all expirations × all strikes = tens of
thousands of contracts), which streams far past the 12s request timeout. So the probe never reached
the whatIf permission check.

This is the first time the preflight ran against live TWS at all: paper skipped it before v1.1.66,
and live was never reached (the account isn't permissioned). So the bug was latent — but it would
have blocked the engine from **ever arming, even once permission is granted**, because the preflight
would always time out → `check_failed` → fail-closed refuse-to-start.

### Fix
New pure `nextMonthlyExpiry(now, minDaysOut=10)` → the next standard monthly expiry (3rd Friday) at
least `minDaysOut` days out, as `YYYYMMDD`, computed **all-UTC** (mixing time bases shifts the date a
day — same class as the `nextFridays` bug). `discoverProbeSpread` now sets
`lastTradeDateOrContractMonth` to that expiry, so the contract-details request is constrained to one
deeply-listed expiry (a few hundred contracts) and resolves quickly; `pickProbeSpread` selects two
strikes from it exactly as before.

### Also fixed — the diagnostic's after-hours verdict
`scripts/ibkr-level3-spread-test.mjs` printed "✅ LEVEL 3 CONFIRMED" on the first `PreSubmitted`,
then *also* printed the real "⛔ NOT permitted" when the order flipped to `Inactive`. A market-closed
order queues as `PreSubmitted` first, but IBKR can still reject it on permission grounds a moment
later. The script now treats a queued status as **tentative** — it confirms only if the order
survives ~6s without a rejection, and reports denial immediately on `Inactive`/`Cancelled` or a
permission error. A real `Filled` still confirms at once.

# v1.1.17 — 2026-06-14

## v2 execution — inflection-direction guard (execution layer)

Completes the "both, configurable" rollout of the FR-SEY-3 follow-up (v1.1.16 did the
strategy/brief layer). The execution engine now also won't propose the validated-losing
inflection side, so the policy holds no matter where entries originate.

### Changes

- Migration **051**: `exec_config.inflection_direction` (`'up'` default / `'down'` / `'both'`,
  CHECK-constrained) — mirrors the app `inflectionDirection` setting but self-contained for
  the headless engine.
- `EntryPolicy.filterPick`: rejects an inflection pick whose breakout direction isn't allowed
  (`short-put-vertical` = up / bull put, `short-call-vertical` = down / bear call) with reason
  `inflection_direction`. Checked right after strategy-eligibility.
- `RiskGovernor`: config row mapping for the new column.
- UI: 🤝 Execution Settings → Mode adds the direction selector.

### Two layers, one policy

- **Brief picks** are gated by the app `inflectionDirection` setting (v1.1.16).
- **Engine-generated entries** are gated by `exec_config.inflection_direction` (this release).
- Both default to **up-only** (down/bear-call inflection is a validated net loser); both
  offer `'both'`/`'down'` for the operator. Defense-in-depth: even if a down-breakout pick
  reaches the engine, the entry policy rejects it.

### Tests

`tests/entry-policy.test.ts` (+2): default rejects a down-breakout pick (`inflection_direction`);
`'both'` accepts it. Full suite **459 green**. typecheck + lint clean.

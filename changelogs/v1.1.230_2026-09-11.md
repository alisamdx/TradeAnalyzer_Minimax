# v1.1.230 — 2026-09-11

## Three of four EDGAR callers were never instrumented

### How it surfaced

The operator set the EDGAR contact address in Settings and asked whether it had taken. There was no
way to answer:

- `GET /settings` is a hand-built allow-list of eight keys and never included `edgarContact`, so its
  silence was not evidence either way.
- The production SQLite cannot be read from the agent shell — it is MSIX-redirected, and opening a WAL
  database from a redirected shell is what destroyed gen-001.
- So a live EDGAR call was made through the Test API screen to observe the `User-Agent` in
  `logs/api/` — and **the log had no EDGAR entries at all**.

### The gap

Four call sites reach sec.gov. Only one was logged.

| Caller | Before |
|---|---|
| `ElectronCollectorHost.httpGet` (NewApp collector) | logged, since v1.1.223 |
| `sec-edgar-provider.resolveEdgarCik` | raw `fetch` + `edgarHeaders()` |
| `sec-edgar-provider.getEdgarFundamentals` | raw `fetch` + `edgarHeaders()` |
| `ipc-test-api` EDGAR handler | raw `fetch` + `edgarHeaders()` |

This is the E*Trade-before-v1.1.144 shape exactly, and it was found the same way: by needing the log
and finding it empty. It is also the fourth write-up in this project of one pattern — **a capability
that must apply to every caller belongs in the function they all call** — and the previous three were
the portfolio cash snapshot, the E*Trade OAuth transport, and the dev scripts' redirect guard.

The subtler half is why it looked finished: v1.1.227 *did* unify the identity. `edgarHeaders()` is
shared by all four. Unifying the header while leaving the logging per-caller meant the part that was
easy to see was consistent and the part nobody looks at until they need it was not.

### The fix

`edgarFetch(url)` in `edgar-identity.ts` applies the identity **and** records the call as one
operation. All three raw sites now use it. The log line carries the `User-Agent`, which is what makes
the configured contact observable without touching the database. Failure bodies are logged (first 300
characters); success bodies never are, matching the rule the E*Trade transport already follows.

`GET /settings` now returns `edgarContact`. It is a courtesy address the SEC reads off every request,
not a secret, and a localhost token-authed read-only route is the right place for it — the alternative
is opening the database to check a setting, which from this shell is exactly what must never be done.

### Tests

`tests/edgar-identity.test.ts` — every `sec.gov` fetch line must use `edgarFetch`. The scan was
verified against the real files (3 matching lines) rather than assumed non-vacuous, and the older
assertion that the provider names `edgarHeaders()` was replaced: it had become stale *by design*, and
the stronger property is that the provider routes through `edgarFetch` at all.

1,277 app tests.

### Not changed

The collector, the quality gate and every provider path behave exactly as in v1.1.229. Monday's run is
unaffected.

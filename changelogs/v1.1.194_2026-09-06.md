# v1.1.194 — 2026-09-06

## chore — the ABI-swap script says why it failed

`scripts/rebuild-better-sqlite3.mjs` now catches a file-lock failure and prints
what to do about it, instead of a bare `EBUSY` and a stack trace.

Windows locks a loaded `.node` file, so any running app makes the swap fail.
`pretest` runs this script, and `check-not-running.mjs` guards `package` but not
`test` — so a running exe turns `npm test` into an unexplained crash a hundred
lines from the cause. Hit while building NewApp B2: the new exe was open, and
the failure said `EBUSY: resource busy or locked` with no mention of an app.

The message now names both executables and `npm run dev`. Nothing else changed;
a non-lock failure still throws as before.

This is change-adjacent to the seven in `NewApp/requirements/06 §5` — it touches
a build script both applications share — and it alters no behaviour of the
existing app.

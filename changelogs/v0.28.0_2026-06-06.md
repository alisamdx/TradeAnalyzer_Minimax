# v0.28.0 — 2026-06-06

## Price Gap Fill — 3 performance improvements (~5-8× faster)

### 1. Concurrent batches (biggest impact)
Tickers now processed 5 at a time with 150ms between batches instead of
one-at-a-time with 500ms sleep. Each Polygon agg call takes ~150-300ms so
5 parallel calls complete in ~350ms → ~350ms + 150ms = ~500ms per 5 tickers.

| | Before | After |
|--|--------|-------|
| Rate | ~75 tickers/min | ~500 tickers/min |
| 1,500 tickers | ~20 min | ~3 min |

### 2. Targeted date range (reduces API payload & DB writes)
Instead of always fetching 1 month (~22 bars), the job now computes each
ticker's actual gap: fetches from `(max_date − 3 days)` to today. For a
1-day gap this returns ~5 bars instead of ~22, cutting both network and DB
work by ~4×.

### 3. Transaction-wrapped DB writes
`fetchAndStorePrices` now wraps all upserts for a ticker in one transaction
via the new `HistoricalDataService.storePriceBatch()` method. Previously each
bar was a separate auto-committed write (~22 transactions per ticker → 1).

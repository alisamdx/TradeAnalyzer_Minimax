# v1.1.8 — 2026-06-14

## v2 execution subsystem — Phase 5a (engine assembly)

The glue that wires the Phase 1–4 pieces into one engine and exposes a facade for the
control surfaces. Still dormant — assembled but not instantiated in the app.

### `execution-engine.ts` — `ExecutionEngine`

Constructs and wires: `RiskGovernor`, `OrderManager` (callbacks wired), `EntryPolicy`,
`ExitPolicy` + `ManagementLoop`, and `ExecutionCore` — binding the management loop to the
core's **market-cycle hook** so every market-open cycle evaluates exits and acts (§3.3).

- **Broker is injected** — the same assembly runs the `MockExecutionBroker` (tests/dev) or
  the IBKR adapter (Phase 6); paper vs live is a broker config, never a branch.
- **Facade** for the IPC / control-API layers: `startEngine`/`stopEngine`/`pauseEngine`,
  `tripKillSwitch`/`clearKillSwitch`, `runCycle`, `onEvent`, `generateEntries`,
  `approveProposal` (routes entry→order-manager, exit→management) / `rejectProposal`, and
  reads (`getState`, `getConfig`/`updateConfig`, `getRiskState`, `getPositions`,
  `getProposals`, `getAudit`).
- **Inert to construct** — engine starts `stopped`, no broker connection, no orders.

### Tests

→ open position; the **full loop** (open → mark moves → protective stop auto-closes via a

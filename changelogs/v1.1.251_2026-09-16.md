# v1.1.251 — 2026-09-16

`@tradeanalyzer/core` 0.6.12. Two gate checks fixed after validating the 2026-09-16 daily run (run 16, RED, 2,321 blocking).

## QC-604 had never evaluated

`QC-604` (earnings report date on a non-trading day) queried `ref_trading_day.trade_date`. The column is `date`. The check threw `no such column: trade_date` on every run, and a check that throws is recorded as a blocking finding, so for the life of the generation it contributed one blocking row and zero evaluations.

No test existed for it. The regression test runs it against the real dictionary schema and the real calendar seeder (`ensureTradingCalendar`), with three report dates: a Thursday session (not flagged), a Saturday (flagged), and Thanksgiving 2026-11-26 (flagged; only the calendar knows it, weekday arithmetic would pass it). It failed with `no such column: trade_date` before the fix.

Expect QC-604 to start producing real **warnings** from the next run: E*Trade's UTC dates put Thursday-evening reports on Saturday, which is exactly what it exists to flag.

## QC-404 bounded every ask by the underlying

`QC-404` fired when `ask > 3 × underlying_price`. That is a call's ceiling. A put is worth at most its **strike**, so a deep in-the-money put on a collapsed underlying legitimately asks many times the share price. Live on 2026-09-16: BMNR at $22.81, the $95 put asked $73.45. Intrinsic value is $72.19, so the quote is correct, and 476 findings like it were blocking (warnings promoted by the third-consecutive-firing rule).

The bound is now `underlying_price` for a call and `strike` for a put. Threshold key renamed `maxAskOverUnderlying` → `maxAskOverMaxValue`, tested quantity `ask_over_max_value_ratio`; evidence records `right`, `strike` and `maxValue`. The existing open QC-404 put exceptions stop firing on the next run.

Tests capture a real E*Trade-shaped chain through `captureResponse` and assert: the BMNR-shaped put does not fire; a put asking 3.2× its strike and a call asking 3.5× the underlying both do. Both failed before the fix.

## Not changed

QC-410 (provider vs model delta, 1,373 blocking + 3,762 warning) needs investigation before any change; ADP's call read 0.476 from E*Trade against a model 0.696, which is too large to be a model-convention difference.

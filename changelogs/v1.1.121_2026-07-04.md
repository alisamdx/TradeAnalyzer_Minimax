# v1.1.121 — 2026-07-04

## Filters Prefill default: drop plain IV High, keep only IV High (Vetted)

Direct follow-up request after v1.1.120 shipped IV High (Vetted). Explicit ask: the batch job should automatically precompute only these four —

- RSI Oversold
- Price Alert
- IV High (Vetted)
- Wheel (Vetted)

### The change

```diff
 export const DEFAULT_PREFILL_TEMPLATES = [
   'rsi_oversold',
-  'iv_rank_high',
   'iv_rank_high_vetted',
   'price_alert',
   'wheel_vetted',
 ];
```

Plain `iv_rank_high` is untouched as a template — it still runs live on click from the Filters view for browsing the full, unscreened match list (which can be 200+ names). It's just no longer part of the automatic nightly precompute set.

### A gap this surfaced: code defaults don't reach an already-seeded install

`BatchService.registerJob()` seeds `batch_jobs.config_json` with `INSERT OR IGNORE` — meaning it writes the default **only on the row's first-ever creation**. Every registration after that (every app start) leaves an existing row untouched. This is by design (so a user's customized `enabledTemplates` allowlist survives an app upgrade) — but it also means **changing `DEFAULT_PREFILL_TEMPLATES` in code has zero effect on an install that already ran the job once.**

Checking the live production DB confirmed this had already bitten the v1.1.120 change itself:

```
current config_json: {"enabledTemplates":["rsi_oversold","iv_rank_high","price_alert","wheel_vetted"]}
```

This is the **v1.1.115-era** 4-template default — seeded before `iv_rank_high_vetted` existed as a template at all. So IV High (Vetted) — and by extension the summary email's vetted IV High section — had never actually run on this install, despite v1.1.120 shipping successfully. Relaunching the app alone would not have fixed this either, since the seed logic only fires when the row doesn't exist yet.

**Fix applied**: with the app confirmed not running (health check refused), the live row was updated directly to the new 4-template default:

```
updated config_json: {"enabledTemplates":["rsi_oversold","iv_rank_high_vetted","price_alert","wheel_vetted"]}
```

This is a one-time, targeted metadata patch (a single JSON array in one settings row) — not a schema change, and not something future installs need, since a fresh install seeds correctly from the code constant on first run. Documented in `.ai/AI_CONTEXT.md` as a quirk so a future default-list change knows to check (and if necessary patch) an already-seeded install rather than assuming the code change alone takes effect.

### Tests

`tests/filters-prefill.test.ts` — the existing "runs only DEFAULT_PREFILL_TEMPLATES when no allowlist is configured" test gained an explicit assertion locking in the exact 4-template list (`['iv_rank_high_vetted', 'price_alert', 'rsi_oversold', 'wheel_vetted']`) and an explicit `not.toContain('iv_rank_high')`, so a future accidental re-inclusion of the plain template is caught immediately.

Full suite: 909 passed, 1 skipped.
